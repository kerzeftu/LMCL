# 步骤 07 · 下载源配置

> **阶段**：阶段一 · 工程底座 ｜ **优先级**：P0 ｜ **工期**：3–5 天
> **前置**：[步骤 06](06-数据目录与用户迁移.md) ｜ **后续**：[步骤 08](08-启动保障-启动前体检.md)
> **侵入点**：0（**不新增界面、不改上游下载器**；只写 Bootstrap 可选属性 + 文档 + 测试）
> **基线**：v3.16.4。上游已内建"大陆自动优先 BMCLAPI"与下载源选择 UI，本步骤不是"新建下载源系统"，而是**把既有能力配好、验证透、把默认值定死**。

---

## 1. 目标

1. 中国大陆用户**首次启动、不做任何设置**即可获得可接受的下载速度（版本列表与文件下载自动优先 BMCLAPI）；
2. 海外用户默认走官方源，不被强制镜像；
3. 高级用户可整体指向自定义镜像（内网镜像、自建反代），且**只有一个入口**，不产生第二份配置文件；
4. 下载失败的错误提示沿用上游（超时/SSL/404/文件损坏均有本地化文案），本步骤不重造轮子；
5. 自更新源（步骤 05 的 `hmcl.update_source.override`）与资源下载源**彻底解耦**，改一个不影响另一个；
6. 0 行上游代码修改；新增代码只有 `CommunityBootstrap` 中的可选属性转发与（Phase 4）仪表盘只读展示。

完成标志（DoD）：

- [ ] 新装（`launcher-settings.json` 无下载源字段）→ 生效值 = `DEFAULT`；
- [ ] 模拟大陆环境 → `DownloadProviders.getDownloadProvider().getVersionListURLs()` 的第一个 URI 是 BMCLAPI；
- [ ] 切换 `OFFICIAL` / `MIRROR` → URL 列表按 §2.3 的表变化；
- [ ] `-Dhmcl.bmclapi.override=...` 生效于所有替换表（forge/fabric/optifine/liteloader/authlib-injector…）；
- [ ] 断开网络 → 版本列表在候选间回退，错误提示为本地化文案，不出现裸异常；
- [ ] 更新检查（步骤 05）在三种下载源下行为一致；
- [ ] 文档写明"不创建 `.hmclsource.json`"（旧方案作废）。

## 2. 上游现状（v3.16.4 实测，全部为源码结论）

### 2.1 设置模型

`HMCL/src/main/java/org/jackhuang/hmcl/setting/LauncherSettings.java`：

| 字段 | 类型 | 默认值 | 行 |
|---|---|---|---|
| `versionListSource` | `ObjectProperty<DownloadSource>`（`RawPreservingObjectProperty`） | `DownloadSource.DEFAULT` | ~512 |
| `fileDownloadSource` | `ObjectProperty<DownloadSource>`（`RawPreservingObjectProperty`） | `DownloadSource.DEFAULT` | ~521 |
| `defaultAddonSource` | `StringProperty` | `"modrinth"` | ~530 |
| `autoDownloadThreads` / `downloadThreads` | `BooleanProperty` / `IntegerProperty` | `true` / `64` | ~490/~508 |

- 枚举 `org.jackhuang.hmcl.setting.DownloadSource` 只有三个值：`DEFAULT`（自动选择最佳源）、`OFFICIAL`（优先官方）、`MIRROR`（优先镜像）；
- `RawPreservingObjectProperty` 的作用：把 JSON 中不认识的原始表示保留下来，避免"读进来是 enum、写回去变字符串"的格式漂移——这也是为什么我们**不应该**自建一份下载源配置文件（会出现两个真相源）；
- 持久化在 `<本地根>/config/launcher-settings.json`（步骤 06），字段名即上表。

### 2.2 候选与默认行为

`HMCL/src/main/java/org/jackhuang/hmcl/setting/DownloadProviders.java`（139 行，HMCL 模块）：

```java
// 静态初始化
String bmclapiRoot = System.getProperty("hmcl.bmclapi.override", "https://bmclapi2.bangbang93.com");
BMCLAPI_PROVIDER = new BMCLAPIDownloadProvider(bmclapiRoot);
MOJANG_PROVIDER = new MojangDownloadProvider();

// getCandidates
case DEFAULT -> LocaleUtils.IS_CHINA_MAINLAND
        ? List.of(BMCLAPI_PROVIDER, MOJANG_PROVIDER)
        : List.of(MOJANG_PROVIDER, BMCLAPI_PROVIDER);
case OFFICIAL -> List.of(MOJANG_PROVIDER);
case MIRROR  -> List.of(BMCLAPI_PROVIDER, MOJANG_PROVIDER);
```

- `init()`（由 `Launcher.initializeSettingsRuntime()` 第 158 行调用）监听两个属性，任一变化即重建 `PROVIDER_WRAPPER` 的底层 provider；
- **重要时机**：`hmcl.bmclapi.override` 在 `DownloadProviders` 类静态初始化时读取一次，而该类初始化发生在 `Launcher.start()` 的 `initializeSettingsRuntime()` 内 → **只要在 `Main.main` 之前设置就有效**，Bootstrap 天然满足（步骤 05）；
- 注意：`hmcl.update_source.override` 更早（`Metadata` 类初始化，`HMCL/src/main/java/org/jackhuang/hmcl/EntryPoint.java:48` 触发），两者不要混在同一个工具方法里，避免顺序错误。

### 2.3 大陆判定（`LocaleUtils.IS_CHINA_MAINLAND`）

`HMCLCore/src/main/java/org/jackhuang/hmcl/util/i18n/LocaleUtils.java:51`，静态初始化时计算一次，满足任一即 `true`：

1. 系统时区 ID 恰为 `Asia/Shanghai`；
2. 当前 UTC 偏移 = +8 小时，且 `Locale.getDefault().getCountry()` 为 `CN`；
3. 当前 UTC 偏移 = +8 小时，且 Windows + JNA 可用，且 `GetUserGeoID(GEOCLASS_NATION) == 45`（中国）。

推论（写进验收与用户文档）：

- 新加坡/吉隆坡等 UTC+8 且非 CN 地区 → `false`，默认走官方；
- 人在海外但系统时区仍是 `Asia/Shanghai` → `true`，默认走 BMCLAPI（与上游行为一致，可手动切 `OFFICIAL`）；
- **我们不加"强制大陆"开关**，避免与上游行为分叉。

### 2.4 候选回退的实际语义（`AutoDownloadProvider`，HMCLCore `download/AutoDownloadProvider.java`）

| 方法 | 行为 |
|---|---|
| `getVersionListURLs()` | 所有候选的 URL **按顺序去重并联**（`getAll`），版本列表用 `MultipleSourceVersionList` 逐源尝试 |
| `getAssetObjectCandidates(...)` | 所有候选并联（先 BMCLAPI 后官方，或反之） |
| `injectURL(...)` | 用**首选**候选（用于单 URL 场景，如 Forge 安装器直链） |
| `injectURLWithCandidates(...)` | 所有候选并联 |
| `getVersionListById(id)` | 每个候选各建一份 `VersionList`，包进 `MultipleSourceVersionList`（逐源回退） |
| `getConcurrency()` | 取首选候选 |

→ 断网/镜像故障时**自动回退**是上游既有能力；我们的验证只需覆盖"首选失败 → 第二候选可用"。

### 2.5 镜像替换表（`BMCLAPIDownloadProvider`，apiRoot 默认 `https://bmclapi2.bangbang93.com`）

构造器里的 `replacement` 列表（官方 URL → `apiRoot` 衍生路径）覆盖：Mojang 版本列表/资源/库、`libraries.minecraft.net`、Forge maven（多个域名）、NeoForge maven、LiteLoader、Fabric meta/maven、authlib-injector 下载、Maven Central（→ 腾讯云镜像）、HMCL 自建元数据域（cleanroom/fmllibs/unlisted-versions）等。另有 `fallbackReplacement`：Modrinth / CurseForge 的 API 与 CDN → `mod.mcimirror.top`。

推论：`-Dhmcl.bmclapi.override` 是"整体换镜像根"，不是"只换文件下载"；目标镜像必须能提供 `/mc`、`/assets`、`/libraries`、`/maven`、`/fabric-meta` 等路径，否则 Forge/Fabric 安装会失败。文档必须写清，避免用户把它当"单文件加速"。

### 2.6 现有 UI（我们沿用，不改）

`HMCL/src/main/java/org/jackhuang/hmcl/ui/main/DownloadSettingsPage.java:51`（设置 → 下载）：

- `LineSelectButton<DownloadSource>` ×2：版本列表源（`settings.launcher.version_list_source`）、文件下载源（`settings.launcher.download_source`）；
- 枚举显示名 i18n：`settings.launcher.download_source.auto` / `download.provider.official` / `download.provider.mirror`；
- 描述文案：`download.provider.balanced.desc` / `download.provider.official.desc` / `download.provider.mirror.desc`（`I18n.hasKey` 判空）；
- 插件默认源：`settings.launcher.default_addon_source`（modrinth / curseforge）；
- 另有公共目录、下载线程（自动/自定义）子项；
- 这些 i18n key 已存在于四份 `assets/lang/I18N*.properties`，**本步骤不新增 key**（若 Phase 4 要加"当前源"提示，再按步骤 03 的 i18n 流程加 key，四份文件同步）。

### 2.7 旧配置迁移

`LegacyConfigMigrator`（`HMCL/src/main/java/org/jackhuang/hmcl/setting/LegacyConfigMigrator.java:942-958`）把旧字符串映射为枚举名：

```
"default"/"balanced" → DEFAULT
"official"/"mojang"  → OFFICIAL
"mirror"/"bmclapi"   → MIRROR
```

→ 步骤 06 的导入器只需按此表净化旧字段，不重复实现。

## 3. 决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 是否新建下载源系统 | **否**，复用上游 `DownloadSource` + `DownloadSettingsPage` | 0 侵入；上游 2026 版已经做了大陆自动择优，自研无收益 |
| 默认值 | **`DEFAULT`**（不硬编码 `MIRROR`） | 大陆用户自动 BMCLAPI；海外用户不被镜像拖慢；与上游行为一致 |
| 自定义镜像入口 | 仅 `-Dhmcl.bmclapi.override`（Bootstrap 可从环境变量 `HMCL_BMCLAPI_OVERRIDE` 转发，可选） | 一个真相源；不新增 UI 字段（上游设置文件无该字段） |
| 是否写 `.hmclsource.json` | **不写**，旧文档该方案作废 | 会出现第二个真相源，且上游迁移器不识别 |
| 首装引导 | Phase 1 不做；Phase 4 仪表盘只读展示"当前：自动（大陆 → BMCLAPI）" | 不打断首启，不重复上游 UI |
| 下载线程 | 沿用上游（自动 / 自定义默认 64） | 与上游一致，避免弱网问题被归因到我们 |
| 与步骤 05 的关系 | 更新源 `hmcl.update_source.override` 只影响自更新；下载源只影响资源 | 两者同一属性类但**独立 key**，验收分别覆盖 |

## 4. 详细实施

### 4.1 代码改动清单（0 侵入）

| 文件 | 改动 |
|---|---|
| `community/CommunityBootstrap.java`（步骤 05 已建） | 可选：读取环境变量 `HMCL_BMCLAPI_OVERRIDE`，非空则 `System.setProperty("hmcl.bmclapi.override", value)`；**只在属性尚未显式设置时**写入，并 `LOG.info` 打印（不打印带账号信息的 URL） |
| 其余 | 无 |

> 不修改 `DownloadProviders.java` / `BMCLAPIDownloadProvider.java` / `DownloadSettingsPage.java` / 任何 `I18N*.properties`。

### 4.2 Bootstrap 顺序（与 05/06 合并后的最终形态）

```java
public static void main(String[] args) throws Throwable {
    // 1) 自更新源 + 完整性（步骤 05；Metadata 类初始化前）
    String updateSource = System.getenv("HMCL_COMMUNITY_UPDATE_SOURCE");
    if (updateSource != null) System.setProperty("hmcl.update_source.override", updateSource);
    System.setProperty("hmcl.self_integrity_check.disable", "false");

    // 2) 数据目录（步骤 06；Metadata 类初始化前）
    CommunityPaths.applySystemProperties();

    // 3) 下载镜像（本步骤；必须在 DownloadProviders 类初始化之前）
    String bmclapi = System.getenv("HMCL_BMCLAPI_OVERRIDE");
    if (bmclapi != null && System.getProperty("hmcl.bmclapi.override") == null) {
        System.setProperty("hmcl.bmclapi.override", bmclapi);
    }

    // 4) 进入上游（v3.16.4 的 Main.main 声明 throws Exception）
    org.jackhuang.hmcl.Main.main(args);
}
```

顺序不是美学问题：`Metadata` 的静态初始化早于 `Launcher.start()`（`HMCL/src/main/java/org/jackhuang/hmcl/EntryPoint.java:48`），`DownloadProviders` 的静态初始化晚于 `Metadata`、早于设置监听器挂载（`HMCL/src/main/java/org/jackhuang/hmcl/Launcher.java:158`）。`hmcl.bmclapi.override` 若在 `DownloadProviders` 类加载之后才设置，将**静默无效**。

### 4.3 验证"默认生效"的三种手段

1. **自动化测试**（推荐，可进 CI）：`HMCL/src/test/java/.../community/download/DownloadSourceDefaultsTest`：

```java
@Test
void defaultSourceFollowsChinaMainlandFlag() {
    var provider = DownloadProviders.getDownloadProvider();
    var urls = provider.getVersionListURLs();
    String expectedHost = LocaleUtils.IS_CHINA_MAINLAND
            ? "bmclapi2.bangbang93.com" : "piston-meta.mojang.com";
    assertEquals(expectedHost, urls.get(0).getHost());
}
```

> 注意：`DownloadProviders.init()` 监听 `SettingsManager.settings()`，测试需先初始化设置（用 `-Dhmcl.dir` 指向临时目录，或参考现有迁移测试的 jimfs 初始化）。若初始化成本过高，退化为手工抓包验证，但至少要保留"首选顺序"断言，防止上游未来改默认顺序时我们静默失去差异。

2. **手工抓包**（验收必做）：mitmproxy / Fiddler 挂代理 → 启动器 → 打开"下载"页 → 检查首个版本列表请求域名：

   - 时区改 `Asia/Shanghai` → `bmclapi2.bangbang93.com`；
   - 时区改 `Europe/Berlin` → `piston-meta.mojang.com`；
   - 设置里切 `OFFICIAL` → 只有 `piston-meta`；切 `MIRROR` → 先 `bmclapi`。

3. **日志**：下载失败时上游 `DownloadProviders.localizeErrorMessage()` 生成的文案包含具体 URI 与原因（超时/SSL/404），验收时直接看 UI 弹窗文本，不允许出现 `java.net.SocketTimeoutException` 裸栈。

### 4.4 断网/镜像故障回退验收

| 场景 | 期望 |
|---|---|
| 镜像宕机（`-Dhmcl.bmclapi.override=http://127.0.0.1:9`） | 版本列表回退到 `piston-meta`（`MultipleSourceVersionList` 逐源尝试），UI 不崩；文件下载尝试下一候选 |
| 完全断网 | 提示本地化超时文案；启动器可进入离线模式（上游既有） |
| 镜像返回 404 | `download.code.404` 文案（`localizeErrorMessage`） |
| 企业 SSL 拦截 | `exception.ssl_handshake` 或 `exception.dns.pollution` 文案；**不绕过证书校验** |
| 设置切换下载源 | 立即生效（`init()` 监听属性 → 重建 wrapper），无需重启 |

### 4.5 与步骤 06 导入器联动

- 导入 `launcher-settings.json` 时，`versionListSource` / `fileDownloadSource` 若已是 `"DEFAULT"|"OFFICIAL"|"MIRROR"` → 原样保留（尊重用户选择）；
- 若是旧字符串 → 按 §2.7 映射表净化；
- 导入后不强制改源；值为 `DEFAULT` 时首次使用仍由大陆判定决定。

### 4.6 与 Phase 4 仪表盘的关系（只读展示）

仪表盘"网络"卡片（步骤 14）允许显示：

- 当前设置值（读 `settings().versionListSourceProperty()`）；
- 推断的生效顺序（若值为 `DEFAULT`，按 `LocaleUtils.IS_CHINA_MAINLAND` 显示"BMCLAPI → Mojang"或"Mojang → BMCLAPI"）；
- **不得**反射调用 `DownloadProviders.getCandidates`（private）；不要另存一份判定结果，避免与实际生效值漂移。

## 6. 风险与应对

| 风险 | 等级 | 应对 |
|---|---|---|
| BMCLAPI 由第三方运营，可能限速/宕机 | 中 | 上游已有回退；文档提供切 `OFFICIAL` 的说明；不自建镜像服务（超出范围） |
| `IS_CHINA_MAINLAND` 靠时区/GeoID，海外用户误判 | 低 | 与上游一致；设置页可手动切官方；文档说明判定规则 |
| `hmcl.bmclapi.override` 被当成"单文件加速"乱配 | 中 | 文档强调"整体镜像根"及所需路径清单；错误配置导致 Forge 安装失败属预期并给出排查提示 |
| 属性设置晚于类初始化 → 静默无效 | **高** | Bootstrap 顺序固定 + 单测断言 `getApiRoot()`；代码评审检查 `DownloadProviders` 类首次加载点 |
| 新增测试依赖 UI/设置初始化，脆弱 | 中 | 测试用 `-Dhmcl.dir` 临时目录；只断言 provider 候选，不启 JavaFX |
| 强制镜像违反"海外可用"约束 | 低 | 默认 DEFAULT；不写死 MIRROR |
