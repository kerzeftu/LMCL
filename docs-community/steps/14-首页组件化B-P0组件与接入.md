## 1. 目标

用 **6 个 P0 卡片**把仪表盘做成"打开就能用"的状态，并把前序步骤沉淀的数据接上首页：

| # | 组件 id | 名称 | 尺寸 | 人日 |
|---|---|---|---|---|
| 1 | `launch` | 启动卡（选中实例 + 一键启动） | 2×1 | 2.5 |
| 2 | `pinned-instances` | 置顶实例 | 2×1 | 3 |
| 3 | `memory` | 启动器内存透明化 | 1×1 | 2 |
| 4 | `crash-history` | 最近崩溃 | 1×1 | 1.5 |
| 5 | `java-recommend` | Java 推荐 + JVM 参数（两个 tab） | 1×1 | 2 |
| 6 | `network` | 下载源状态（只读） | 1×1 | 1 |

完成标志（DoD）：

- [ ] 6 个组件全部注册、首次写入默认布局、可编辑（增删/排序/尺寸）；
- [ ] 启动按钮**复用上游唯一启动入口** `Versions.launch(...)`，步骤 08 的体检/快照钩子必然生效；
- [ ] 全部数据读取异步；FX 线程零阻塞 IO；首帧 < 200 ms（骨架屏占位）；
- [ ] 每张卡片都有空态/错误态/降级态，任何一种不导致其它卡片或首页异常；
- [ ] 无实例、无账号、离线、前序数据文件缺失/损坏五种场景均有可读文案；
- [ ] 所有 i18n key 四份 properties 齐全，`CheckTranslations` 通过；
- [ ] 挂机 1 小时 + 反复开关编辑模式，组件实例/监听器不增长。

## 2. 范围与取舍

### 2.1 为什么是这 6 个

| 组件 | 数据形态 | 覆盖的框架能力 | 承接的产品价值 |
|---|---|---|---|
| 启动卡 | 本地状态 + 异步启动流程 | 事件、按钮态、失败提示 | 首页第一诉求：一键启动 |
| 置顶实例 | 本地列表（可能上百） | 列表截断、选中联动 | 多实例用户高频切换 |
| 内存 | 周期快照（本进程） | 只读数据刷新、开关 | 内存透明化（12 的出口） |
| 崩溃历史 | 只读历史文件 + 动作 | 文件读取容错、外部动作 | 崩溃后第一落点（09 的出口） |
| Java 推荐 | 偏好 + 平台矩阵 | 静态数据 + 对话框跳转 | Java 选择降门槛（10 的出口） |
| 下载源 | 上游设置只读 | 观察者绑定 | 大陆可用性可见（07 的出口） |

### 2.2 明确不做（防止范围膨胀）

| 不做 | 原因 | 去处 |
|---|---|---|
| 问候语/时钟卡片 | 无数据价值，纯装饰 | 15 的打磨阶段可加，不计入本步 |
| 更新提示卡片 | 自更新已禁用（[05](05-自更新禁用与完整性校验.md)），更新 JSON 是否托管仍是开放项（`00` §12 #14） | 18（发布准备）拍板后再做 |

| 卡片内自绘图表 | 先把数据接通 | 15/19 再做视觉 |

## 4. 组件规格

通用约定：

- 每个组件一个类，继承 13 的 `DashboardWidget`；UI 只用上游已有 CSS 变量与 `JFX*` 控件，不写死颜色；
- 卡片内不做阻塞 IO；`createContent()` 只搭静态骨架，数据在 `refreshAsync()` 里用 `loadAsync` 拉；
- 卡片宽高由 13 的布局引擎决定，组件必须能在 1×1 / 2×1 / 2×2 三种尺寸下不溢出（文本截断 + tooltip）；
- 所有动作按钮点击后要有防抖（同一动作 300 ms 内忽略重复）。

### 4.1 `launch`（启动卡，2×1，2.5 人日）

```
┌────────────────────────────────────────┐
│ 当前实例                                │
│ 1.20.4-Fabric            [切换 ▾]       │
│                                        │
│        [        启 动        ]          │
└────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 数据 | `context.repository()`（`Supplier<@Nullable HMCLGameRepository>`）→ `getSelectedInstance()`；`context.selectedInstanceId()` 变化时刷新 |
| 空态（无选中实例） | 文案"还没有选择实例" + 按钮 [新建实例] → `Versions.addNewGame()`；[管理实例] → `Controllers.navigate(new GameListPage())` |
| 启动 | `Versions.launch(repository, selectedId)`（FX 线程；该方法内部负责登录/校验/启动，**禁止**自己 new `LauncherHelper`） |
| 启动中 | 按钮禁用 + 文案"启动中…"；状态来源 = 08 `LaunchTracker` 的 `REQUESTED`/`PROCESS_CREATED`/`EXITED_*`；**不看进程数猜**（`countMangedProcesses` 含其它实例） |
| 成功/失败 | 成功不在卡片弹窗（8 号体检/上游已有反馈）；失败交给 `Versions.launch` 自己的错误弹窗，卡片只恢复按钮态 |
| 切换实例 | [切换 ▾] → `JFXPopup` 列出 `repository.getVersions()`（按 `Version.getReleaseTime()` 降序，最多 20），点击 `setSelectedInstance(id)`；底部"更多…"→ `GameListPage` |
| 上次启动 | 08 的 `LaunchTracker` 持久化的最近一次同实例启动时间；无记录显示"—"（**不读文件 mtime 冒充**） |
| 降级 | `repository` 为 null（启动早期）→ 骨架屏；实例 id 在刷新后消失（用户删除）→ 回到空态 |
| i18n | `community.launch.title / current / switching / launching / no_instance / new_instance / manage / switch / last_launch.never` |

### 4.3 `memory`（内存透明化，1×1，2 人日）

```
┌────────────────────────────────┐
│ 启动器内存                      │
│ 已用   182 MB / 上限 2.0 GB     │
│ 可归还 278 MB（理论值）          │
│ 上次归还 12:31 · 释放 96 MB      │
│ [立即归还]  [自动归还: 开]       │
└────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 数据 | `MemoryReclaimer.metrics()`（12 §3.4 的 `MemoryMetrics` record） |
| 刷新 | 卡片可见 + 窗口聚焦时每 **30 s** 拉一次（`Timeline`，仅在插件可见时运行）；`dispose()` 停止 |
| 手动归还 | `MemoryReclaimer.reclaimNow()`（内部有 60 s 冷却；卡片显示冷却中） |
| 自动归还开关 | `MemoryReclaimer.setEnabled(boolean)`；写 `community-settings.json` 的 `memoryBase.enabled` |
| 禁用原因 | `disabledReason` 映射文案：`by_user` / `pause_too_long` / `explicit_gc_disabled`（12 §3.6） |
| 游戏运行中 | `metrics.gameRunning()` → 底部小字"游戏运行中，自动归还每 10 分钟检查一次" |
| 免责 | 文案固定标注"理论可归还"与"是否归还是 JVM 决定"——不许写成"已释放" |
| 降级 | 12 未合入 → 先不合入 `MemoryWidget` 这个类（其余五卡照常），12 合入后再加回 `descriptors()`；**禁止反射绕过编译依赖**。数据拉取失败 → 错误卡片 + [重试] |
| i18n | `community.memory.*`（12 §3.6 已定义，本步直接复用，不新增重复 key） |

### 5.1 Provider

`HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/builtin/CommunityWidgetsProvider.java`：

```java
/// 社区版内置组件 provider；通过 META-INF/services 注册。
public final class CommunityWidgetsProvider implements WidgetProvider {
    @Override
    public @NotNull List<DashboardWidgetDescriptor> descriptors() {
        return List.of(
            new DashboardWidgetDescriptor("launch", "community.launch.title", "community.launch.desc", 2, 1, 10),
            new DashboardWidgetDescriptor("pinned-instances", "community.pinned.title", null, 2, 1, 20),
            new DashboardWidgetDescriptor("memory", "community.memory.title", null, 1, 1, 30),
            new DashboardWidgetDescriptor("crash-history", "community.crash.title", null, 1, 1, 40),
            new DashboardWidgetDescriptor("java-recommend", "community.java.title", null, 1, 1, 50),
            new DashboardWidgetDescriptor("network", "community.network.title", null, 1, 1, 60)
        );
    }

    @Override
    public @NotNull DashboardWidget create(@NotNull DashboardWidgetDescriptor d,
                                           @NotNull DashboardContext context) {
        return switch (d.id()) {
            case "launch" -> new LaunchWidget(d, context);
            case "pinned-instances" -> new PinnedInstancesWidget(d, context);
            case "memory" -> new MemoryWidget(d, context);
            case "crash-history" -> new CrashHistoryWidget(d, context);
            case "java-recommend" -> new JavaRecommendWidget(d, context);
            case "network" -> new NetworkWidget(d, context);
            default -> throw new IllegalArgumentException("unknown widget: " + d.id());
        };
    }
}
```

`META-INF/services/org.jackhuang.hmcl.community.dashboard.WidgetProvider` 内容为上述全限定类名。

## 6. 线程、性能与泄漏

| 要求 | 做法 |
|---|---|
| 首帧 < 200 ms | `createContent()` 只创建骨架（标题 + 占位），数据全部 `loadAsync` |
| FX 线程零阻塞 | 读 `crash-history.json`、`repository.getVersions()` 全在 `Schedulers.io()`；FX 线程只更新控件 |
| 列表截断 | 置顶实例最多渲染 12，超出"+N"；启动卡切换列表最多 20 |
| 防抖 | 按钮 300 ms；`refreshAsync` 用 13 的 `loading` 去重 |
| 无定时轮询 | 仅 memory 卡片可见时 30 s 刷新；其余事件驱动 |
| 泄漏 | 每个 listener/binding/`Timeline` 都 `onDispose`；`dispose()` 幂等；`-Dcommunity.dashboard.debugLeaks=true` 验证 |

**明确禁止**：

- 组件内存/磁盘 IO 写死在 FX 线程；
- 直接 `new Thread` / `Thread.sleep`；
- 用 `countMangedProcesses()` 判断"是否在启动"（多实例会误判）；
- 在卡片里内联"上传崩溃日志"等联网动作（09 明确不联网）。
