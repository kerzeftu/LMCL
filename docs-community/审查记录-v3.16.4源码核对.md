## 2. 阻断级问题（修文档前必须定案）

### 2.1 stub：预编译二进制，但**源码公开**（HMCL-dev/HMCLauncher，C++/CMake，GPLv3）
- `HMCL/build.gradle.kts`：`launcherExe` 为空时依赖 `org.glavo.hmcl:HMCLauncher:3.7.0.1`（`libs.versions.toml` 同版本）；非空时把该文件塞进 `assets/`。最终 `makeExecutables` 把 `assets/HMCLauncher.exe` 的字节 + shadow jar 字节拼成 `HMCL-<name>.exe`。
- 构件内容：只有 `META-INF/MANIFEST.MF`(25 B) + `assets/HMCLauncher.exe`(454,144 B)，无源码；源码在 `https://github.com/HMCL-dev/HMCLauncher`（main，C++20/CMake，约 20 KB 源码 + `HMCL.ico` + `HMCL.rc.in`）。
- stub 实际职责（源码实读）：取自身路径并把 exe 自身当作 jar → 选 `java.exe`/`javaw.exe`（按是否 AttachConsole）→ 依次尝试 `HMCL_JAVA_HOME`、同目录 `jre-{x64,x86,arm64}`、`.hmcl\java\windows-<arch>`、Program Files 厂商目录、PATH → `CreateProcessW("java" -jar <exe>)` 后立即退出。**无自更新、无 jar 签名校验、无完整性拦截**（04 原 L178 "改 stub 触发完整性拦截"不成立）。
- 构建方式：`cmake -A Win32` + MSVC `/MT` + Windows 7 目标；官方 CI 为 `windows-2022`，产出 exe 后以 `HMCL_LAUNCHER_EXE` 传给 `makeExecutables`。即"fork 源码重建 + 私有 CI"可完全复刻，成本约 2–5 天（不是重写的 1–2 周）。
- 许可证：GPLv3 **含 §7 附加条款**——修改版必须改名/改版本号以区别于原版（7(c)），且不得删除版权声明（7(b)，资源里 `LegalCopyright "Copyright (C) 2025 huangyuhui"` 必须保留）。官方 stub 未做 Authenticode 签名（CI 无 signtool）。
- **已定决策（用户 m00446）**：采用 **C 案——fork HMCLauncher 源码重建**。只改 `HMCL.ico`、`HMCL.rc.in`（产品名/公司名/文件名/版本，保留 `LegalCopyright` 原行）、`CMakeLists.txt` 版本号、必要时 `i18n.cpp` 错误文案；保持 **32 位 MSVC 目标**与既有 JVM 搜索顺序；Windows CI 产出 exe 后以 `HMCL_LAUNCHER_EXE` 注入 `makeExecutables`；公开 fork 仓库以满足 GPLv3 对应源码义务。不采用 rcedit 补丁（B），暂不做 Rust 重写（D）。

### 2.2 L2（Windows 服务）与分发形态冲突
- 上游**没有安装器**：分发物只有 `LMCL-*.exe`（stub+jar 拼接）、`LMCL-*.sh`、`.deb`；绿色版/便携版是主形态（00 原 §5 已写）。
- Windows 服务安装需要管理员提权 + SCM 注册 + 安装路径固定；便携版（每次换目录）与服务模型不兼容。
- **已定决策（用户 m00420）**：采用方案 ②——L2 改为**登录后后台守护进程（HKCU Run 启动）**，不装 Windows 服务、不需管理员权限；便携版可用。文档需补权限模型、自启注册/注销、卸载清理、与主程序单实例的互斥关系。

### 2.3 "零侵入"不成立：页面导航是硬编码的
- `Controllers.java`：页面是硬编码 `Lazy` 字段 + 显式 getter（`rootPage/gameListPage/accountListPage/terracottaPage/settingsPage/downloadPage` 等），无插件/扩展点。
- `RootPage.Skin`：侧栏是 `AdvancedListBox` 里逐个 `add(...)` 的硬编码项（账号、版本、下载、设置、Terracotta、聊天抽屉）。
- `MainPage`：`StackPane`，只挂了公告（条件）、更新气泡、右下角启动/菜单按钮；**没有中央内容容器**，版本列表只在 RootPage skin 的 ScrollPane 里。
- 结论：新增"仪表盘/主页组件"必然侵入。推荐首发方案：**只改 `MainPage`**（在 children 头部插入我们的容器，z 序在启动按钮之下），不改 Controllers/RootPage；如果走"新页面"，则固定侵入 `Controllers`（+1 字段/getter）+ `RootPage.Skin`（+1 项）+ 新页面文件，**"零侵入"话术必须删掉**，并按 00 §4.2 表登记。
- 00 §4.2 的"唯一 3 处侵入点"上限失效（A3），修订时改为**分级登记表**：P0 必须改的文件、P1 可选、构建脚本类、资源类。

### 2.4 下载源：上游已内建大陆自动走 BMCLAPI（07 前提作废）
`DownloadProviders.java`（HMCL 模块，139 行）：
- 静态字段 `BMCLAPI_ROOT = System.getProperty("hmcl.bmclapi.override", "https://bmclapi2.bangbang93.com")`；
- `DEFAULT` 候选：`LocaleUtils.IS_CHINA_MAINLAND ? [BMCLAPI, MOJANG] : [MOJANG, BMCLAPI]`；`OFFICIAL=[MOJANG]`；`MIRROR=[BMCLAPI, MOJANG]`；
- `DownloadSource` 已有 UI：`DownloadSettingsPage.java:86/93` 用 `DownloadSource.values()` 填充下拉；
- `DownloadProviders.init()` 只在 `Launcher.initializeSettingsRuntime()`（`HMCL/src/main/java/org/jackhuang/hmcl/Launcher.java:158`）调用一次；类静态初始化发生在该时点，所以 `-Dhmcl.bmclapi.override` 只需在 `Launcher.start()` 前写入即可。
- 修订方向：07 从"新增源"改为"**源策略可视化 + 覆盖域名 + 默认值治理**"；把 `hmcl.bmclapi.override` 写进启动早期（与更新源覆盖同一个 bootstrap 点）。

### 2.5 i18n：`.properties` + 构建期强制对齐（不是 JSON）
- `HMCL/src/main/resources/assets/lang/` 下是 `I18N.properties`、`I18N_zh_CN.properties`、`I18N_zh.properties`、`I18N_lzh.properties` 等 properties 文件（JSON 只用于 `getBuiltinResource` 的通用资源）。
- `I18n.i18n()` 用 `@PropertyKey(resourceBundle = "assets.lang.I18N")`；`I18n.java:130` 行左右。
- `HMCL/build.gradle.kts` 注册 `CheckTranslations`（英文/简中/繁中/文言四份对齐）并让 `processResources` 依赖它 → **新增 key 不进这 4 个文件，CI 会挂**。
- 修订方向：文档给出"新 key 落点 = 这 4 个 properties + 校验任务说明"；禁止再写 `assets/lang/*.json`。品牌词替换（原 03 L168）要避开版权头与 `I18N` 中的法务文本。

### 2.6 设置存储架构已重构（06/13/16 的依据全部要换）
- `SettingsManager`（1712 行）现在管理 **11 个 `JsonSettingFile`**：`LauncherSettings`、`LauncherState`、`UserSettings`、`UserState`、`GameSettings.Instance`、`GameDirectories`、`GameSettingsPresets`、`AccountMetadataStore`、`AccountPrivateData`、`AuthlibInjectorServerList`、`AuthlibInjectorServerMetadataCache`；两类目录：`HMCL_LOCAL_HOME/{config,state,cache,private}` 与 `HMCL_USER_HOME/{config,state,private}`。
- 文件：`config/launcher-settings.json`、`state/launcher-state.json`、`USER config/user-settings.json`、`USER state/user-state.json`、`config/game-directories.json`、`config/game-settings.json`、`config/accounts.json`、`private/account-private-data.json`…；`settings.json` 只作为**迁移输入**（`LEGACY_SETTINGS_LOCATION`）。
- `JsonSettingFile` 有 schema 校验状态机（MISSING/INVALID/UNPARSEABLE/UNEXPECTED_ID/UNSUPPORTED_MAJOR/READ_ONLY_PRESERVE_SCHEMA/READ_WRITE/READ_WRITE_PRESERVE_SCHEMA），`SettingFileAccess` 只读/不可读；`installAutoSave` + `FileSaver`；`backupAndOverwrite`。
- 修订方向：
  - 06 从"改目录常量"改为"**目录策略 + 迁移测试**"：改 `HMCL_USER_HOME`/`HMCL_LOCAL_HOME` 派生逻辑要覆盖 Linux XDG、Windows 便携模式、旧 `settings.json` 迁移三种情况；补 JUnit（参照 `LauncherSettingsMigrationTest`、`UserSettingsTest`、`MigrationReceiptTest`）。
  - 13 的 `dashboard.json` 必须**自带 `JsonSchemaSetting` 实现 + schema 版本**（路径建议 `HMCL_LOCAL_HOME/config/dashboard.json`），不能只写 schema 片段；不能依赖上游 `DashboardConfig`（不存在）。
  - 16 的"启动成功判定"落在 `LauncherHelper.HMCLProcessListener.onExit(int, ExitType)`（约 970 行）与 `repository.markVersionLaunchedAbnormally(...)` 之间，而不是改 `MainPage`。

### 2.7 启动钩子位置修正（15/16/17/18 共用）

- `launch()`（约 132 行）→ `makeLaunchScript` / `launch0`；`integrityCheck = repository.unmarkVersionLaunchedAbnormally(selectedVersion)`（约 153 行）；
- 进程监听器 `HMCLProcessListener.onExit(int exitCode, ExitType exitType)`（约 970 行）：`launchingLatch.countDown()`、`INTERRUPTED` 直接返回、`!lwjgl` 时 `finishLaunch()`、非 `NORMAL` → `markVersionLaunchedAbnormally` + `GameCrashWindow`；
