## 1. 结论速览

> 本节已按 v2 返工改写；§3–§4、§6–§15 中“两层足够”“三卡可能没包”等表述是 v1 历史，不再成立。

1. **v1 做对的部分**：`GlassSurface` 已删 sheen/白色高光边框/噪点，账户卡与 9 张主页卡都走 `BuiltinWidgets.materialCard`，侧栏也走同一 `Kind.SIDEBAR`；`.card` 在 `.lmcl-m3-glass` 下已透明。三张问题卡没有“漏包”。
2. **v1 做错的部分**：只生成 far（屏幕半径 64）和 near（24）两张图，且快照上限只有 640×400。对 1×1 卡（约 300×120）来说，快照上可见区域只有约 150×60 px，far 模糊半径约 32 px，已经覆盖卡高的一半；局部方差接近 0，肉眼就像一块半透明实色。2×1 卡宽一倍，仍能看到横向明暗，所以“只有 Java 推荐/启动健康/下载源不对”与“1×1 采样面积小 + 单一大半径”高度吻合。
3. **三卡仍需日志排除 fallback**：它们的静态结构相同，不能只靠读代码断定。`GlassSurface` 的 `[glass-material]` 必须输出卡片 id、尺寸、快照是否为空、viewport、fallback 原因；若三卡日志显示 `fallback: no snapshot/viewport outside`，先修时序；若显示 `shown`，就是尺度/层数问题。**v2 两条路径都修，不把未验证的假设写成已证实根因。**
4. **“大量多层”是可实现的，不是无限叠 Blur**：同一张壁纸分别用 5 个不同半径做高斯模糊，得到 5 张独立图，再以低不透明度叠加；这比“对同一张图连续 BoxBlur 5 次”更可控，也避免半径被平方放大。默认 5 层，低端机可降为 3 层。
5. **1×1 卡必须单独调层权重**：当表面宽 < 280 或高 < 150 时加 `lmcl-m3-glass-compact`，降低远层不透明度、提高 24/12 px 近层不透明度；否则无论总层数多少，远层都会把卡片“糊平”。
6. **目标**：所有主页卡（含账户卡）、侧栏都呈现“低不透明度 + 多层高斯模糊 + 统一 tint + 单层 16 px 圆角”；删除任何第二层边框/高光/渐变；没有快照时用同一套半透明 fallback，不出现某张卡突然实色。

## 4. 根因分析

### 4.1 双层卡片与高光描边（确定）

- `BuiltinWidgets.glassCard` 的 wrapper 没有背景，但 `community.css:328` 给 active wrapper 加了 `-fx-border-color: rgba(255,255,255,0.20)`、`-fx-border-width: 1`、圆角 16。
- `GlassSurface.sheen` 在玻璃层顶部再叠一条白色渐变；`noise` 再叠颗粒。
- 内层 `.card` 在 active 时虽然背景透明，但**圆角、padding、描边体系仍然存在**；视觉上就是“外层高光框 + 内层卡片”。
- 结论：**删除 wrapper 边框和 sheen；`.card` 在材质模式下彻底透明，只保留 padding 与排版；圆角只由材质表面裁一次。**

### 4.2 侧栏渐变（确定）

- 侧栏没有 CSS 渐变；`GlassSurface` 构造时无条件创建 `sheen`，其背景是 `LinearGradient`（顶部白色 14% → 38% 处透明）。
- 该 `sheen` 对侧栏和所有卡片一视同仁，所以侧栏出现“上亮下暗”的渐变。
- 结论：**删除 `sheen` 字段、构造、CSS class 和所有相关样式；不再保留任何 `LinearGradient`。**

### 4.3 账户卡与页头缺失（确定，历史有意为之）

- `HomePane.buildHeader()` 直接返回 `HBox`，没有 `glassCard`；`infoColumn.getChildren().add(accountCard)` 也没有包装。
- M3 方案 §25（v3.17.18）记录：用户 m26719 要求“主页玩家/每日一言不要组件框”，因此去掉了头部玻璃，账户卡也退回普通 `.card`。
- 本轮用户明确把“当前账户”列入应有材质的范围，所以需要**只恢复账户卡材质**；页头仍保持透明无框，避免把问候语/每日一言重新装进框里。
- 结论：账户卡用同一个 `materialCard` 包装；页头不动。

### 4.4 Java 推荐 / 启动健康 / 下载源为什么单独没有（待日志确认）

静态代码上，这三张卡与其他六张卡没有分支差异：

- 都经 `itemsForHome()` 返回，`addWidget()` 调用 `registry.create` 后统一 `glassCard(widget, 16)`；
- 都使用同一个 `DashboardWidget` 基类，根节点都有 `.card`；
- 都通过 `loadAsync` 更新内容，没有替换根节点。

因此**不能**用“少包了一层”解释。更可能的原因在 `GlassSurface.update()` 的可见性判定：

1. `width <= 1 || height <= 1`：异步内容尚未撑开高度时，表面保持隐藏；若后续尺寸变化没有触发到该表面（或触发时仍为 0），会一直隐藏。
2. `getScene() == null`：卡片刚创建、尚未挂入场景时隐藏；之后挂入场景若没有再次触发，可能停留在隐藏。
3. `image == null`：快照尚未生成；等快照生成时所有表面都应通过 `image` 监听更新，但如果监听被弱引用回收/表面已不可见，仍可能漏掉。
4. `setViewport` 越界：`imageX/imageY + imageWidth/imageHeight` 超出快照边界时，`clampedWidth/Height <= 1` 直接隐藏；滚动、窗口缩放、右栏底部卡片最容易命中。

**本轮不猜测性地改某一个条件**，而是：

- 给每张卡一个稳定 id（`home-card-java-recommend` 等），在 `[glass-material]` 日志中输出 `active/fallback`、尺寸、scene、viewport、快照尺寸；
- 把“材质表面”从“卡片可见性”里解耦：**表面始终显示 tint（fallback），只有模糊图按条件显示**；即使快照/裁切失败，也不会退回不透明 `.card`；
- 对 viewport 越界改为**边界钳制后仍显示可用部分**，而不是整块隐藏；必要时用边缘拉伸兜底，避免卡片突然断层。

这三条会在 Windows 日志里直接给出答案，不需要用户手动判断。

### 4.5 模糊弱（确定）

- 只有一张 640×400 的模糊图；`BoxBlur` 一次，12–32 px（图片像素，屏幕像素约为 `radius / scale`）。
- 没有“远景/近景”两个尺度；卡片上又叠了 sheen/noise/边框，细节被装饰掩盖。
- tint 0.30 加上 `.card` 的实色（如果 active 未生效）会进一步吃掉透明感。
- 结论：**两层不同半径的模糊 + 统一 tint**，而不是继续把单层半径调大；半径过大只会变成均匀色块，失去壁纸的色彩层次。

### 4.6 对比度未验证（H6）

- 半透明表面叠任意壁纸无法天然保证 4.5:1；当前也没有测量。
- 本方案不宣称合规；P1 完成后按 VIS-02 取浅/深壁纸、亮/暗主题、玻璃开/关四组测量，不达标时提高 tint 或给文字局部统一 scrim（**仍是纯色，不引入渐变**）。

## 5. 目标材质

### 5.1 材质公式

> **材质 = 低不透明度表面色 + 两层高斯模糊。**
> 不含：渐变、顶部高光、高光描边、内层实色卡片、装饰性噪点。

```text
表面（16 px 圆角，一次裁剪）
  ├─ 远层模糊图（大半径，低不透明度）  ← 壁纸大色块
  ├─ 近层模糊图（小半径，低不透明度）  ← 局部颜色/纹理
  ├─ 统一 tint（surface-container-low，低不透明度）
  └─ 内容（.card 背景/边框透明，只保留 padding/排版）
```

### 5.2 分层参数

**卡片（9 张 + 账户卡）**

| 参数 | 值 | 说明 |
|---|---|---|
| 圆角 | 16 px | 只由表面裁一次 |
| 远层屏幕半径 | 56–72 px | 默认 64 px；抹平壁纸大结构 |
| 远层不透明度 | 0.45–0.55 | 默认 0.50 |
| 近层屏幕半径 | 20–28 px | 默认 24 px；保留局部色块 |
| 近层不透明度 | 0.25–0.35 | 默认 0.30 |
| tint | `surface-container-low`，0.24–0.30 | 默认 0.28；卡片整体有效不透明度约 0.64–0.72 |
| 边框/高光 | 无 | 删除 wrapper 边框、sheen、noise |
| fallback tint | 0.70–0.75 | 无快照时仍半透明，但不伪造模糊 |

**侧栏**

| 参数 | 值 | 说明 |
|---|---|---|
| 圆角 | 0 | 全高贴边；右侧不再画高光边 |
| 远层屏幕半径 | 48–64 px | 默认 56 px |
| 近层屏幕半径 | 16–24 px | 默认 20 px |
| tint | 0.36–0.42 | 比卡片略高，保证 64 px 内图标对比度 |
| 渐变/高光 | 无 | 删除 sheen；`.community-sidebar` active 时背景透明 |

**页头/标题栏**

| 表面 | 本轮处理 |
|---|---|
| 主页页头（问候 + 每日一言 + 运行状态） | **保持透明无框**，不恢复 `glassCard`；这是 v3.17.18 已确认的视觉决策 |
| 标题栏 | **保持 M3 动态取色实色**（`M3DynamicColors`），不做玻璃；若要玻璃另开切片 |

### 5.3 为什么 v1 的两层不够，v2 改为五层

v1 的判断“3 层以上收益很低”只对**大卡片**成立；对 1×1 卡不成立。原因是快照先统一缩小到 640×400，再按屏幕半径乘 `scale`：

```text
1200×800 窗口，scale = 0.533
far 半径 = 64 × 0.533 ≈ 34 px
1×1 卡 ≈ 300×120 屏幕像素 → 快照上约 160×64 px
34 px 模糊 ≈ 卡高的 53%
```

一块 160×64 的区域被半径 34 px 的模糊覆盖一半以上，横向明暗也被抹平，最终只剩接近均匀的表面色；2×1 卡宽度约 600，仍保留左右差异，所以看起来“其他卡有玻璃、这三张没有”。**这不是三张卡漏包，而是多尺度信息被单一大半径吃掉了。**

v2 改为同一张壁纸生成 5 张不同半径的图（96/64/40/24/12 屏幕像素），分别以低不透明度叠加。远层保留色块和深度，中层过渡，24/12 px 近层保留可辨认的纹理；1×1 卡再通过 `lmcl-m3-glass-compact` 降低远层、提高近层，避免“糊平”。

> 不是“把同一张图连续 BoxBlur 五次”——那等价于一次更大的模糊，半径近似按平方累加，且每层都从上一次结果取图，边缘/性能都不可控。v2 始终从**同一张原始壁纸画布**生成五个独立结果。

---

## 6. 架构改造

### 6.1 快照层：一张采样，两层输出

`GlassBackdrop` 从“单图 + 三个标量属性”改为“一个不可变快照对象”：

```java
public record GlassSnapshot(
        Image far,
        Image near,
        double scale,
        double originX,
        double originY,
        double padding) {
}
```

- 只保留一个 `ReadOnlyObjectProperty<GlassSnapshot> snapshotProperty()`；不再分别发布 `image/scale/originX/originY`，避免四个属性更新间隙导致表面短暂错位。
- `render()` 只画一次 Canvas；用同一个 Canvas 节点做两次 `snapshot`：
  - 远层：`BoxBlur(farRadius, farRadius, 2)`；
  - 近层：`BoxBlur(nearRadius, nearRadius, 2)`。
- 半径按**屏幕像素 × snapshotScale** 换算，避免不同 DPI/窗口尺寸下视觉半径漂移：
  - `farRadius = clamp(64 * scale, 20, 48)`；
  - `nearRadius = clamp(24 * scale, 8, 20)`。
- `padding = ceil(max(farRadius, nearRadius) * 1.5) + 2`；`originX = sceneX - padding / scale`，`originY` 同理；两张图共用同一 origin，切片严格对齐。
- 背景变更/窗口缩放仍由 160 ms `PauseTransition` 合并，一次生成两层，不按卡片重复生成。
- `[glass] snapshot ready: image=… rank=2 scale=… origin=…` 日志保留；新增 `layers=2` 字段。

### 6.2 表面层：一个表面，两个 ImageView

`GlassSurface` 改为：

```java
final class GlassSurface extends StackPane {
    private final ImageView farView;
    private final ImageView nearView;
    private final Region tint;
    private final Rectangle clip;
    private final ReadOnlyBooleanWrapper ready;

    private void update() {
        // 1) 尺寸/场景无效：只显示 tint fallback，不隐藏整块表面
        // 2) snapshot == null：隐藏两个 ImageView，显示 tint fallback
        // 3) viewport 越界：钳制到快照边界；仍无可用像素时仅显示 tint fallback
        // 4) 正常：设置两个 viewport、fitWidth/fitHeight、显示两层
    }
}
```

关键变化：

- **删除** `sheen`、`noise`、`NOISE_TEXTURE`、`Random`、`PixelWriter`、`BlendMode`、`LinearGradient` 等；
- **表面不再因没有快照而隐藏**：tint 始终可见，wrapper 通过 `ready` 属性在 `community-material-active` / `community-material-fallback` 之间切换；
- `ready` 只表示“模糊层可用”，不表示“卡片可见”；
- `clip` 只裁一次，圆角由构造参数决定（卡片 16，侧栏 0）；
- viewport 越界时**保留可用部分**，不再整块 `setVisible(false)`；如果可用宽/高 ≤1，则隐藏两层图但保留 tint；
- 不处理鼠标事件，保持背景层语义。

### 6.3 包装层：单一材质表面

保留 `BuiltinWidgets` 工厂，但语义从 `glassCard` 改为 `materialCard`：

```java
static StackPane materialCard(Node content, double arc) {
    GlassSurface surface = new GlassSurface(arc);
    StackPane wrapper = new StackPane(surface, content);
    wrapper.getStyleClass().add("community-material-card");
    wrapper.setId(...); // 由调用方给稳定 id，便于审计
    surface.readyProperty().addListener((obs, old, ready) -> {
        wrapper.getStyleClass().removeAll(
                "community-material-active", "community-material-fallback");
        wrapper.getStyleClass().add(ready
                ? "community-material-active"
                : "community-material-fallback");
    });
    return wrapper;
}
```

- 统一类名：`community-material-card` / `community-material-active` / `community-material-fallback`；
- 旧 `community-glass-card` / `community-glass-active` 在代码与 CSS 中删除，避免两套规则并存；
- `HomePane.addWidget` 改为 `materialCard(widget, 16)`，并给 wrapper 设 `id = "home-card-" + id`；
- `HomePane.rebuildBody` 的账户卡改为 `materialCard(accountCard, 16)`，id=`home-card-account`；
- `HomePane.buildHeader` **不动**；
- `CommunitySideBar` 改用 `GlassSurface` + `community-material-card` 语义（id=`sidebar`），由 CSS 控制 active 时背景透明。

### 6.5 为什么这样能修好三张“没效果”的卡

- 以前：玻璃层不 ready → wrapper 没有 active 类 → `.card` 实色 → 用户看到“没玻璃”；没有日志能说明是哪一步失败。
- 现在：材质层始终有 tint；wrapper 明确处于 `fallback` 或 `active`；`[glass-material]` 会打印 id、尺寸、scene、viewport、layer 状态。即使模糊层失败，卡片也保持同一半透明材质，不会突兀变实色。
- 对滚动到下方的 Java/健康/网络卡，viewport 改为钳制而非隐藏，避免“滚到下面就变实色”。

## 10. 参数与性能预算

| 项 | 预算 |
|---|---|
| 快照 | 640×400 上限；两层同尺寸；每层约 1 MB RGBA |
| 刷新 | 背景/尺寸变化 160 ms 合并；一次生成两张，不按卡片生成 |
| Blur | 远层 2 次 BoxBlur；近层 2 次；不使用实时 `Effect` 链 |
| 表面数 | 主页约 11 个（9 卡 + 账户 + 侧栏）；每个只做两个 viewport |
| 帧率 | 滚动/缩放目标 60 fps；生成期间不阻塞输入；必要时 `layers=1` |
| 降级 | `glass=off` → 实色；`layers=1` → 只远层；快照失败 → tint fallback |
| 内存 | 全局两张图，不随卡片复制；`clip` 每表面一个矩形 |

**注意**：JavaFX 的 `BoxBlur` 在快照阶段执行，不要在 `GlassSurface` 上挂 `Effect`（会对每个表面重复计算）。

## 16. v2 返工方案：五层高斯模糊与 1×1 卡一致性（2026-10-29，待批准）

> 执行说明：§5–§15 是 v3.17.22 已交付的 v1 实现记录，不再作为当前施工依据。本节取代其材质层数、快照尺寸、1×1 卡判断与验收口径；§1、§2、§5.3 已按本节重写。

### 16.1 目标与不变量

用户验收意见（m28683）：

- `java-recommend`（Java 推荐）、`network`（下载源）、`health-check`（启动健康）三张卡“效果还是不对，要和其他卡效果一样”；
- 毛玻璃“精髓是大量多层的高斯模糊”，v1 的 far/near 两层“没有实装”。

因此 v2 的目标不是再调一次透明度，而是同时解决两件事：

1. **把玻璃材质从 2 层升级为 5 个独立半径的高斯模糊层**，让卡片在 1×1、2×1 等不同尺寸下都保留可感知的层次和细节；
2. **让 1×1 的三张卡与其余卡走同一条材质管线**，用统一规则（compact 权重）解决小面积卡片被大半径模糊“糊平”的问题，而不是给三张卡写特例。

不变量：

- 不新增上游 `.java` 侵入点；只改 `community/**` 与两份社区 CSS。
- 不改 9 卡默认布局、左右栏语义、`dashboard.json` 字段、64 px 侧栏宽度。
- 玻璃仍只用于 M3 模式的社区表面（侧栏、标题栏、主页卡片、账户卡）；设置/下载/管理/其他页继续保持实色。
- 无快照时**不隐藏表面**，显示统一 fallback；不允许出现“有的卡透明、有的卡实色”的静默差异。
- 不使用 CSS `-fx-effect: gaussian-blur` 模拟多层；它只对最终合成图做一次模糊，既不是多尺度，也会放大 GPU 开销。
- 不截取真实 UI 做模糊（递归/闪烁风险已在 v1 证明），仍从 `Themes.backgroundProperty()` 的壁纸源离屏重绘。

### 16.2 三张卡为什么“看起来不对”

#### 16.2.1 已排除的静态因素

逐文件核对结论：

| 卡 | 类 | 内容构造 | 自定义背景/内层 GlassSurface |
| --- | --- | --- | --- |
| Java 推荐 | `community/dashboard/builtin/JavaRecommendWidget.java` | `BuiltinWidgets.cardContent(VBox(...), cardFooter(...))` | 无 |
| 下载源 | `community/dashboard/builtin/NetworkWidget.java` | `BuiltinWidgets.cardContent(VBox(...), cardFooter(...))` | 无 |
| 启动健康 | `community/dashboard/builtin/HealthCheckWidget.java` | `BuiltinWidgets.cardContent(VBox(...), cardFooter(...))` | 无 |

三者都继承 `DashboardWidget`，根节点都有 `.card` 类；`HomePane.addWidget` 对全部 9 卡统一调用：

```java
column.getChildren().add(BuiltinWidgets.materialCard(widget, 16, id));
```

所以“漏包 `materialCard`”“三卡单独隐藏玻璃”“三卡自己画了实色背景”这三种解释都不成立。问题更可能在**小面积采样 + 模糊尺度失配**，其次是运行时 fallback。

#### 16.2.2 主假设 H1：1×1 卡的采样面积太小，64 px 远层把细节抹平

以 1200×800 窗口、v1 的 640×400 快照上限计算：

```text
scale = min(1, 640 / 1200, 400 / 800) = 0.533
farBlur = 64 × 0.533 ≈ 34 px
1×1 卡约 300×120 场景像素 → 快照上约 160×64 px
```

一个 64 px 高的采样区域，叠加 34 px 半径（直径 68 px）的高斯核，结果接近该区域的平均色，局部方差趋近 0；2×1 卡横向约 600 px，同样半径下还能保留左右明暗变化。于是**只有 1×1 卡看起来像一块实色/塑料片**，而尺寸更大的卡还能看出壁纸的明暗。

这解释了为什么用户点名的恰好是三张 1×1 卡；但不能只靠推理结案，必须用 H2 的日志排除 fallback。

#### 16.2.3 次假设 H2：运行时走了 fallback

`GlassSurface` 在以下情况显示 fallback 而不是模糊层：

- `getScene() == null`；
- `GlassBackdrop.snapshotProperty()` 为 `null`（壁纸未加载、背景不是图片、或快照尚未生成）；
- viewport 完全越界；
- 宽/高 ≤ 1。

fallback 是 `-m3-color-surface-container-low` 的 72% 实色，视觉上就是“材质没生效”。三张卡若在某个布局时序下先拿到 0 尺寸，或滚动出快照范围，可能落在 fallback；而其他卡因为更早/更大而正常。

v2 必须把 fallback 原因变成**可观测**的，而不是靠猜。

#### 16.2.4 次假设 H3：内容层有未清理的实色底

`.lmcl-m3-glass .community-material-card > .card` 只覆盖卡片根节点的背景。若三张卡内部某个容器（例如 `LinePane`、`ComponentList`、自定义 `VBox`）带不透明背景，就会盖住玻璃。当前源码静态检查未发现三卡有自定义背景，但 CSS 主题包/外观覆盖仍可能给 `.card` 或内部类加背景；v2 需要在 debug 日志里输出实际背景填充数量和来源，并准备一条“材质卡内部容器透明”的兜底规则。

#### 16.2.5 诊断字段（v2 必须落地）

`GlassSurface` 的 `[glass-material]` 日志（仅 `-Dlmcl.visual.debug=true`）至少包含：

```text
id=java-recommend size=302x121 layers=5 scale=0.533 viewport=... fallback=none
id=network size=302x121 layers=5 bgFills=1 cardBg=...
id=health-check size=302x121 layers=5 snapshotGen=17 visible=true
```

并做**变化节流**：同一 id 的尺寸、层数、fallback 原因、snapshot generation 都没变时不重复打印，避免滚动/布局每帧刷日志。

验收时要求 9 张卡各至少有一条带 id 的日志；任何 `fallback` 都必须写明原因，不允许空字符串。

### 16.3 五层模糊设计

#### 16.3.1 层参数

从同一张原始壁纸 Canvas 分别生成 5 张图，每张使用独立半径；不是对上一张继续模糊。

| 层 | 场景半径（px） | 作用 | 默认不透明度 | BoxBlur 迭代 |
| --- | --- | --- | --- | --- |
| L0 ambient | 96 | 大面积底色/环境光 | 0.16 | 3 |
| L1 backdrop | 64 | 中远景 | 0.18 | 3 |
| L2 mid | 40 | 中景 | 0.20 | 2 |
| L3 detail | 24 | 近景纹理 | 0.22 | 2 |
| L4 micro | 12 | 小卡细节、边缘明暗 | 0.22 | 2 |

合成不透明度（按 over 合成，未含 tint）：

```text
1 - (1-0.16)(1-0.18)(1-0.20)(1-0.22)(1-0.22)
= 1 - 0.84 × 0.82 × 0.80 × 0.78 × 0.78
≈ 0.665
```

再叠加 22% 的 tint：

```text
1 - (1-0.665)(1-0.22) ≈ 0.739
```

整体仍低于 v1 的 far .50 + near .30 + tint .28（约 0.748），但**细节层的权重显著提高**，1×1 卡不再被单一大核抹平。

#### 16.3.2 快照分辨率

v1 的 640×400 对 1×1 卡太粗。v2 改为：

```text
MAX_SNAPSHOT_WIDTH  = 960
MAX_SNAPSHOT_HEIGHT = 640
scale = min(1, 960 / sceneWidth, 640 / sceneHeight)
```

1200×800 时 scale≈0.8；1920×1080 时 scale≈0.5。分辨率提高后，L4（12 px）在 1×1 卡上仍有约 6–10 px 的有效半径，能产生可见的局部纹理。

代价：5 张 960×640 RGBA 图约 12.3 MB（不含 Canvas/临时对象），比 v1 的 2 张 640×400（约 2 MB）明显增加；通过“仅在壁纸/尺寸变化时重建 + 160 ms 合并”控制重建频率，静态显示不产生每帧开销。

#### 16.3.3 为什么不能递归模糊

若把 L0 的输出再模糊成 L1，再模糊成 L2，卷积半径会累积，等效于一个超大核：

- 细节被连续低通，层数越多反而越平；
- 每层都要读上一层的全尺寸图，错误会累积；
- 无法独立调节各层权重。

因此必须 `baseImage → 每层独立 BoxBlur(radius[i])`。

#### 16.3.4 1×1 卡的 compact 权重

仅靠五层还不够：1×1 卡仍可能被 L0/L1 的大核主导。`GlassSurface` 根据自身尺寸切换样式类：

```text
Kind == CARD 且 (width < 280 或 height < 150)  →  GlassSurface 自身加 lmcl-m3-glass-compact
```

CSS 覆盖为：

| 层 | 默认 | compact |
| --- | --- | --- |
| L0 | .16 | .10 |
| L1 | .18 | .14 |
| L2 | .20 | .16 |
| L3 | .22 | .24 |
| L4 | .22 | .28 |

compact 合成不透明度约 0.644，加 tint 约 0.722；远层让位、近层增强，卡片会从“平均色塑料片”变成“能看出壁纸明暗与局部结构的磨砂面”。

> 不能把 compact 做成“三张卡专用类”。所有小尺寸材质表面（含未来新增卡、侧栏顶部小块）都按尺寸自动切换，保证规则一致。

### 16.4 代码改造

#### 16.4.1 `GlassSnapshot`

```java
public record GlassSnapshot(
        List<Image> layers,
        double scale,
        double originX,
        double originY,
        int padding) {
    public GlassSnapshot {
        layers = List.copyOf(layers);
        // 非空、每张非 null、尺寸一致、scale > 0、padding >= 0、origin 有限
    }
    public double scenePadding();
    public Point2D imageOrigin();
    public @Nullable Rectangle2D viewport(double sceneX, double sceneY, double width, double height);
}
```

- `layers` 至少 1 张；v2 正常为 5 张。
- `viewport` 保持现有语义：场景坐标 → 快照坐标，钳制到图像边界；完全越界返回 `null`。
- 记录不可变，避免渲染线程与 FX 线程共享可变列表。

#### 16.4.2 `GlassBackdrop`

- 常量：`BLUR_RADII_SCENE = {96, 64, 40, 24, 12}`、`MAX_SNAPSHOT_WIDTH=960`、`MAX_SNAPSHOT_HEIGHT=640`。
- `render()` 只绘制一次 base Canvas；循环生成 `layers[i] = blur(baseCanvas, blurRadius(radii[i], scale), iterations[i])`。
- `padding` 取最大半径（L0）的 `ceil(radius * 1.5) + 2`，保证四边有足够像素供平移采样。
- `origin = host.localToScene(0,0) - padding / scale`，与 v1 相同。
- 160 ms `PauseTransition` 合并尺寸/壁纸变化；每次 render 递增 `generation`，`GlassSnapshot` 带 generation 或在日志中打印，便于排除过期快照。
- 壁纸异步加载失败时发布 `null`，由表面走 fallback；**不在 FX 线程重试网络/磁盘**。

#### 16.4.3 `GlassSurface`

- 固定创建 5 个 `ImageView`（`MAX_LAYERS=5`），`setManaged(false)`、`setMouseTransparent(true)`、`setPreserveRatio(false)`、`setSmooth(true)`；少于 5 层时隐藏多余 view。
- 每层类名 `lmcl-glass-layer-0` … `lmcl-glass-layer-4`，不写 inline opacity；opacity 全部由 CSS 控制。
- `update()` 对每层设置同一个 viewport 和 `fitWidth/fitHeight`；尺寸变化时同步 clip。
- `refreshCompactClass()`：仅 `Kind.CARD` 且 `getWidth() < 280 || getHeight() < 150` 时给 **GlassSurface 自身**加 `lmcl-m3-glass-compact`，否则移除；在 width/height 监听里调用。侧栏 64 px 宽不参与 compact。
- `showFallback(FallbackReason reason)`：`fallback` 可见、各层隐藏、tint 保留；`reason` 枚举 `NO_SCENE / NO_SNAPSHOT / ZERO_SIZE / OUT_OF_BOUNDS`，debug 日志打印。
- 日志节流：仅在 `id + w + h + layerCount + reason + generation` 变化时打印；禁止每次 `layoutBounds` 变化都刷。
- 保持 `Kind.CARD/SIDEBAR` 与 `setDebugName`；标题栏使用同一个类，自然获得 5 层。

#### 16.4.4 `materialCard` 与 `HomePane`

- 保持 `BuiltinWidgets.materialCard(Node content, double arc, @Nullable String debugName)`；
- `HomePane.addWidget` 继续传 9 个稳定 id；账户卡传 `"account"`；
- `materialCard` 内 `GlassSurface` 必须 `setMaxSize(MAX_VALUE, MAX_VALUE)`，外层 `StackPane` 不设固定高度；
- 校验 `StackPane` 的 content 与 surface 同尺寸：如果 content 的 `maxHeight=USE_PREF_SIZE` 导致 wrapper 高度小于 surface，应让 wrapper 的 `minHeight` 取 `content.prefHeight(-1)`，而不是反过来压扁 surface；
- 材质卡内部若存在不透明容器，统一在 `.lmcl-m3-glass .community-material-card` 作用域下置透明，不逐卡写特例。

### 16.5 三卡验收与修复判定

按以下顺序验收，不允许“看起来好一点”就结束：

1. **日志确认**：`java-recommend`、`network`、`health-check` 三张卡各有一条 `[glass-material]`，`layers=5`、`fallback=none`、`size` 非零。
2. **层数/尺寸**：三张卡均为 1×1，应自动带 `lmcl-m3-glass-compact`；其他 2×1 卡不带。
3. **与 2×1 对比**：同一窗口、同一壁纸下，1×1 卡近层纹理可见，且没有明显的“实色塑料片”感；与 2×1 卡的材质方向一致，只允许采样面积不同造成的自然差异。
4. **fallback 回归**：切纯色背景 / 删除壁纸 / 窗口最小化，三卡进入 fallback 并打印原因；恢复壁纸后自动回到 5 层，不需要重启。
5. **滚动/缩放**：上下滚动右栏、缩放窗口，玻璃纹理跟随背景，不出现错位、拉伸、白边或整卡闪烁。
6. **主题切换**：M3 Expressive ↔ Classic ↔ M3 glass off 连续切换 10 次不崩溃；切回后 5 层恢复。
7. **账户卡**：展开/收起、切换账户时，材质不消失、不盖住列表。
8. **性能**：连续拖动窗口 10 秒，UI 不卡死；任务管理器 GPU/CPU 无明显持续飙升；静态停留时 CPU 接近空闲。

若第 1 步显示 `fallback!=none`，先修 fallback 触发条件，不得直接调 opacity 掩盖；若第 1 步正常但观感仍平，按 §16.5.1 调整 compact 权重/快照分辨率。

#### 16.5.1 允许的二次调整范围

- compact 阈值：280×150 → 300×160（只影响 1×1 附近尺寸）。
- L4 半径：12 → 10；L3：24 → 22。
- compact 的 L0/L1 再降 0.02–0.04。
- 快照上限：960×640 → 1024×680；超过 1024 宽需重新评估内存。

不允许的“修复”：

- 给三张卡单独加更不透明的背景；
- 用 `setVisible(false)` 隐藏玻璃；
- 把三卡改成 2×1 或改默认布局来“绕开”；
- 在 CSS 里对卡片直接加 `-fx-effect: gaussian-blur`。

## 18. v3.17.24 实时背景对齐与三张 1×1 卡透明修复（m3expressive25）

> 本节是 2026-11-01 对 m29235 的修复记录。用户原话：
> “模糊要实时渲染，实例快照框的模糊层位置不对，java推荐，下载源和启动健康三个组件没有实现效果”。

### 18.1 根因

1. **层位置错**：`GlassBackdrop` 之前按宿主 `Decorator` 的尺寸手动 `paintImages`/`paintFill` 壁纸，再把同一张壁纸画到 padded Canvas；它没有读取 `DecoratorSkin` 内部真实的 `backgroundNode`。该节点是 `BOTTOM_CENTER` 对齐、高度为 `wrapper.height - titleContainer.height`、透明度绑定 `LauncherBackground.opacity()` 的 `Region`，与手动重绘的宿主坐标系不一致，所以实例快照卡片的模糊层整体偏上/偏下，标题栏透明时更明显。
2. **三张卡没效果（当时归因，已被 v3.17.25 推翻）**：v3.17.24 以为 `community.css` 的 3 类透明规则被后加载的 3 类实色规则覆盖；实际上 `m3-community.css` 的 4 类规则 specificity 更高且运行时命中，CSS 不是根因。v3.17.25 确认真正原因是 1×1 卡内容根铺满整张卡、主题给内容根加了实色 `.card` 背景，把玻璃层盖住；详见 §19.1。
3. **不实时**：`refreshDelay` 为 160ms，且 `refresh()` 在定时器 RUNNING 时直接 return；拖动缩放/切背景时多次变化被合并到一次，用户感知为“模糊不跟着动”。

### 18.2 实现

- `HMCL/src/main/java/org/jackhuang/hmcl/ui/decorator/DecoratorSkin.java`（**第 18 处上游侵入**）：创建 `backgroundNode` 后追加 `backgroundNode.getStyleClass().add("lmcl-launcher-background")`，不改布局、透明度或绑定。
- `HMCL/src/main/java/org/jackhuang/hmcl/community/ui/m3/GlassBackdrop.java`：
  - 新字段 `@Nullable Node backgroundNode` 与 `backgroundNodeListener`；`attach()` 绑定，`detach()` 解绑；
  - `bindBackgroundNode(Region host)` 通过 `host.lookup(".lmcl-launcher-background")` 查找，监听 `layoutBoundsProperty()` 与 `localToSceneTransformProperty()`；
  - `refresh()` 重新查找节点后调用 `render(host, backgroundNode, background, width, height)`；
  - `render(...)` 在非透明窗口先填 `SURFACE_CONTAINER`，优先 `paintBackgroundNode(...)`；节点缺失时退回 `paintImages/paintFill` 并应用 `LauncherBackground.opacity()`；
  - `paintBackgroundNode(...)` 用 `SnapshotParameters` + `new Scale(scale, scale)` 快照真实节点，绘制起点为 `padding + (node.localToScene - host.localToScene) * scale`，因此天然包含 `BOTTOM_CENTER` 与标题栏偏移；
  - `extendEdges(...)` 仅在节点贴住宿主边缘时延伸边缘像素，不把壁纸抹进标题栏空白；
  - `refreshDelay` 160ms→**16ms**；若计时器 RUNNING 只标记待刷新，结束后再合并一次，避免拖动期间完全丢帧。
- `HMCL/src/main/resources/assets/css/m3-community.css`：在 `.lmcl-m3 .community-home .card` 之后增加
  `.lmcl-m3-glass .community-home .community-material-card > .card { -fx-background-color: transparent; -fx-border-color: transparent; }`
  （4 类，高于原 3 类规则），确保三张 1×1 卡的 `.card` 不再盖住 `GlassSurface`。
- `HMCL/src/test/java/org/jackhuang/hmcl/community/ui/m3/CommunityCssTest.java`：断言上述 4 类选择器存在。
- 五层模糊、半径/迭代、`960×640` 快照上限、compact 阈值 `280×150` 与层透明度均不变；不新增第二套材质。

## 21. v3.17.27 边缘渐隐与模糊加深（m3expressive28）

### 21.1 设计决策：渐隐到真实背景，而不是渐进模糊

用户要求“上下不要生硬截断，用模糊过渡”，参考小米 HyperOS 2 的高级材质。工业界的 progressive blur 需要**空间变化**的高斯半径：越靠滚动区边缘越糊。JavaFX 的 `BoxBlur`/`GaussianBlur` 只有节点级均匀半径，没有可变半径模糊；要在 JavaFX 内模拟，只能把滚动区内容逐帧 `snapshot` 成图，再按行做不同半径的模糊或多层叠加。这条路径的代价：

- 每帧快照整个列表（含图片、文本、按钮与玻璃卡片），并与滚动位置同步；主页两列同时滚动时 CPU/GPU 上传成本高，容易掉帧。
- 快照会把玻璃卡片本身也拍进去，再对“已经模糊的卡片”二次模糊，观感不可控。
- 透明窗口/半透明壁纸下，快照内容与真实背景的合成顺序更难保证一致。

本轮改用**过渡带叠层**：过渡带图像的 RGB 直接采样**真实壁纸**（不是列表内容），alpha 从外缘 255 按 smoothstep 降到内侧 0。外缘 RGB 与页面背景同色，因此边界没有可见接缝；玻璃卡片滚入过渡带时按 alpha 逐渐“溶解”为清晰壁纸，视觉上等价于边缘淡出，而不是把内容糊掉。

不采用纯色 scrim 的原因：半透明白/表面色渐变在深色与浅色壁纸下都会偏色，且与玻璃卡片的表面色/tint 不一致；取真实壁纸像素才能跟随壁纸、主题和窗口透明度。过渡带高度固定 72 px，与现有卡片圆角、间距同一量级，足以覆盖“生硬截断”的视觉边界，再高会占用首屏内容并放大采样成本。

### 21.2 实现

**图像生成（`GlassEdgeFadeImage`，304 行）**

- `static @Nullable WritableImage render(Image image, Rectangle2D imageViewport, double opacity, @Nullable Color surface, int width, int bandHeight, int distance, boolean topEdge)`：只读采样壁纸视口，输出 `width × rows` 的 `WritableImage`。
- `rows = clamp(distance, 1, bandHeight)`；上边缘取带内前 `rows` 行，下边缘取后 `rows` 行（`bandOffset = bandHeight - rows`）；采样坐标始终按完整 `bandHeight` 对齐，保证小 distance 时 RGB 与整条带一致。
- `rampAlpha(row, height, topEdge)` 使用 `1 - smoothstep(t)`：外缘 255、内侧 0；`height <= 1` 返回 255。
- 双线性采样以像素中心 `i + 0.5` 计算，越界钳制；`surface` 非空时按 `rgb = src * a + surface * (1 - a)` 合成（`a = srcA/255 * opacity`）；`surface == null`（透明窗口）时只在实际写入行 `a ≈ 1`（容差 `1e-6`）时返回图片，否则返回 `null`。
- 纯 CPU 像素运算，不依赖 `Canvas`/`Toolkit`/`Scene`；每 4 px 距离档生成一次，不逐帧。

**节点（`GlassEdgeFade`，361 行）**

- `public final class GlassEdgeFade extends Region`，`Edge { TOP, BOTTOM }`、`FADE_HEIGHT = 72.0`、`DISTANCE_STEP = 4.0`；跨包被 `HomePane` 引用，因此为 public，但仍在 community 包。
- `scrollDistance(vvalue, contentHeight, viewportHeight) = clamp(vvalue, 0, 1) * max(0, contentHeight - viewportHeight)`；`setDistance` 按 4 px 向上量化、夹到 bandHeight，0 隐藏。
- 节点内一个 unmanaged `ImageView`，TOP 贴顶/BOTTOM 贴底，节点 `mouseTransparent`；监听 `GlassBackdrop.liveRevisionProperty()`、scene/宽高、窗口透明与主题色。
- `update()` 经 `GlassLiveViewport.map(..., margin = 0)` 取完整过渡带视口；隐藏条件包括玻璃关闭/无 live source、无 scene、背景 scene 不一致、band 被裁剪（0.5 px 容差）、mapping 为空、透明窗口无法复现背景。
- 滚动期间每个 4 px 档重渲染一次，单张约“列宽 × 72”（主页列约 340 px 宽），不随每一帧变化。

**HomePane 布局**

- `HOME_PADDING` 底部 12→8 px，总底部留白 76→8 px；右列 `instanceColumn` 底部 padding 56 px（`64 - 8`），两处合计仍为 64 px 启动按钮安全区，左列不加。
- 两列 `ScrollPane` 各包一层 `StackPane`（`createColumnFrame` 复制 min/pref/maxWidth、`minHeight=0`、`maxHeight=MAX`），上下叠 72 px fade；`HBox.setHgrow` 移到实例列 frame。
- `vvalue`、`viewportBounds`、内容 `layoutBounds` 共 6 个监听统一重算上下边缘距离；`refresh()` 重算一次，`dispose()` 移除监听并释放四个 fade。

**模糊加深**

- `GlassBackdrop` 五层半径 **96/64/40/24/12 → 128/88/56/32/16**；迭代 3/3/2/2/2、层数 5、960×640 上限不变。
- 场景外扩 `paddingFor(0.5)` 74→98、`paddingFor(1.0)` 146→194；`GlassSurface.java:58` 与 `GlassLiveViewport.java:81` 的 Javadoc 同步为 128 px / 194 px。
- 真实半径约 +33%，五层同时加深，不是只加最远层。

### 21.3 回退

## 24. v3.17.30 过渡带材质化：让渐隐带与卡片同质（m3expressive31）

### 24.1 为什么改

§21 引入的两列滚动区上下 72 px 过渡带，带内是**清晰的壁纸采样**：它把真实壁纸按 alpha 渐隐到透明，而卡片是「五层高斯模糊 + 22% tint」。两者材质不同，带子在卡片边缘形成一条可辨的“色带”（颜色/亮度与卡片底不一致），被用户指为不属于毛玻璃。同时旧滚动路径每 4 px 重建整条带、逐像素 `setArgb`、带宽随行数跳档、alpha 曲线随行数重排，滚动中出现抖动/闪烁。

本轮不改五层模糊本身，只把**过渡带的内部材质**改成与卡片磨砂底同质，并把滚动路径从“重建”改成“缩放”。

### 24.2 参数与公式

**材质化（`GlassEdgeFadeImage`，304→450 行）**

- `render` 去掉 `distance` 参数，一次输出固定 `width×bandHeight` 整条带；先按 cover 采样、与表面色合成得到 sharp 底图，`surfaceColor==null`（透明窗口）返回 `null`。
- `materialize`：按 `MATERIAL_BLOCK_SIZE=24` 做块平均（`meanBlockColor`），再按块中心双线性上采样到整带，按 `MATERIAL_TINT=0.22` 混入表面色——与卡片“模糊 + tint”的观感对齐，但成本远低于对整带做高斯模糊。
- 边缘混合 `edgeSharpWeight`：靠边 `EDGE_SHARP_ROWS=2` 行保留 sharp 采样，随后 `EDGE_BLEND_ROWS=6` 行线性过渡到材质层，避免带子与滚动区内容之间出现硬边。
- `rampAlpha` 由 §21 的 smoothstep 改为 `(1-t)^2`：上带 `t=row/(h-1)`、下带 `t=(h-1-row)/(h-1)`，边缘 alpha 255、内侧 0。
- 逐像素 `setArgb` 只发生在整带重建；重建由 `GlassEdgeFade.update()` 在几何/壁纸/主题变化时触发。

**滚动路径（`GlassEdgeFade`，361→392 行）**

- `DISTANCE_STEP` **4→1.0**：`setDistance` 在行数变化且已有图时只调 `applyRows()`（`setFitHeight(rows)` + `relocate` + `setFitWidth` + 可见性），只有尚无图时才 `update()` 整带重建。
- 整带一次渲染后按 `rows/bandHeight` 缩放，带宽不跳档、alpha 曲线不重排；`hide`/`layoutChildren`/`dispose`/`debug` 保留。

### 24.3 与 §17–§23 的关系

- §17–§20（96/64/40/24/12 历史层、三卡透明守卫、footer 点击）与 §22/§23（192 档五层、tint 0.22、质感三措施回退）继续有效；本轮**不改卡片材质**，只改过渡带内部材质与滚动驱动。
- §21 的几何全部保留：72 px 带高、页底 8 px、右列 56 px、顶部 6 px 间距、静态/尽头隐藏、`glass=off`/Classic 回退；被替换的是 §21 的 **smoothstep alpha 与 4 px 量化**（现为 `(1-t)^2` 与 1 px 步长），以及带内“清晰壁纸”取样（现为块平均 + tint 材质）。
- §22.2 的五层半径/迭代、§23.2 的“五层模糊 + tint + 圆角裁剪”不变；过渡带材质只是向该定义靠拢，不新增模糊层。
- 回退顺序沿用 §23.4：性能不足先整包回退 `m3expressive30`（无过渡带材质化）。

### 24.4 回退与取舍

- glass=off / Classic：`GlassEdgeFade` 仍按 §21 隐藏，材质化参数不参与渲染；外观与 v3.17.29 一致。
- 透明窗口：`surfaceColor==null` 直接返回 `null`，带子隐藏，不出现“无 tint 的清晰壁纸条”。
- 取舍：材质化后卡片间隙会出现一条很淡的磨砂条（带子在滚动区外仍按 72 px 覆盖），这是“与卡片同质”的必然结果；如实机判定碍眼，可调低 `MATERIAL_TINT` 或缩短带高，但不再回到“清晰壁纸”取样。
- 24 px 块平均是性能与观感的折中：块越小越接近模糊，成本越高；当前值未在 Windows 实机上做帧率/观感对照。

### 24.5 未实机验证

- **Windows 实机未验收，需确认**：带内材质是否与卡片磨砂底一致、色带是否消失、间隙淡磨砂条能否接受、`(1-t)^2` 曲线是否比 smoothstep 更自然、72 px 带高是否仍合适。
- 未测 DPI 100/125/150/200%、浅色/深色/高对比壁纸、滚动中带子与卡片边缘的过渡稳定性；不写“视觉已修复/已实机验证”。

### 26.1 为什么恢复，且不是简单回滚

- v3.17.31 删除底部带后，用户实机反馈“这次下方的模糊直接没有了”“左侧下方没有留下边距”“右侧下方离按钮距离太远”“三个按钮没有置顶且字显示不全”。
- 不能直接回滚 v3.17.30 的代码：那版底部带外缘仍有 2 行清晰壁纸 + 6 行过渡，正是用户“我不希望有亮的这条”指的亮边；回滚会把亮边一起带回来。
- 因此本版走 §25.5 预留的路线——“去掉 `EDGE_SHARP_ROWS` 的清晰外缘（整带纯材质化）”，恢复带子但让外缘与带身同为材质色。

### 26.2 整带材质化与外缘处理

- `GlassEdgeFadeImage`（450→400 行）删除 `EDGE_SHARP_ROWS`、`EDGE_BLEND_ROWS`、`edgeSharpWeight`、`blendRgb`；`render` 不再对靠边行采样清晰壁纸。
- 保留 `MATERIAL_BLOCK_SIZE=24`（`:59`）与 `MATERIAL_TINT=0.22`（`:62`）：`materialize`（`:192-284`）对 cover 采样图做 24 px 块平均，再按块中心双线性上采样，最后按 `1-0.22` 混入表面色。
- `render`（`:120`）第三步对整条带逐行写 `(alpha<<24)|material[...]`；外缘行使用同一材质色，alpha 仍由 `rampAlpha`（`:68-91`）按 `255*(1-t)^2` 从 255 递减到 0。外缘不再出现比带身更亮的像素。
- 透明窗口 `surfaceColor==null` 仍直接返回 `null`（与 §24 一致）。
- `GlassEdgeFade.render` 的调用点（`GlassEdgeFade.java:294`）与 72 px 带高、1 px 步长、尽头隐藏不变。

### 26.3 与 §25 的关系

- §25 删除底部带；本版恢复底部带，但采用 §25.5 的“整带纯材质化”分支，并保持 §25 的页底 8 px 与“内容底 57 px”布局替代 64 px 外边距。
- 顶部带与底部带共用 `GlassEdgeFadeImage.render`：清晰外缘删除后，顶部带外缘也同步变为材质色。顶部带几何与接线未动，这是共享渲染器的必然结果，待实机确认观感。
- §24 的 24 px 块平均、双线性、0.22 tint、`(1-t)^2` alpha 继续有效；§22/§23 的 192 档五层与 tint、§17–§20 的实时采样与三卡透明守卫均未改。

### 26.4 验证与测试

- `GlassEdgeFadeImageTest` 12 例；新增 `renderMaterializesWholeBandIncludingOuterEdges`（`:133-169`）断言外缘行同为材质色 `0x640064`、alpha 255，与相邻行容差 2；`renderTintsMaterialWithSurfaceColor` 期望外缘 `0x38C7`；半透明合成期望 `(255,155,155)`。
- `renderBottomEdgeReversesRamp`（`:117`）、`rampAlphaMirrorsForBottomEdge`（`:61`）继续覆盖 BOTTOM 方向；`GlassEdgeFadeTest` 10 例。
- 完整构建/测试/打包数字见[步骤 21 §41.3](steps/21-主页重构与侧边栏移除.md)。

### 26.5 回退条件

- 若实机反馈“外缘材质色与内容衔接生硬”，可调低 `MATERIAL_BLOCK_SIZE` 或 `MATERIAL_TINT`，或恢复少量清晰行但需接受亮边风险；不改五层与 tint。
- 整包可回退 `m3expressive32`（无底部带）或 `m3expressive31`（有亮边）；回退 `m3expressive32` 只需恢复 `HomePane` 两条底部带与 `HOME_PADDING` 8 px，并重新引入 `EDGE_SHARP_ROWS`/`EDGE_BLEND_ROWS` 的清晰外缘。

### 26.6 未实机验证

- **Windows 实机未验收，需确认**：两列底部带外缘无亮边、带身与卡片材质一致；滚到底带子淡出；顶部带外缘材质化可接受；DPI 100/125/150/200%、浅色/深色壁纸、透明窗口、`glass=off`/Classic 回退。
- 不写“视觉已修复/已实机验证”。
