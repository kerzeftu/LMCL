## 0. 结论摘要

本方案分两期，避免一次改动把“任务生命周期”和“下载内核”同时打开。

| 期 | 内容 | 是否需要新上游侵入 |
|---|---|---|
| 一期 | 后台下载中心、管理页“下载管理”、其他页“小工具 → 下载工具”（分段下载器） | 只新增 **#18** `TaskExecutorDialogPane.java` |
| 二期 | `FileDownloadTask` 级 aria2 式多连接分段下载，游戏/模组/资源全部受益 | 再新增 **#19** `HMCLCore/.../FileDownloadTask.java` |

核心判断：

1. **后台运行不应重写任务系统**。现有 `TaskExecutor` 已经能在没有对话框时继续运行；缺的是“谁持有它、谁记录它、谁在 UI 里重新找到它”。因此新增 `DownloadCenter` 作为任务登记与历史中心，`TaskExecutorDialogPane` 只负责把任务交出去。
2. **不能直接复用 `TaskListPane` 当管理器**。它只绑定一个 executor，任务完成即删除节点，没有历史、重开、取消入口。
3. **分段下载必须落在 `FileDownloadTask` 层**。它有 48 个构造点，逐个改调用点会不可维护；在 `FileDownloadTask` 内部加策略，才能同时覆盖游戏本体、资源、库、模组、整合包和工具下载，并保留缓存、校验、镜像 fallback。
4. **第一期就能交付一个完整可用的“后台下载 + 下载管理 + 下载工具”**，不依赖二期。二期默认关闭、可单项回退，避免 CDN 不支持 Range 时把普通下载弄坏。
5. 不引入 aria2 二进制、不引入 BT/磁力、不新增第三方依赖；只用 JDK `HttpURLConnection`，复用现有 `NetworkUtils` 的 UA、代理、语言与 API key 处理。

建议默认值：

- 启动器分段下载：**默认开启**，但只对“有 SHA-1 完整性校验、总大小 ≥ 8 MiB、服务器支持 Range”的文件生效；可在设置里关闭。
- 每文件连接数：**4**；全局分段连接上限：**8**；工具允许 1–16。
- 后台运行：**显式按钮** `[后台运行]`，不是“关窗即后台”。ESC / 取消仍取消任务。
- 安装/整合包任务：一期不支持暂停/继续；下载工具支持暂停、继续、重启后继续。
- 历史保留：最近 **50** 条；应用退出时运行中的任务标记为“已中断”，不假装完成。

## 1. 需求与边界

### 1.1 用户原话

> 要求下载的时候，下载任务可以后台运行，然后可以在管理-下载管理（下载管理是新加的）里面查看，下载工具在其他-小工具里，类似pcl2，做一个分段下载选项，可以用启动器自带的分段下载功能下载其他文件。启动器自己下载游戏和模组等参考一下aria2的路线，并且配置分段下载，先写md，还有些要考量的。

### 1.2 范围

必须做：

1. 下载任务可以后台运行：关闭任务对话框后任务继续，不弹“已取消”。
2. 管理页新增“下载管理”tab：活动任务、历史任务、进度、速度、状态、取消/打开目录/清理。
3. 其他页“小工具”新增“下载工具”：粘贴 URL、选择目录、设置分段数，下载任意 HTTP(S) 文件；有进度、速度、暂停/继续/取消。
4. 启动器自身下载（游戏、资源、库、模组、整合包等）支持 aria2 式多连接分段下载，并有配置项。
5. 先写本方案 md；用户批准后才改代码。

明确不做（本方案不包含）：

- 不集成 aria2 进程，不实现 aria2 JSON-RPC，不做 BT/磁力链接。
- 不做浏览器扩展、系统托盘、Windows 服务、开机自启下载。
- 不做账号级下载队列、跨设备同步、云端历史。
- 不重写 `Task`/`TaskExecutor` 框架，不把 `TaskListPane` 改成通用任务管理器。
- 不做安装任务的“暂停/继续”（安装任务由多层 `Task` 组合，暂停语义不可靠）。
- 不做下载限速（可作为后续独立功能；本方案先控制连接数）。
- 不改变现有下载源、镜像、BMCLAPI、Modrinth/CurseForge 的地址策略。

### 1.3 成功标准

1. 启动一个游戏安装或模组下载，点 `[后台运行]` 后对话框关闭，任务继续；从管理 → 下载管理能看到它，进度持续变化；完成后状态变为完成。
2. 后台任务运行时关闭再打开管理页，任务仍在；应用重启后，未完成任务显示“已中断”，不会显示为“下载中”。
3. 下载工具能下载一个 1 GiB 测试文件，4 连接分段，速度明显高于单连接；暂停后可继续；关闭启动器再打开后可继续。
4. 启动器下载游戏本体/资源时，抓包能看到多个 `Range` 请求；服务器不支持 Range 时自动退回单连接，文件校验通过。
5. 现有下载、缓存、完整性校验、镜像 fallback、整合包安装无回归。
6. 所有 UI 文案三语齐全；没有 FX 线程磁盘 IO；没有新增内存泄漏。

## 3. 设计决策

| 编号 | 决策 | 理由 | 备选（否决） |
|---|---|---|---|
| D1 | 后台运行用显式 `[后台运行]` 按钮 | ESC/取消语义明确，不改变用户预期 | 关窗即后台：会让人以为取消 |
| D2 | `DownloadCenter` 只做登记/历史/控制，不重写 `Task` | 风险小，现有 executor 生命周期足够 | 重写任务框架：成本过高 |
| D3 | 安装任务不支持暂停/继续 | 多层 `Task` 组合无法安全暂停 | 用线程挂起：会卡死网络/磁盘 |
| D4 | 工具支持暂停/继续/重启后续传 | 单文件可控，PCL2 同类工具体验 | 只支持取消 |
| D5 | 分段下载策略放在 `FileDownloadTask` | 一处覆盖 48 个调用点 | 改 48 个调用点 |
| D6 | 只对有完整性校验且 ≥8 MiB 的文件尝试分段 | 避免小文件、无校验文件被拆坏 | 所有文件都分段 |
| D7 | 固定连接数 + 分片队列；不动态加减连接 | 行为可预测、易测试 | 动态分片：首版复杂 |
| D8 | 服务器不支持 Range 就整文件回退单连接 | CDN/对象存储兼容性 | 强制分段：会失败 |
| D9 | 不引入 aria2/外部进程/新依赖 | 打包体积、许可、跨平台 | 内置 aria2：不可控 |
| D10 | 管理页 tab 顺序：账户、实例、下载管理、Java | 下载管理是常用运行态入口 | 放在最前：干扰账户操作 |

| D12 | 新 UI 走 M3 token/控件 | 当前默认 M3，视觉一致 | 旧样式拼贴 |

## 4. 后台下载中心

### 4.1 架构

```text
TaskExecutorDialogPane
  │ setExecutor(executor, title)
  ▼
DownloadCenter (单例, FX 线程)
  ├─ attach(executor, title) -> Attachment
  ├─ TaskListener.onRunning/onStop -> 更新 DownloadJob
  ├─ 控制：cancel(job) / background(job)
  └─ 历史：DownloadHistoryStore (IO 线程, 原子写)

DownloadManagerPane（管理页 tab）── 订阅 DownloadCenter.jobs()
DownloadToolPane（其他页 tab）── 创建 SegmentedDownloadController → DownloadCenter
```

### 4.2 数据模型

`DownloadJob`（FX 属性，除标注外只在 FX 线程读写）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | UUID；历史主键 |
| `title` | `String` | 对话框标题；默认“下载任务” |
| `kind` | `DownloadJobKind` | `LAUNCHER` / `TOOL` / `OTHER` |
| `state` | `DownloadJobState` | `RUNNING` / `COMPLETED` / `FAILED` / `CANCELLED` / `INTERRUPTED` |
| `backgrounded` | `boolean` | 用户是否点过后台运行 |
| `createdAt` / `finishedAt` | `Instant` | 历史排序 |
| `progress` | `double` | -1 表示不确定；0..1 |
| `stage` | `String` | 当前阶段/任务名（可空） |
| `bytesDownloaded` / `totalBytes` | `long` | 仅单文件/工具可确定；否则 -1 |
| `speedBytesPerSecond` | `long` | 工具精确；启动器任务显示全局速度 |
| `targetDirectory` | `@Nullable Path` | 打开目录；来自任务或工具设置 |
| `error` | `@Nullable String` | 失败摘要（脱敏） |
| `tool` | `@Nullable ToolSpec` | 工具 job 的 URL/文件名/连接数/校验值，不写 token |

`DownloadJobKind.OTHER` 不显示在下载管理中；用于非下载任务复用同一对话框时保持静默。

`Attachment`：

- `@Nullable DownloadJob jobProperty()`：检测到下载任务后才非空。
- `BooleanProperty backgroundable`：`job != null && state == RUNNING`。
- `Runnable hideDialog`：由 pane 提供，只关 UI，不取消。

### 4.3 生命周期

```text
attach (executor 创建, 未启动)
  │
  ├─ onRunning(task)
  │    ├─ 第一次检测到 FetchTask/FileDownloadTask → 建 DownloadJob(kind=LAUNCHER)
  │    ├─ 后续任务 → 更新 stage，保留总进度策略
  │    └─ 不是下载任务 → 不建 job（OTHER 静默）
  │
  ├─ 用户点 [后台运行] → hideDialog(); backgrounded=true
  │
  ├─ onStop() → COMPLETED / FAILED / CANCELLED
  │    ├─ 若 backgrounded → 发 Toast，不弹成功/失败框
  │    └─ 若未后台 → 保持现有 autoClose 行为
  │
  └─ 应用退出 → shutdown() 把 RUNNING 写为 INTERRUPTED
```

状态映射：

| 条件 | 状态 |
|---|---|
| executor 运行、无异常 | `RUNNING` |
| `onStop` 且无异常、`!executor.isCancelled()` | `COMPLETED` |
| `onStop` 且异常 | `FAILED` |
| 用户取消 | `CANCELLED` |
| 启动时发现上次 `RUNNING` | `INTERRUPTED` |

### 4.4 登记钩子（第 18 处）

在 `TaskExecutorDialogPane.setExecutor(executor, autoClose)` 内：

1. 保留现有 `TaskListPane` 绑定、`onStop` 自动关闭。
2. 调用 `DownloadCenter.get().attach(executor, titleProperty, this::hideDialog)`。
3. 新增 `[后台运行]` 按钮，初始不可见；`attachment.backgroundableProperty()` 为 true 时显示。
4. 点击后：`attachment.background()`；`fireEvent(new DialogCloseEvent())`；不调用 `executor.cancel()`。
5. 向导任务的 `onEnd()` / 页面收尾逻辑不拦截；后台只隐藏任务对话框，不改变安装向导的完成回调。

`Controllers.taskDialog` 和 `TaskExecutorDialogWizardDisplayer` 不需要再改；两处都走这个 pane。

`hideDialog` 只发 `DialogCloseEvent`，与 `DialogPane.onCancel` 的 UI 语义一致；任务不取消。

**无下载任务时**：`attach` 不建 job，按钮永不出现；普通“安装 Java”“检查更新”等对话框行为与现在完全一致。

### 4.5 进度/速度/阶段

- 单个 `FetchTask`：进度用 `task.progressProperty()`；`totalBytes` 可从 Range 探测或 `Content-Length` 取得；没有就 -1。
- 多个任务（游戏安装）：总进度不确定，`progress=-1`；显示“当前：下载资源 3/12”这类 stage，不伪造百分比。
- 速度：
  - 工具：`SegmentedDownloadController` 自己按字节/秒计算。
  - 启动器任务：使用 `FetchTask.SPEED_EVENT` 的全局速度，显示在管理页顶部；单 job 不显示精确速度，避免多个任务相加误导。
- 完成文件数：`FileDownloadTask` 完成时累加 `completedFiles`；不显示“总文件数”，因为没有可靠总数。

### 4.6 取消与后台

| 操作 | 行为 |
|---|---|
| ESC / 对话框关闭按钮 | 现有语义：取消任务（`btnCancel` → `executor.cancel()`） |
| `[取消]` | 取消任务；job → `CANCELLED` |
| `[后台运行]` | 只隐藏对话框；job 继续；`backgrounded=true` |
| 管理页 `[取消]` | `executor.cancel()`；job → `CANCELLED` |
| 应用退出 | 任务随进程结束；历史写 `INTERRUPTED` |

注意：`AsyncTaskExecutor.cancel()` 只置标记，实际停止依赖任务轮询；`DownloadCenter` 不能假设 cancel 立即完成，显示“正在取消…”直到 `onStop`。

### 4.7 持久化与重启

`DownloadHistoryStore`：

- 路径：`<localHome>/community/downloads/history.json`。
- 写入：临时文件 + `ATOMIC_MOVE`；不写 URL、token、API key、完整异常堆栈。
- 读取：损坏/版本不识别的文件移到 `history.corrupt-<timestamp>.json`，用空历史启动。
- 启动：所有 `RUNNING` → `INTERRUPTED`；`backgrounded` 保留用于 UI 说明。
- 工具 job 额外检查 `tool/<id>.json` 与 `.part` 是否存在；存在且元数据完整时状态 `INTERRUPTED` 且可 `[继续]`；否则只保留历史。
- 不自动恢复安装任务；不自动重试失败任务。

`history.json` 结构示意：

```json
{
  "schema": 1,
  "jobs": [
    {
      "id": "4b6f...",
      "title": "安装 Minecraft 1.21.1",
      "kind": "LAUNCHER",
      "state": "INTERRUPTED",
      "createdAt": "2026-10-27T01:00:00Z",
      "finishedAt": "2026-10-27T01:04:00Z",
      "backgrounded": true,
      "targetDirectory": ".minecraft/versions/1.21.1",
      "error": null
    }
  ]
}
```

### 4.8 线程模型

- `DownloadCenter` 的 `ObservableList`、`DownloadJob` 属性只在 FX 线程改。
- `TaskListener` 回调可能在任意线程：统一 `Platform.runLater`；同一 job 的更新合并，避免每 10 ms 刷新 UI。
- `history.json` 读写、工具文件 IO 在 `Schedulers.io()`。
- `DownloadCenter.shutdown()` 只做快照和标记，不等待磁盘；用 shutdown hook 或 `CommunityBootstrap` 退出路径，保证不阻塞退出。
- 禁止在 FX 线程做 `Files.size`/`Files.write`/`load`。

## 7. 分段下载引擎

### 7.1 协议探测

对每个候选文件，先发探测请求：

```http
GET <url>
Range: bytes=0-0
Accept-Encoding: identity
User-Agent: <NetworkUtils 现有 UA>
```

判定可分段的条件：

1. 状态码 `206`；
2. `Content-Range: bytes 0-0/<total>`，`total > 0`；
3. `Accept-Ranges: bytes`（有则更可信，没有但 206 + Content-Range 也可）；
4. 强 `ETag`（不以 `W/` 开头）或 `Last-Modified`；两者都没有则不续传、不分段；
5. `Content-Encoding` 为 identity 或缺失；
6. `total >= minSize`（默认 8 MiB）。

不满足：关闭连接，返回 `UNSUPPORTED`，由 `FileDownloadTask` 走原单连接。

### 7.2 分片计划

- `connections = clamp(settings.connections, 1, 16)`；运行中固定。
- `chunkSize = clamp(total / (connections * 4), 1 MiB, 16 MiB)`。
- 分片数 `ceil(total / chunkSize)`，最后一个分片到 `total-1`。
- 队列按 offset 升序；worker 取下一个未完成分片。
- 每分片最多重试 3 次：500 ms / 1 s / 2 s 退避；`429`/`5xx` 才重试；`4xx` 直接失败。
- 任何分片收到 `200`（服务器忽略 Range）→ 整个文件中止分段，清理后回退单连接；不允许把 200 响应写进某个分片。
- 任何分片 `Content-Range` 与请求不一致、`ETag`/`Last-Modified` 变化、`416` → 中止，回退或失败。
- 分片之间不重叠、不遗漏；完成后 `FileChannel` 长度为 `total`。

### 7.3 写入与校验

- 临时文件：`Files.createTempFile(parent, ".lmcl-download-", ".part")`；与最终文件同目录，保证 `ATOMIC_MOVE`。
- 预分配：仅当总大小已知且磁盘剩余空间 ≥ total + 64 MiB 时 `RandomAccessFile.setLength(total)`；否则边写边扩展。
- 写入：每个 worker 用独立 `FileChannel` + `position(offset)`；`FileChannel.write` 循环直到写完。
- 进度：每个分片维护 `AtomicLong downloaded`；每 200 ms 汇总。
- 完成后：
  1. 关闭所有 channel；
  2. 校验文件长度 == total；
  3. 计算/校验 `IntegrityCheck`（复用 `FileDownloadTask` 的现有算法与比较逻辑，失败抛同类 `ChecksumMismatchException`）；
  4. 依次执行 `integrityCheckHandlers`（例如 `LibraryDownloadTask` 的 `ZIP_INTEGRITY_CHECK_HANDLER`），不能跳过；
  5. `Files.move(temp, target, ATOMIC_MOVE, REPLACE_EXISTING)`；
  6. 更新 `CacheRepository`（能复用的路径复用，不新写缓存协议）。
- 失败/取消：关闭 channel，删除 `.part`（工具在“暂停”时保留；在“取消”时删除）。
- 文件锁：工具 `.part` 用 `FileChannel.tryLock()`；拿不到说明另一个实例在下载，拒绝启动。

### 7.4 回退与重试

| 场景 | 行为 |
|---|---|
| 探测不支持 Range | 回退原 `FetchTask` 单连接 |
| 某个分片 200 | 中止分段，清理，回退单连接 |
| 分片 5xx/429 | 分片级重试 3 次；仍失败则整文件失败（不回退，避免重复下载大量数据） |
| 校验失败 | 删除临时文件，抛 `IOException`；不自动回退（防止重复下载坏文件） |
| 用户取消 | 抛 `CancellationException`；`FileDownloadTask` 保持取消状态 |
| 磁盘不足 | 启动前检查；写入中 `IOException` → 失败并清理 |

### 7.5 并发上限

新增 `SegmentedDownloadLimiter`（`HMCLCore` 新类）：

- `Semaphore global = new Semaphore(settings.maxGlobalConnections)`，默认 8。
- `ConcurrentHashMap<String, Semaphore> perHost`，每个 host 默认 4。
- worker 在发请求前 `acquire`，响应关闭后 `release`；取消/异常必须 `finally release`。
- 不与 `FetchTask.SEMAPHORE` 合并；普通单连接任务仍走原并发。设置页提示“分段连接 + 普通下载并发可能叠加”。
- 可选：`maxGlobalConnections=0` 表示禁用分段（等价于开关关）。

### 7.6 `FileDownloadTask` 集成（第 19 处）

`FileDownloadTask.execute()` 增加早分支：

```java
if (!SegmentedDownloadPolicy.shouldAttempt(integrityCheck, uris)) {
    super.execute();
    return;
}
EnumCheckETag cached = shouldCheckETag();
if (cached == EnumCheckETag.CACHED) {
    return;
}
if (!SegmentedDownloadSupport.download(this, file, uris, integrityCheck)) {
    super.execute();
}
```

要点：

- `shouldAttempt` 检查策略开关与 `integrityCheck != null`；总大小阈值在 support 的探测结果里判断。
- `shouldCheckETag()` 仍先查完整性缓存；命中直接返回，避免重复下载。
- `SegmentedDownloadSupport.download` 返回 `false` 表示“未开始/不支持”，此时没有留下临时文件；返回 `true` 表示已落盘并通过校验。
- 分段成功后调用 `cacheFile()`（同一类内可见）；跳过 `cacheRemoteFile` 是已知偏差：下次仍会探测，而不是走 ETag 缓存，后续版本再补。
- 必须执行 `integrityCheckHandlers`；`LibraryDownloadTask.java:123` 等会加 `ZIP_INTEGRITY_CHECK_HANDLER`，跳过会漏掉压缩包校验。
- 不改 `FileDownloadTask` 的 48 个调用点，不改 `FetchTask` 的普通路径。
- `caching` 为 false 的文件仍可分段（如工具），但 `FileDownloadTask` 本身只处理有 `integrityCheck` 的文件，工具走独立引擎。

### 10.1 静态与单元

- `VERSION_ROOT=1.0 BUILD_NUMBER=0 ./gradlew :HMCL:compileJava`。
- `:HMCL:checkTranslations`。
- community 全量测试；全量 `:HMCL:test`。
- `SegmentedDownloadControllerTest`：分片计划数学、重试、200 回退、ETag 变化、校验失败、取消、暂停/继续。
- `DownloadJobTest`：状态机、`INTERRUPTED` 转换、历史脱敏、50 条截断。
- `DownloadHistoryStoreTest`：原子写、损坏恢复、未知字段保留。
- `SegmentedFileDownloadTaskTest`：本地 `HttpServer` 支持/不支持 Range、缓存命中、SHA-1 校验、2/4/8 连接。
- 所有测试不依赖外网；HTTP server 在 `127.0.0.1` 随机端口。

### 10.2 手工验收（Windows 11）

1. 安装 Minecraft 1.21.1（原版），下载中 `[后台运行]`；关闭对话框；管理 → 下载管理能看到进度；完成后状态完成；打开版本目录文件存在。
2. 安装 Fabric/Forge 或整合包，后台运行；期间切换设置/其他页；任务不中断。
3. 任务运行中关闭启动器；重开；管理页显示“已中断”，不是“运行中”。
4. 下载工具下载 1 GiB 文件，4 连接；任务管理器/资源监视器看到多条连接；暂停后连接释放；继续后从断点继续；关闭启动器再打开，工具页显示“可继续”，继续成功。
5. 用不支持 Range 的 URL（或本地 Python `http.server` 不带 Range）测试回退；文件校验通过。
6. 设置里关闭分段下载，抓包只有单连接；再开启，抓包出现 `Range`。
7. 按住 ESC / 点取消，任务确实取消；`[后台运行]` 不取消。
8. M3 Expressive / M3 关闭玻璃 / Classic 三种主题下页面/按钮/进度条不破版；DPI 100%/125%/150% 下不裁切。
9. 无 FX 线程卡顿：下载时切换页面、滚动管理列表。
10. 网络断开/恢复：失败显示错误；不崩溃；不无限重试。

### 10.3 性能/资源

- 4 连接 1 GiB 下载，速度相对单连接提升 ≥ 1.5×（受服务器/线路限制，记录实测值，不承诺固定倍数）。
- 连接数不超过设置上限；取消后 5 秒内连接释放。
- 管理页 50 条历史 + 5 个活动任务，滚动/切换无 >100 ms 卡顿。
- 内存增量 < 30 MiB（不含 JVM 文件缓存）。

### 10.4 回归

- 游戏本体/资源/库/模组/整合包安装全部通过。
- 完整性校验失败时仍能正确报错，不落坏文件。
- 缓存命中、BMCLAPI 镜像、Modrinth/CurseForge 下载不受影响。
- `TaskExecutorDialogPane` 对非下载任务行为不变。
- 现有 189 个社区测试、全量 299 个测试保持通过。

## 11. 风险与回退

| 风险 | 等级 | 缓解 | 回退 |
|---|---|---|---|
| 改 `FileDownloadTask` 破坏下载/校验 | 高 | 二期独立提交；默认阈值 8 MiB；全套 Range/缓存测试；先灰度设置 | 设置关闭分段；或 revert #19 |
| CDN 不支持 Range / 返回 200 | 高 | 探测 + 分片 200 立即回退；不把 200 写入分片 | 自动回退单连接 |
| 连接数过高触发限流/封 IP | 高 | 默认 4/文件、8 全局、每 host 4；可调低；UA 复用现有 | 设置 1 连接 |
| 后台任务被误以为取消 | 中 | 显式按钮；管理页红点；完成后 Toast | 去掉按钮，恢复关窗即取消 |
| 关闭应用丢任务 | 中 | 历史标记中断；工具保留 `.part` 可续 | 不承诺跨进程继续安装 |
| `TaskExecutorDialogPane` 改动影响所有对话框 | 中 | 只在检测到下载任务时启用；非下载无按钮；测试现有对话框 | revert #18 |
| 进度不准/总大小未知 | 中 | 不确定进度条 + stage；不伪造百分比 | 只显示 stage |
| 内存/监听泄漏 | 中 | job 完成清 executor 引用；listener 移除；历史不持任务 | 限制历史 50 |
| FX 线程 IO 卡顿 | 中 | 所有磁盘/网络 IO 在 IO 线程；属性更新合并 | 代码审查 + 性能测试 |
| 路径/文件名安全 | 中 | 拒绝 `..`、分隔符、控制字符；限制长度；目标目录用户确认 | 禁用自定义文件名 |
| URL 带 token 写入历史 | 中 | 历史只存 host/文件名，不存 query；日志脱敏 | 清空历史 |
| 工具下载被用于盗链/滥用 | 低 | 只做普通 HTTP(S)；不绕过鉴权；不内置盗版源 | 不提供预设源 |
| 包体积增加 | 低 | 无新依赖；只增 class/资源 | — |

**总开关**：

- 一期：管理页不注册 tab 即可隐藏；`TaskExecutorDialogPane` 钩子可用系统属性 `lmcl.download.center=off` 跳过。
- 二期：`segmentedEnabled=false` 或 `-Dlmcl.download.segmented=off` 立即回退单连接，不需要改代码。
- 发布包默认值可在不改代码的情况下通过设置调整；若 Windows 验收失败，直接把默认改为关闭。

## 14. 附：本方案明确不承诺的事

- 不承诺所有服务器都能提速；不支持 Range 的服务器只会回退。
- 不承诺安装任务在应用退出后继续；只有工具 `.part` 支持跨进程续传。
- 不承诺分段下载一定比单连接快；受服务器限速、线路、磁盘影响。
- 不承诺支持需要登录/Cookie/自定义 Header 的下载；工具首版只做公开 HTTP(S) 直链。
- 不承诺 Windows 以外的 GUI 验证；当前构建环境是 WSL2，无 Windows 桌面。
