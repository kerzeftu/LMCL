## 4. 性能与平台数据（决策留痕）

### 4.1 8 款 JDK 同环境实测（冷启动）

| 发行版 | 冷启动 | 常驻内存 |
|---|---|---|
| Temurin | 5.60 s | 230 MB |
| Corretto | 5.95 s | 220 MB |
| Liberica | 6.05 s | 219 MB |
| Oracle | 6.10 s | 211 MB |
| **Zulu** | 6.20 s | 215 MB |
| Dragonwell | 6.45 s | 216 MB |
| Microsoft | 6.90 s | 219 MB |

结论：**无显著差异**（在误差范围内）。Zulu 的选型理由是**架构覆盖最广**（x86/64、ARM32/64、MIPS、PPC、SPARC、嵌入式）+ LTS 长，**不是更快**。真正快 20–50% 的是商业版 Azul Zing（Falcon JIT + C4），与 Zulu Community 是两回事。

### 4.2 上游 JVM 默认参数（`DefaultLauncher`）

```
-XX:+UseG1GC -XX:MaxGCPauseMillis=50 -XX:G1NewSizePercent=20
-XX:G1ReservePercent=20 -XX:G1HeapRegionSize=32m -XX:G1MixedGCCountTarget=5
```

用户若自己在 JVM 参数框写了另一套 GC 参数 → 必须提示"二者会冲突，请打开「不添加默认的 JVM 优化参数」"。

### 4.3 JEP 346（L0+ 基座）

```
-XX:+UseG1GC
-XX:G1PeriodicGCInterval=30000
-XX:G1PeriodicGCInvokesConcurrent
-XX:G1PeriodicGCSystemLoadThreshold=30
-XX:MinHeapFreeRatio=5
-XX:MaxHeapFreeRatio=10
-XX:+ShrinkHeapInSteps
```

- 仅对 **G1** 生效；`G1PeriodicGCSystemLoadThreshold` **必须显式设置**（0 = 任何负载都触发，可能骚扰）。
- JDK 12+；`ShrinkHeapInSteps` 在 JDK 13+。
- ZGC/Shenandoah 自动归还，无需追加；Parallel/Serial/CMS 不支持。
