## 0. 摘要

这次调整把“账户/实例管理”从“其他”页里独立出来，变成侧栏的第四个一级入口：

```
64px 图标侧栏：
主页  →  下载  →  管理  →  设置  →  （弹性空白）  →  其他
```

- **管理页**：账户、实例两个 tab，复用现有 `AccountsPane` / `InstancesPane`。
- **其他页**：移除账户、实例、社区设置三个 tab；保留帮助、反馈、关于，并新增“内存优化”入口。
- **主页**：账户卡 → 管理页·账户；启动卡的“切换/更多”、最近存档的“全部实例” → 管理页·实例；不再打开独立的 `GameListPage`。
- **可配置动作**：有对应页面的，跳到页面；没有对应页面的（置顶管理、日历设置、崩溃历史、快照管理、Java 推荐/JVM 参数）保留弹窗，但统一成 HMCL 的 `DialogPane` 视觉。
- **内存优化**：版本设置与全局游戏设置各出现一个“启动游戏前执行内存优化”复选框（同一个可继承 `GameSettings` 属性），启动任务在游戏进程创建前调用 `MemoryReclaimer.optimizeForLaunch()`。
- **视觉收口**：清掉 `✕` 自绘标题栏、内联 `setStyle`、自绘按钮层级；统一 `DialogPane` / `ComponentList` / `LinePane` / `HintPane` / `AdvancedListBox` / `TabHeader`。

预计 **5.0–5.5 人日**（约 1–1.5 周），新增 2 处上游代码侵入（共 11 处）。

## 4. 实现设计

### 4.1 `ManagementPage`

新增 `lmcl/HMCL/src/main/java/org/jackhuang/hmcl/community/ui/ManagementPage.java`：

```java
@NotNullByDefault
public final class ManagementPage extends DecoratorAnimatedPage
        implements DecoratorPage, PageAware {

    private static @Nullable ManagementPage instance;

    private final ReadOnlyObjectWrapper<State> state =
            new ReadOnlyObjectWrapper<>(State.fromTitle(i18n("community.management.title")));

    private final TransitionPane transitionPane = new TransitionPane();
    private final TabHeader.Tab<AccountsPane> accountsTab =
            new TabHeader.Tab<>("communityManagementAccountsPage");
    private final TabHeader.Tab<InstancesPane> instancesTab =
            new TabHeader.Tab<>("communityManagementInstancesPage");
    private final TabHeader tab;

    private ManagementPage() {
        accountsTab.setNodeSupplier(AccountsPane::new);
        instancesTab.setNodeSupplier(InstancesPane::new);

        tab = new TabHeader(transitionPane, accountsTab, instancesTab);
        tab.select(accountsTab);

        AdvancedListBox sideBar = new AdvancedListBox()
                .startCategory(i18n("community.management.category").toUpperCase(Locale.ROOT))
                .addNavigationDrawerTab(tab, accountsTab,
                        i18n("community.management.tab.accounts"), SVG.PERSON, SVG.PERSON)
                .addNavigationDrawerTab(tab, instancesTab,
                        i18n("community.management.tab.instances"), SVG.GAMEPAD, SVG.GAMEPAD);

        FXUtils.setLimitWidth(sideBar, 200);
        setLeft(sideBar);
        setCenter(transitionPane);
    }

    @NotNull
    public static ManagementPage getInstance() {
        FXUtils.checkFxUserThread();
        if (instance == null) {
            instance = new ManagementPage();
        }
        return instance;
    }

    public void showAccounts() { tab.select(accountsTab, false); }
    public void showInstances() { tab.select(instancesTab, false); }

    @Override public void onPageShown() { tab.onPageShown(); }
    @Override public void onPageHidden() { tab.onPageHidden(); }
    @Override public ReadOnlyObjectProperty<State> stateProperty() {
        return state.getReadOnlyProperty();
    }
}
```

要点：

- 单例；重复 `navigate` 不重建列表。
- `AccountsPane` / `InstancesPane` 的构造已经绑定账户/认证服务器/游戏目录，无需改内部逻辑。
- 账户页的工具栏（Microsoft/离线/认证服务器）和实例页的工具栏（目录/新建/导入/全局设置）保持现有实现。
- 管理页左侧只放“账户/实例”两项，不再出现“社区设置”。

#### 4.7.3 `MemoryReclaimer.optimizeForLaunch()`

在 `MemoryReclaimer.java` 增加：

```java
/// 启动游戏前执行一次堆内存优化。
///
/// 与自动回收的 6 个条件无关：不要求游戏已运行、不受 60s 手动冷却限制；
/// 但受 `-XX:+DisableExplicitGC` 与 JVM 关闭状态约束。
///
/// @return 是否实际执行了回收
public synchronized boolean optimizeForLaunch() {
    if (shutdown.get() || explicitGcDisabled) {
        LOG.info(LOG_PREFIX + " trigger=launch skipped"
                + (explicitGcDisabled ? " reason=explicit_gc_disabled" : " reason=shutdown"));
        return false;
    }
    doReclaim("launch");
    return true;
}
```

同时把 `doReclaim` 改为 `private synchronized void doReclaim(String trigger)`，避免启动优化与周期回收/手动回收并发写同一份 settings。

语义：

- `System.gc()` 只是建议，JVM 可以不立即回收；UI 不承诺“一定释放多少”。
- 回收会更新 `lastReclaimAt` / `totalReclaimed`，因此“上次回收”可能显示为启动前；日志用 `trigger=launch` 区分。
- 不做 Windows 工作集裁剪；不引入 JNI/JNA。

#### 4.7.4 `MemoryLaunchOptimizationTask`

新增 `lmcl/HMCL/src/main/java/org/jackhuang/hmcl/community/memory/MemoryLaunchOptimizationTask.java`：

```java
@NotNullByDefault
public final class MemoryLaunchOptimizationTask implements LaunchStartupTask {

    public static final String ID = "memory-optimization";

    @Override
    public @NotNull String id() {
        return ID;
    }

    @Override
    public int order() {
        return 150; // 体检 100 之后，快照 200 之前
    }

    @Override
    public @NotNull Task<?> run(@NotNull LaunchContext context) {
        if (!context.interactive() || context.setting() == null) {
            return Task.completed(null);
        }
        if (!Boolean.TRUE.equals(context.setting().getInheritable(
                GameSettings::memoryOptimizationOnLaunchProperty))) {
            return Task.completed(null);
        }
        MemoryReclaimer.instance().optimizeForLaunch();
        return Task.completed(null);
    }
}
```

注册到：

`lmcl/HMCL/src/main/resources/META-INF/services/org.jackhuang.hmcl.community.launch.LaunchStartupTask`

```
org.jackhuang.hmcl.community.preflight.PreflightStartupTask
org.jackhuang.hmcl.community.memory.MemoryLaunchOptimizationTask
```

注意：

- 任务失败只会被 `CommunityLaunchHooks` 记录，不阻断启动。
- `interactive=false`（生成启动脚本）跳过，避免“只生成脚本也 GC”。
- 任务在非 FX 线程，`MemoryReclaimer` 的 `synchronized` 保证与周期任务互斥。
- 如果 `GameSettings.Effective` 为 null（离线/异常路径），跳过，不抛异常。

#### 4.7.5 边界与降级

| 场景 | 行为 |
|---|---|
| 全局关闭、实例未覆盖 | 不执行 |
| 全局开启、实例覆盖关闭 | 不执行 |
| 实例覆盖开启、全局关闭 | 执行 |
| 生成启动脚本 | 不执行 |
| JVM 带 `-XX:+DisableExplicitGC` | 跳过并 INFO 日志；设置 UI 仍可勾选，但不会生效 |
| 启动器正在关闭 | 跳过 |
| `System.gc()` 耗时很长 | 不自动停用启动优化；日志记录耗时；自动回收的自适应策略不受影响 |
| 多实例同时启动 | 每个启动任务串行 `synchronized`，不会并发 GC |
