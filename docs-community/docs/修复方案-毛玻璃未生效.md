# 毛玻璃未生效：诊断与修复方案

> 状态：**待批准（2026-10-27）**，只做诊断与设计，尚未改代码。
> 触发：用户 m26263：“毛玻璃效果没有生效，也要准备修复”。
> 关联：[M3 方案](修复方案-Material3Expressive视觉重构.md) §20（B1 侧栏玻璃）、[待办总览](待办总览.md) VIS-01、审查记录 §68.4（H6 对比度）。
> 当前基线：`lmcl` HEAD `fc384403d`；包 m3expressive17；M3 切片 A/B1 已实现，B2 未开始。

---

## 1. 结论速览

1. **当前只有左侧 64px 侧栏有玻璃**，主页头部、9 张卡片、标题栏都还没有接 `GlassSurface`。如果用户的预期是“整个界面毛玻璃”，看到侧栏只有窄窄一条、卡片仍是实色，就会认为“没有生效”。
2. **纯色/主题色背景下不存在可模糊的纹理**。`GlassBackdrop` 对壁纸图片做离屏模糊；如果 `Themes.background` 是 `BackgroundFill`（纯色/主题色），模糊结果仍是均匀色，视觉上不会出现毛玻璃纹理。这属于实现边界，不一定是代码错误。
3. **壁纸快照存在一次性的时序风险**：`GlassBackdrop.render` 在 `BackgroundImage` 尚未加载完成时返回 `null`，且没有监听图片加载完成；之后背景属性不再变化，快照可能永远不生成。这是最值得先修的代码问题。
4. **`GlassSurface` 初始不可见**，只有 `update()` 拿到非空图片且宽高 > 1 才显示；若布局/场景时序不满足，表面会一直隐藏，只剩侧栏的 CSS 半透明底色。
5. **42% tint + 仅 64px 宽度 + 18px 模糊**可能让效果偏弱；即使渲染成功，肉眼也可能觉得“没有玻璃”。

**建议顺序**：先做一次带日志的 Windows 诊断包，区分“产品预期/纯色背景”与“快照/可见性 bug”；再修时序和可见性；最后用 B2 把玻璃扩展到主页/标题栏。不要在未确认根因前盲目加大模糊或降低透明度。

## 2. 当前实现（B1）

### 2.1 渲染链

```text
Themes.backgroundProperty()
  └─ LauncherBackground(Background, opacity)
       └─ GlassBackdrop.attach(M3Host)
            ├─ 监听 host 宽高 + Themes.background
            ├─ schedule()：160ms PauseTransition 合并刷新
            └─ refresh()
                 ├─ 离屏 Canvas 重绘 LauncherBackground.background()
                 ├─ BoxBlur(max(6, min(18, pixelWidth / 18)))
                 ├─ snapshot(scale = min(1, 640/w, 400/h))
                 └─ 更新 image / originX / originY / scale
                      └─ GlassSurface（侧栏内）
                           ├─ 按 localToScene 计算 viewport
                           ├─ ImageView + 42% tint + Rectangle clip
                           └─ 无 image 时 setVisible(false)，退回 CSS
```

### 2.2 关键文件

| 文件 | 职责 |
|---|---|
| `HMCL/src/main/java/org/jackhuang/hmcl/community/ui/m3/GlassBackdrop.java` | 监听背景/宿主尺寸，离屏快照，发布 `image/scale/origin` |
| `HMCL/src/main/java/org/jackhuang/hmcl/community/ui/m3/GlassSurface.java` | 订阅快照，计算 viewport，显示模糊图 + tint |
| `HMCL/src/main/java/org/jackhuang/hmcl/community/ui/m3/M3Host.java` | M3 壳层宿主，构造时 `GlassBackdrop.attach(this)`，销毁时 detach |
| `HMCL/src/main/java/org/jackhuang/hmcl/community/ui/CommunitySideBar.java` | 侧栏 `StackPane`：`GlassSurface` 在下，`VBox content` 在上 |
| `HMCL/src/main/resources/assets/css/m3-community.css` | `.community-sidebar` 不透明底色、`.lmcl-m3-glass-surface`、42% tint |

### 2.3 已核实的行为

- `M3Settings.isGlassEnabled()`：系统属性 `lmcl.visual.glass` → `visual.glass` → `"auto"`；`auto`/`on` 都允许尝试，`off` 明确关闭。
- `M3Settings.isM3Enabled()`：系统属性 `lmcl.visual.m3` → `visual.enabled` → 旧 `m3` → **默认 true**。
- `VisualTheme.M3_EXPRESSIVE` 映射 `(m3=true, glass="on")`；`M3_GLASS_OFF` 映射 `(true, "off")`；`CLASSIC` 映射 `(false, "off")`。
- `Themes.background` 初始是白色 `BackgroundFill`；首次访问触发 `startBackgroundUpdates()`。
- `LauncherBackground` 是 record `(Background background, double opacity)`；壁纸图片路径得到 `BackgroundImage`，纯色/主题色路径得到 `BackgroundFill`。
- `GlassSurface` 构造时 `setVisible(false)`；`update()` 在 `width <= 1 || height <= 1`、`image == null` 或 `image.isError()`、viewport 为空时隐藏。
- `GlassBackdrop.render` 找不到可绘制的 image/fill 时返回 `null`，随后 `clear()`，没有重试。

## 3. 复现与判定树

> 目标：先确定“用户看到的是哪一种没有生效”，再改代码。每一步都记录截图/日志，不靠猜。

### 3.1 先排除开关

1. 打开 设置 → 外观 → 视觉主题，确认当前是 **M3 Expressive**，不是 “M3 关闭玻璃” 或 “Classic”。
2. 如果是旧配置，确认 `community-settings.json` 的 `visual.enabled`/`visual.glass`：
   - `visual.enabled=false`：M3 整个关闭，当然没有玻璃。
   - `visual.glass=off`：玻璃关闭，属于选择而非 bug。
3. 检查启动参数是否带 `-Dlmcl.visual.m3=off` 或 `-Dlmcl.visual.glass=off`（例如误用了 `run-classic.bat`）。系统属性优先级高于设置文件，且只在当前进程生效。

### 3.2 再排除背景类型

在 设置 → 外观 → 背景 中依次测试：

| 背景 | 预期 | 判定 |
|---|---|---|
| 内置壁纸（图片） | 侧栏出现壁纸纹理的模糊切片，和 `glass=off` 明显不同 | 如果无差异 → 快照/可见性 bug |
| 自定义图片壁纸 | 同上；切换后 1–2 秒内出现 | 如果切换瞬间无、稍后有 → 快照时序，可修 |
| 纯色/主题色 | 只有半透明色块，没有纹理 | 这是实现边界；需要产品决策或 B2 叠层方案 |

### 3.3 带日志复测（需新增，不在本方案直接改）

新增调试开关 `-Dlmcl.visual.debug=true`，在以下位置各打一条 `INFO`（不要每帧刷）：

- `GlassBackdrop.refresh`：host 尺寸、`Themes.background` 的类型（`BackgroundImage`/`BackgroundFill`）、图片数量/尺寸/是否加载完成、fill 数量、快照是否成功、`scale/origin`。
- `GlassSurface.update`：surface 的 `width/height`、`visible`、scene 原点、`image` 是否为空、计算出的 viewport。
- `M3Settings`：启动时打印最终 `m3/glass` 生效值及来源（property/设置/默认）。

复测步骤：三种背景各截一张图 + 附日志；如果图片背景仍无玻璃，日志应能区分“image 从未生成”和“image 生成但 surface 不可见”。

## 4. 根因候选（按可能性）

### C1. 用户当前是纯色/主题色背景（高）

**证据**：`Themes.createPaintBackground` 走 `BackgroundFill`；`GlassBackdrop.paintFill` 只画均匀色；BoxBlur 对均匀色没有可见变化。

**结论**：这不是快照 bug，是“壁纸快照磨砂”在纯色背景下的必然结果。需要：
- 在设置/关于里说明“纯色背景无纹理，毛玻璃仅在壁纸下可见”；
- 或给纯色背景叠加可辨识的玻璃层（边框/高光/更明显 tint）；
- 或未来用 Windows Acrylic（M3 方案 D2 的 C 方案，当前仅留实验位）。

### C2. 壁纸图片加载时序（高）

**证据**：`GlassBackdrop.render` 只读取当前 `BackgroundImage.getImage()`；未监听 `Image.progressProperty()`/`widthProperty()`；图片未加载时 `paintImages` 跳过，`paintFill` 对纯图片背景没有 fill，最终返回 null。之后 `Themes.background` 不再变化，不会重试。

**修复**：记录当前背景的 `Image`，监听其 `progress`/`width`/`error`；完成或失败时重新 `schedule()`；切换背景时移除旧监听。同时在 `scene`/`window` 显示、`layout` 完成后补一次刷新。

### C3. `GlassSurface` 不可见/零尺寸（中）

**证据**：初始 `visible=false`；`update()` 要求宽高 >1 且图片非空。若第一次布局发生在宿主尺寸为 0 时，之后没有尺寸/场景变化触发，表面可能一直隐藏。

**修复**：
- 构造后监听 `sceneProperty`、`layoutBoundsProperty`、`window.showingProperty`，显示后再刷新；
- 在 `M3Host`/侧栏完成布局后 `Platform.runLater` 补一次 `update()`；
- 调试日志确认 `width/height` 与 `visible`，不靠猜。

### C4. 效果太弱（中）

**证据**：侧栏仅 64px；tint 42%；模糊 18px（快照 640 宽时）；背景若偏暗/偏灰，纹理不明显。

**修复**：在 B2 视觉阶段统一调参（tint 0.32–0.36、blur 20–24、加 1px 高光边框/圆角），但必须在真实壁纸上对比，不可只调数字。

### C5. 用户仍处于 Classic / glass-off（中）

**证据**：v3.17.15–16 允许显式 Classic；`isM3Enabled` 读取持久化 false；`run-classic.bat` 的 `-Dlmcl.visual.m3=off` 会覆盖设置。

**修复**：诊断第一步就排除；若用户希望默认 M3，清除旧 `visual.enabled=false` 或重新选 M3 Expressive；文档说明旧配置不会强制迁移。

### C6. 玻璃范围只有侧栏（确定存在）

**证据**：M3 方案 §20.1 明确 B1 只做侧栏；B2 才做主页头部/9 卡/标题栏。

**结论**：如果用户期待全界面玻璃，这不是 bug，是 B2 未开始。应在 B2 里统一扩展，而不是在 B1 打补丁。

## 5. 修复设计

### 阶段 0：诊断包（0.5 人日）

- 增加 `lmcl.visual.debug` 日志（见 §3.3），默认关闭。
- 包内新增 `run-m3-debug.bat`：`-Dlmcl.visual.m3=on -Dlmcl.visual.glass=on -Dlmcl.visual.debug=true -Xmx1g`。
- 生成 `m3expressive18-debug` 测试包；只加日志，不改视觉行为。
- 请用户按 §3.2 三张背景截图并回传日志；若日志已明确，直接进入阶段 1。

**验收**：能从日志判断背景类型、快照是否生成、surface 是否可见；不改变正常用户路径。

### 阶段 1：快照时序与可见性加固（1 人日）

`GlassBackdrop`：

1. `refresh()` 拿到 `BackgroundImage` 后，保存当前 `Image` 引用；
2. 给该 image 加 `progressProperty`/`widthProperty`/`errorProperty` 监听：`progress >= 1` 或 `width > 0` 时 `schedule()`；`error` 时 `clear()` 并记录；
3. 背景切换/`detach()` 时移除旧 image 监听，避免泄漏；
4. `attach()` 时若 `host.scene == null` 或尺寸 0，监听 `sceneProperty`/`widthProperty`/`heightProperty`，就绪后补一次刷新；
5. 捕获 `Canvas.snapshot` 异常时记录一次，不要每帧重试。

`GlassSurface`：

1. `sceneProperty`/`layoutBoundsProperty` 变化时调用 `update()`；
2. 首次显示后 `Platform.runLater(this::update)`；
3. 仍无图时保持 `visible=false`，让 CSS 回退；不要用 0 尺寸的 ImageView 占位；
4. 调试日志只在 `debug` 开关下输出。

**验收**：壁纸图片加载完成后 1 秒内出现玻璃；切换壁纸/主题/缩放后自动更新；`glass=off` 时无快照开销。

### 阶段 2：视觉强度与纯色回退（0.5–1 人日）

- 在真实壁纸上对比 `tint 0.42 → 0.34`、`blur 18 → 22`、加 `-m3-color-outline-variant` 1px 边框；以“能看出模糊纹理且文字可读”为准，不追求越透越好。
- 纯色背景：不伪造纹理；增加 **玻璃表面边框/高光**，让侧栏与普通实色有层次；在设置或关于里说明“纯色背景无纹理”。
- `glass=off`/Classic 保持现有实色回退。

**验收**：壁纸下侧栏明显有玻璃质感；纯色下不误导为 bug；H6 对比度测量通过。

### 阶段 3：B2 扩展到主页/标题栏（2–3 人日，取决于范围）

- 主页头部、9 张卡、账户卡使用同一 `GlassBackdrop` 快照，不再各自截图（避免递归/性能问题）。
- 卡片圆角用 `Rectangle` clip；每张卡 `GlassSurface` 按 `localToScene` 取 viewport。
- 标题栏玻璃可先做“半透明 tint + 背景模糊”，若需要改 `DecoratorSkin`，先登记新的上游侵入号；预计复用 `DecoratorController`（第 7 处）与 `MainPage`（第 2 处）即可。
- 卡片玻璃与按钮/文字层级分开：玻璃层 `mouseTransparent`，不拦截点击。

**验收**：1920×1080 与 2560×1440 下，主页头部/卡片有统一玻璃；滚动、拖拽、展开账户卡不闪烁；CPU 无持续定时器。

### 阶段 4：B2 之后的对比度收口

- 按 H6 在浅/深壁纸、亮/暗主题、玻璃开/关下测文字对比度；不达 4.5:1 时提高 tint/scrim 或给文字局部底色。
- 结果写入 M3 方案 §G 与审查记录。

## 8. 风险与回退

| 风险 | 处理 |
|---|---|
| 监听 Image 加载导致泄漏 | 背景切换/detach 时移除监听；用弱监听或显式清理 |
| 快照频率过高导致卡顿 | 160ms 合并；只在尺寸/背景/主题变化刷新；不做每帧 |
| 纯色背景仍被用户认为“没修好” | 文档明确边界；提供边框/高光或 Acrylic 实验位 |
| B2 玻璃遮挡点击 | 玻璃层 `mouseTransparent`；事件仍由内容层处理 |
| 对比度不足 | H6 测量；提高 tint/scrim；保留 `glass=off` |
| 新上游侵入 | 先登记再改；优先只改 `community/**` 与 CSS |

回退：`visual.glass=off` 或外观页“M3 关闭玻璃”；代码回退到 B1 提交 `15686cba0` 之后的修复点；包回退 `m3expressive17`。
