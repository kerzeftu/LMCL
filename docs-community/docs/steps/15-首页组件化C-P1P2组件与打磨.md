## 2. 决策与依据

### 2.1 为什么把快照卡移到 16

15 在阶段四、16 在阶段五（[00 §6.2](../00-整体要求.md#6-优先级与里程碑)）。原稿让 15 前置 16，形成"阶段四依赖阶段五"的倒置；且快照数据源 `SnapshotService` 本身就是 16 的交付物。**处理**：15 只做不依赖 16 的 4 张卡，快照卡作为 16 的附加 UI（16 文档已注明须回填）。

### 2.2 游玩记录为什么由本步建数据层

- 上游不记录"哪天玩了多久"，日历没有数据就是空壳；
- 08 已给出**唯一的成功判据**（存活 ≥ 120s）与退出事件，本步只需持久化，不再造判定；
- 打点必须从上线第一天开始，否则日历要等一个月才有内容 → 数据层与 UI 同批交付，但数据层不依赖仪表盘是否可见。

### 2.3 跨步骤契约（已并入 08 §3.1/§3.3，实现以 08 为准）

| 契约 | 用途 | 08 状态 |
|---|---|---|
| `CommunityLaunchHooks` 类初始化时用 `ServiceLoader<LaunchEventListener>` 发现监听器（另加运行时 `addListener`/`removeListener`） | 游玩记录在**任何 UI 出现前**就能注册，不依赖仪表盘被挂载 | ✅ 已补（08 §3.1） |
| `PreflightService.collect(HMCLGameRepository, String versionId)` → `CompletableFuture<PreflightReport>` | 体检卡"复查"，只读、不弹窗 | ✅ 已补（08 §3.3；交互启动内部用 `collect(LaunchContext)` 同一核心） |
| `PreflightService.lastReport()` 读 `community/preflight/last.json`；体检任务结束时写该文件 | 体检卡展示"上次结论" | ✅ 已补（08 §3.3） |
| `PreflightDialog.showReportOnly(PreflightReport)` | 复查结果展示，复用 08 的文案 | 08 的对话框只有"是否继续"语义 → **需补** |

`PreflightReport`（08 定义，本步只读）：

```java
public record PreflightReport(
        int schema,                 // 1
        long at,                    // epoch millis
        String versionId,
        Severity worst,             // OK/WARN/ERROR/SKIPPED
        List<CheckResult> checks) { }

public record CheckResult(
        String id,                  // java.compat / memory.budget / disk.space / mods.duplicate / mods.missing_deps
        Severity severity,
        String code,                // i18n 片段键，如 "java_low"
        long elapsedMillis) { }
```

落盘文件 `<Metadata.HMCL_LOCAL_HOME>/community/preflight/last.json` **只存聚合结论**（严重度、检查 id、i18n code、时间），不存 mod 列表/路径/账号等明细，避免泄露；明细仍在 08 的弹窗与日志里。

## 3. 组件规格

通用约束沿用 13/14：`DashboardWidget` 基类、`loadAsync` 异步、`onDispose` 释放监听、禁止 FX 线程阻塞 IO、禁止 `new Thread`、颜色只用 CSS 变量。

### 3.1 `recent-worlds`（最近存档，2×1，2 人日）

```
┌──────────────────────────────────────────┐
│ 最近存档                          [全部] │
│ ▸ 生存世界       1.20.4 · 2 天前         │
│ ▸ 红石实验       1.20.1 · 上周           │
│ ▸ 空岛           1.19.2 · 3 周前         │
└──────────────────────────────────────────┘
```

**数据**（全部在 `Schedulers.io()`）：

1. 遍历 `repository.getVersions()`（缓存集合，不触发磁盘扫描）；
2. 对每个实例取 `repository.getSavesDirectory(id)`（`DefaultGameRepository.getRunDirectory(id).resolve("saves")`），目录不存在则跳过；
3. 用上游 `World.getWorlds(savesDir)` 解析（内部读 `level.dat`），**单实例上限 100 个世界、总上限 200 个**，超出截断并记日志；
4. 取 `getWorldName()` / `getLastPlayed()` / `getGameVersion()` / `isLocked()` / `getFileName()`，组成 `WorldEntry(instanceId, instanceName, fileName, worldName, lastPlayed, gameVersion, locked)`；
5. 按 `lastPlayed` 降序取前 3（2×1）/ 1（1×1），其余"全部"。

| 项 | 规格 |
|---|---|
| 点击 | `locked == false` → `repository.setSelectedInstance(instanceId)`，再 `Versions.launchAndEnterWorld(repository, instanceId, world.getFileName())`（上游 :314，内部 `QuickPlayOption.SinglePlayer`）；`locked == true` → 不启动，tooltip"该世界正在运行"，点击跳到实例存档列表 |
| 右键 | [打开存档列表]（`WorldListPage.loadInstance(repository, instanceId)` 后 `Controllers.navigate`）、[打开存档文件夹]（`FXUtils.openFolder(savesDir.resolve(fileName))`） |
| [全部] | 进入选中实例的存档列表页（无选中实例时进入实例管理页） |
| 时间 | 绝对时间 tooltip；相对时间（几分钟前/小时前/天前/上周/日期）用 `java.time` 自己格式化，**不引第三方库** |
| 空态 | "还没有存档" + [管理实例] |
| 错误态 | 某个实例读取失败 → 跳过并小字提示"部分实例读取失败"；全部失败 → "存档暂不可读"+[重试] |
| 刷新 | 挂载时、`EXITED_NORMAL/EXITED_ABNORMAL` 事件后 5 s、手动[刷新]；不做定时轮询 |
| 尺寸 | 1×1 显示 1 条；2×1 显示 3 条；2×2 显示 6 条 |
| 性能 | 解析在 io；200 个世界约 0.3–1 s；超过 2 s 未完成先展示已解析部分（流式） |
| i18n | `community.worlds.title / all / locked / empty / manage / open_list / open_folder / partial / error / just_now / minutes_ago / hours_ago / days_ago / last_week` |

**禁止**：读 `session.lock` 文件内容自己判断是否运行（用 `World.isLocked()`）；自己构造 `LauncherHelper` 或命令行。

└────────────────────────────────────────────┘

#### 3.3.1 数据层 `PlayRecordStore`

文件：`<Metadata.HMCL_LOCAL_HOME>/community/play-records.json`，schema v1：

```json
{
  "version": 1,
  "days": {
    "2026-10-21": { "playSeconds": 7320, "sessions": 2, "estimatedSeconds": 1800 },
    "2026-10-20": { "playSeconds": 1800, "sessions": 1 }
  }
}
```

- 只保留最近 **400 天**（写入时裁剪）；本地文件、不上传、不含世界名/服务器地址；
- 写入：临时文件 + `ATOMIC_MOVE`；损坏 → 重命名为 `.corrupt-<ts>` 后从空数据重建，记日志；
- 全部读写 `synchronized` 单写者 + `Schedulers.io()`，UI 只读快照；
- 关闭开关：`community-settings.json` 的 `playRecords.enabled`（默认 `true`）；关闭后**不再打点**，已有数据保留，重新开启后继续累加。

#### 3.3.2 打点状态机（`PlayRecordTracker implements LaunchEventListener`）

| 时刻 | 事件 | 动作 |
|---|---|---|
| 启动请求 | `REQUESTED` | 清理上次未闭合会话（见下行），记录 `requestedAt` |
| 进程创建 | `PROCESS_CREATED` | 内存记录 `sessionStart=now`；写 `play-session.json`（`{version:1, instanceId, startedAt}`）用于崩溃/强杀恢复 |
| 存活阈值 | `SURVIVED_THRESHOLD` | 标记本会话 `trusted=true`（唯一"有效游玩"依据） |
| 正常/异常退出 | `EXITED_NORMAL` / `EXITED_ABNORMAL` | `trusted` 且 `duration >= 阈值` → 累加 `playSeconds = min(duration, 12h)`、`sessions+1`；否则忽略；删 `play-session.json` |
| 用户停止 | `ABORTED_BY_USER` | 忽略（不计入，符合 08 语义） |
| 启动器启动时发现残留 `play-session.json` | 初始化 | `elapsed = now - startedAt`；`elapsed >= 阈值` → 记 `estimated`：`playSeconds += min(elapsed, 12h)`、`estimatedSeconds += ...`、`sessions+1`；否则忽略；然后删文件 |

- 日界按**本地时区** `LocalDate` 划分；跨日会话按退出时刻归一（v1 不做拆分，记在退出日，文档如实写明）；
- 12h 截断防挂机；`estimated` 单独累计，日历上用虚线/浅色区分，tooltip 标"估算"；
- 注册方式：`META-INF/services/org.jackhuang.hmcl.community.launch.LaunchEventListener` → `PlayRecordTracker`（依赖 §2.3 的 ServiceLoader 契约）；
- 单测：119/120/121 s 边界、崩溃会话恢复、12h 截断、跨月/跨年、损坏文件、开关关闭。

#### 3.3.3 UI

- 12 列（周）× 7 行（周一到周日），格子 10 px + 2 px 间隔；只渲染有数据的周，首尾各留 1 周内边距；
- 颜色 5 档（含空）：无记录 `-community-activity-level-0`；`<0.5h` → `-level-1`、`0.5–2h` → `-level-2`、`2–5h` → `-level-3`、`>=5h` → `-level-4`；类名与色值由[步骤 19](19-MD3主题完善.md) 的 `assets/css/community.css` 定义（见 19 §4.7），代码只加 class、不写死 hex；
- hover：tooltip `2026-10-21 · 2 小时 2 分 · 2 次`；估算会话追加"（估算）"；
- 汇总行：本月天数 + 总小时（四舍五入到 0.1h，不用"约"之外的修饰）；
- [清空]：二次确认（`Controllers.confirm`），删除文件内容且重置内存快照；[设置]：弹小面板（开关打点、打开数据目录、清空）——**不新增设置页**；

- 空态："还没有游玩记录，启动游戏后自动记录"；
- i18n | `community.calendar.title / summary / tooltip / estimated / empty / clear / clear_confirm / settings / enabled / disable_hint / open_dir` |

### 3.4 `health-check`（上次启动体检，2×1，1 人日）

```
┌──────────────────────────────────────────┐
│ 启动体检                        [复查]   │
│ ✅ 3 项通过   ⚠️ 1 项警告   ⏱ 10-21 12:04│
│ ⚠️ 内存：分配 12G / 物理 16G             │
└──────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 数据 | `PreflightService.lastReport()`（读 `community/preflight/last.json`）；文件不存在 → 空态"下次启动时会检查" |
| 渲染 | 聚合行（OK/WARN/ERROR/SKIPPED 计数 + 时间）+ 最多 2 条非 OK 检查（按 08 的 i18n code 落文案） |
| 刷新 | 挂载时读一次；收到 08 `TASKS_COMPLETED` 后 2 s 重读（启动刚跑过体检） |
| [复查] | `PreflightService.collect(repository, selectedId)`（io）→ `PreflightDialog.showReportOnly(report)`；运行中按钮禁用 + tooltip"检查中"；失败 → 卡片内错误提示 + 可重试 |
| 陈旧提示 | `now - at > 14 天` → 小字"上次体检较早" |
| 只读保证 | 卡片本身不做任何检查；复查是显式操作，且只读（不写实例目录，不改设置） |
| 尺寸 | 1×1 只显示聚合行；2×1 追加最多 2 条明细 |
| 空态/错误态 | 无记录 → 引导；JSON 损坏 → "体检记录不可读"+[复查]（复查会重建 last.json） |
| i18n | `community.health.title / summary / rerun / rerunning / stale / empty / error / ok / warn / error_count / skipped` |
