## 1. 目标

用户需求：m03806（默认不内置，主源 + ≤5 镜像）、m12016（把内置删干净，完全靠手动配置）、m12351（确保设置里的源真正生效，打包附样例 `.lmcl.json`）。

1. **零内置**：全新安装、未配置任何源时，版本列表与文件下载都**不能**访问 Mojang/BMCLAPI 或任何镜像；必须由用户在“设置 → 下载”填写至少一个源。
2. 用户可配 1 个主源 + 0–5 个镜像；候选顺序固定为 **主源 → 镜像 1..5**，**不追加官方源兜底**。
3. 未配置时，进入下载入口要**提前拦截**并给出“去设置”的按钮，而不是让后台任务弹异常堆栈。
4. 保存后**立即生效**：`CommunityDownloadSettingsPane.save()` 在写盘并重建 provider 后断言 `CommunityDownloadGuard.isConfigured() == !sources.isEmpty()`；不一致直接报保存失败，避免“界面显示已保存、下载仍走空 provider”。
5. 上游 `versionListSource` / `fileDownloadSource` 两个三档设置仍存在以兼容旧配置，但**不再影响实际 provider**；下载设置页不再暴露它们。
6. UI 复用 HMCL 控件（`ComponentList`/`LinePane`/`JFXTextField`/`MessageDialogPane`），不引入新框架。
7. 设置可经 `.lmcl.json` 导出/导入（入口“其他 → 工具”，见步骤 22）；包内提供一份 BMCLAPI 样例。

### 2.3 为什么需要 `MissingDownloadProvider`

`AutoDownloadProvider` 在构造时对空候选列表抛 `IllegalArgumentException`；而版本列表入口 `GameVersionList` 直接取 `downloadProvider.getVersionListURLs()`。所以“零内置”不能靠传空列表，必须有一个**明确失败**的 provider：

```java
DownloadProvider of(CommunityDownloadSources sources) {
    if (sources.isEmpty()) return new MissingDownloadProvider();
    List<DownloadProvider> providers = ...;   // 主源 → 镜像，无官方
    return new AutoDownloadProvider(providers, List.copyOf(providers));
}
```

`MissingDownloadProvider`：`getVersionListURLs()` 返回 `List.of()`，`getVersionListById(...)` 返回 `MissingVersionList`，`injectURL`/`injectURLWithCandidates` 抛 `CommunityDownloadSourceMissingException`，`getConcurrency()` 返回 1。

### 2.4 安装时机

| 时机 | 代码 | 说明 |
|---|---|---|
| 侧栏构造 | `CommunitySideBar` 构造 `try { CommunityDownloadInstaller.install(); }` | 早于用户点“下载/设置” |
| 首页挂载 | `CommunityDashboard.mount()` 最前 `install()` | 兜底；早于 `community.dashboard.enabled` 判断 |
| 下载入口 | `CommunityDownloadGuard.requireConfigured()` 在缓存 false 时再试 `install()` | 防止设置初始化顺序或异常导致未安装 |

`install()` 幂等：把上游两个 source 属性监听注册在自己身上，然后 `apply()`；`apply()` 读取 `CommunityDownloadSources.load()`、`wrapper.setProvider(...)`，随后 `CommunityDownloadGuard.refresh(!sources.isEmpty())`。

### 2.5 上游设置页的处置

## 3. 方案设计

### 3.1 需求 → 实现映射

| 需求 | 实现 |
|---|---|
| 零内置 | `DownloadProviders` 删除静态源，初始 `MissingDownloadProvider`；`CommunityDownloadProvider.of(empty)` 返回 Missing |
| 1 主源 + ≤5 镜像 | `CommunityDownloadSources(primary, mirrors)`；`MAX_MIRRORS=5`；解析与保存双重校验 |
| 顺序固定、无兜底 | `orderedSources()` = primary + mirrors；不构造 `MojangDownloadProvider` |
| 未配置提前拦截 | `CommunityDownloadGuard.requireConfigured(owner)`：三处入口 + “去设置” |
| 保存立即生效 | `save()` → IO 写盘 → `apply()` → 断言 → 回 FX 显示 |
| 持久化 | `community-settings.json` 的 `downloadSources` 段（`CommunitySettings.section/putSection`） |
| UI | `CommunityDownloadSettingsPane` 同时嵌入上游下载设置页与社区设置面板 `download` 分组 |

### 3.2 候选链构建

```java
public static DownloadProvider of(CommunityDownloadSources sources) {
    if (sources.isEmpty()) return new MissingDownloadProvider();
    List<DownloadProvider> providers = new ArrayList<>();
    for (CommunityDownloadSource source : sources.orderedSources()) {
        providers.add(new BMCLAPIDownloadProvider(source.url()));
    }
    return new AutoDownloadProvider(providers, List.copyOf(providers));
}
```

`AutoDownloadProvider` 的版本列表候选取并集（去重、保序），`injectURL` 取首个候选；因此首个可用源即主源，主源失败才轮到镜像。**没有任何官方源可回退**，所有候选失败时任务失败并显示缺源/下载错误。

### 3.3 拦截与生效校验

```java
// 入口
if (!CommunityDownloadGuard.requireConfigured(owner)) return;

// 保存（IO 线程）
sources.save();
CommunityDownloadInstaller.apply();
if (CommunityDownloadGuard.isConfigured() != !sources.isEmpty()) {
    throw new IllegalStateException("Configured download sources were not applied");
}
```

- `requireConfigured` 弹 `MessageDialogPane`：说明“LMCL 不内置任何下载源”，[去设置] 打开 `CommunitySettingsPanel.open(owner, "download")`，[取消] 关闭；
- 保存失败时 UI 显示 `save_failed`，不显示成功文案；日志带 `[CommunityDownload]` 上下文；
- 未配置时 `DownloadProviders.localizeErrorMessage` 把缺源异常转为可读文案，避免 `IllegalStateException` 堆栈。

### 3.4 存储 schema（`community-settings.json`）

```json
{
  "downloadSources": {
    "schema": 1,
    "primary": { "name": "示例主源", "url": "https://p.example" },
    "mirrors": [
      { "name": "镜像 1", "url": "https://m1.example" },
      { "name": "镜像 2", "url": "https://m2.example" }
    ]
  }
}
```

解析规则：

- `primary` 缺失/非法 → 视为未配置；
- `mirrors` 非数组 → 空；非法条目丢弃；重复地址保留第一次；超过 5 个丢弃并 WARNING；
- 未知字段忽略；`schema` 仅记录；
- `name` 可缺省（默认主机名）；UI 不单独提供名称输入，保存时按 URL 复用旧名称。

### 3.5 校验规则

| 规则 | 行为 |
|---|---|
| 空地址 | 该行视为未配置；主源与镜像全空 = 保存“0 个下载源”，下次下载被守卫拦截 |
| 无协议 | 自动补 `https://` |
| 非 `http(s)` / 无主机名 | 拒绝：`community.settings.download.error.invalid` |
| 超长 | 地址截断 2048、名称截断 64 |
| 重复 | 拒绝：`community.settings.download.error.duplicate` |
| 镜像 > 5 | 拒绝 + 按钮禁用：`error.too_many` |

### 3.9 失败降级

| 场景 | 行为 |
|---|---|
| `getDownloadProvider()` 不是 wrapper（上游改结构） | 记 WARNING，不安装；下载入口守卫仍会提示未配置 |
| 配置损坏/不可写 | `load()` 返回空 → Missing；保存失败只提示，不影响当前已生效 provider |
| 自定义源 5xx/超时 | `AutoDownloadProvider` 按候选顺序尝试镜像；全部失败则任务失败，**不回退官方** |
| 第三方源证书错误 | JVM 默认 TLS 拒绝；不绕过 |
| 安装异常 | 侧栏/首页/守卫都只 WARNING，不阻塞启动 |

4. 下载版本列表能加载、能下载一个版本；
5. 清空主源并保存 → 再点下载 → 再次拦截；
6. 设置页确认原三档下拉框不存在；插件源卡片仍可用；
7. 点“恢复默认” → 确认后为 0 个源（不是官方源）；
8. 拖入/导入 `LMCL-download-source-sample.lmcl.json` → 设置 → 下载 显示 BMCLAPI → 测试通过；
9. 断网/填不可达源 → 保存仍成功（配置合法），下载失败时显示缺源/下载错误而非堆栈。

### 5.3 回归关注点

- 版本列表、资源、模组、整合包下载均走同一 provider；
- `hmcl.bmclapi.override` 已不再参与（`DownloadProviders` 不再读取）；
- 下载线程数、代理等上游设置不受影响；
- 上游同步后重点回归 `DownloadProviders` 与 `DownloadSettingsPage` 两处侵入。

## 6. 风险

| 风险 | 影响 | 处置 |
|---|---|---|
| 自定义源不是 BMCLAPI 兼容 | 路径 404/下载失败 | UI 提示“必须是 BMCLAPI 兼容 API 根”；不会自动回退官方 |
| 零内置导致首次使用门槛 | 用户不知道去哪找源 | 守卫弹窗 + 设置页提示 + 包内样例；发布说明给出 BMCLAPI 示例 |
| 上游重构 `DownloadProviders` | 第 13 处侵入冲突 | 每次同步上游回归；`instanceof` 检查失败只 WARNING |
| 上游重构 `DownloadSettingsPage` | 第 4 处侵入冲突 | 保留社区 pane 为唯一内容，插件源卡片单独处理 |
| 保存成功但未生效 | 下载仍走 Missing | `save()` 断言 guard 状态；失败即报错 |
| 无头环境无法验证 UI | 交互缺陷后置 | §5.2 手工清单；CI 只做编译/单测/打包 |

## 7. 回退

1. 运行时：清空主源/镜像并保存 → 回到“未配置”状态（不会回到官方源）；
2. 代码：删除 `DownloadProviders.java` 的第 13 处改动并恢复上游静态源，即可回到上游行为；同时移除 `CommunityDownloadInstaller.install()` 调用（侧栏/首页/守卫）；
3. UI：恢复 `DownloadSettingsPage` 三档选择器并移除社区 pane；
4. 注意：仅删社区配置不会恢复官方源；零内置是产品决策，回退必须同时回退代码。
