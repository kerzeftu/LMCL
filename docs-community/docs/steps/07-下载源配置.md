## 1. 目标

用户需求（m03806）：**默认不内置下载源**；设置里可自行配置 **1 个主源 + 最多 5 个镜像源**；缺失的 UI 按 HMCL 风格补齐。

1. 全新安装、未做任何配置时，版本列表与文件下载**只走官方 Mojang 源**，不携带任何第三方镜像；
2. 用户可配置 1 个主源与 0–5 个镜像源，候选顺序固定为 **主源 → 镜像 1..5 → 官方源兜底**；
3. 每个源可单独测试连通性，地址非法/重复/超量在保存前拦截；
4. 保存后**立即生效**（无需重启），并持久化到 `<本地根>/config/community-settings.json`；
5. 上游“下载源”设置变化**不能**覆盖社区配置（监听器后注册、后执行）；
6. 补齐 UI 全部复用 HMCL 现有控件与样式（`ComponentList`/`LinePane`/`JFXTextField`/`MessageDialogPane`），不引入新框架；
7. 0 行上游代码修改；新增代码集中在 `org.jackhuang.hmcl.community.download`。

### 2.3 初始化时序

`HMCL/src/main/java/org/jackhuang/hmcl/Launcher.java`：

- `:103` `initializeSettingsRuntime()`；

- `:138` 之后才 `Platform.runLater` 构建 UI → `MainPage` 构造时 settings 与 provider 均已就绪。

### 2.4 上游设置页的处置

上游 `DownloadSettingsPage` 保留不动（避免侵入），但其三档枚举**不再决定实际下载**——本步安装后，每次两个 source 属性变化都会被我们的监听器重新覆盖为社区配置。为避免用户困惑，在“下载源”分组顶部提示“上游下载源设置不再生效，请在本页配置”。

## 3. 方案设计

### 3.1 需求 → 实现映射

| 需求 | 实现 |
|---|---|
| 默认无第三方源 | `CommunityDownloadSources.empty()` → 候选只有 `MojangDownloadProvider` |
| 1 主源 + ≤5 镜像 | `CommunityDownloadSources(primary, mirrors)`，`MAX_MIRRORS = 5`，解析与保存双重截断/校验 |
| 顺序固定 | `orderedSources()` = primary + mirrors；`build()` 追加官方源 |
| 立即生效 | 保存后调用 `CommunityDownloadInstaller.apply()`（`wrapper.setProvider(...)`） |
| 持久化 | `community-settings.json` 的 `downloadSources` 段（`CommunitySettings.section/putSection`） |
| 自定义地址语义 | 与 `BMCLAPIDownloadProvider` 相同：BMCLAPI 兼容 API 根 |
| UI | 设置面板扩展分组 `download`（`SettingsSectionProvider` + `META-INF/services`） |

### 3.2 接入机制（0 侵入）

```java
// 安装（幂等，只做一次）
DownloadProvider current = DownloadProviders.getDownloadProvider();
if (current instanceof DownloadProviderWrapper wrapper) {
    settings().versionListSourceProperty().addListener(ON_SETTINGS_CHANGED);
    settings().fileDownloadSourceProperty().addListener(ON_SETTINGS_CHANGED);
    apply(); // wrapper.setProvider(build(load()))
}
```

顺序保证：`DownloadProviders.init()` 在启动早期先注册它自己的监听器；我们的监听器在首页挂载时后注册。JavaFX `ObservableValue` 按注册顺序通知，因此上游先把自己的 provider 写回，我们随后覆盖，最终生效的一定是社区配置。

安装入口放在 `CommunityDashboard.mount(MainPage)` 的最前面（**早于** `community.dashboard.enabled` 判断），这样即使仪表盘被关闭，下载源配置仍然生效；安装失败只记 WARNING，不阻塞首页。

### 3.3 候选链构建

```java
static DownloadProvider build(CommunityDownloadSources sources) {
    List<DownloadProvider> providers = new ArrayList<>();
    for (CommunityDownloadSource source : sources.orderedSources())
        providers.add(new BMCLAPIDownloadProvider(source.url()));
    providers.add(new MojangDownloadProvider());   // 永远兜底
    return new AutoDownloadProvider(providers, providers);
}
```

`AutoDownloadProvider` 的版本列表候选取所有 provider 的并集（去重、保序），`injectURL` 取首个候选，因此“第一个可用源”即主源；失败时上游 task 会按候选列表逐个尝试，最后落到官方源。

### 3.4 存储 schema（`community-settings.json`）

```json
{
  "downloadSources": {
    "schema": 1,
    "primary": { "name": "示例主源", "url": "https://p.example" },
    "mirrors": [
      { "name": "镜像 1", "url": "https://m1.example" },
      { "name": "镜像 2", "url": "https://m2.example" }
    ]
  }
}
```

解析规则：

- `primary` 缺失/非法 → 视为未配置；
- `mirrors` 非数组 → 视为空；非法条目丢弃；重复地址只保留第一次出现；超过 5 个丢弃并记 WARNING；
- 未知字段忽略；`schema` 仅记录，当前不参与分支；
- `name` 可缺省（默认取主机名），UI 不单独提供名称输入，保存时按 URL 复用已有名称。

### 3.5 校验规则

| 规则 | 行为 |
|---|---|
| 空地址 | 该行视为未配置（主源留空 = 仅官方源） |
| 无协议 | 自动补 `https://` |
| 非 `http(s)` / 无主机名 | 保存被拒：`community.settings.download.error.invalid` |
| 超长 | 地址截断 2048、名称截断 64 |
| 重复 | 保存被拒：`community.settings.download.error.duplicate` |
| 镜像 > 5 | 保存被拒 + 按钮禁用：`community.settings.download.error.too_many` |

```
[提示条 .hint.info]  默认不内置第三方镜像……

主源
┌──────────────────────────────────────────────┐
│ 主源              [URL 输入框] [测试]          │
```

行为细节：

- 测试按钮：禁用自身 → 副标题“测试中…” → 结果写回该行副标题（连接正常/无法连接），不弹窗；
- 保存：先本地校验，全部通过后 `Schedulers.io()` 写盘 + `apply()`，回 `Schedulers.javafx()` 显示“已保存并应用”；写盘失败显示“保存失败，详见日志”；
- 恢复默认：`MessageDialogPane` QUESTION + `yesOrNo` 二次确认，清空后写空配置并重建 provider；
- 忙碌期间禁用输入框与全部按钮，避免并发保存；
- 无镜像时显示占位行“未配置镜像源”，不显示空卡片。

### 3.9 失败降级

| 场景 | 行为 |
|---|---|
| `getDownloadProvider()` 不是 wrapper（上游改结构） | 记 WARNING，放弃安装，启动器继续用上游默认源 |
| 配置文件损坏/不可写 | `load()` 返回空（仅官方源）；保存失败只提示，不影响当前下载 |
| 自定义源返回 5xx/超时 | 上游 `AutoDownloadProvider` 自动尝试下一个候选，最终官方兜底 |
| 第三方源证书错误 | 由 JVM 默认 TLS 行为拒绝；该源失败后回退，不做绕过 |
| 安装时异常 | `mount` 捕获后只记 WARNING，首页照常显示 |

## 5. 测试与验收

### 5.1 单元测试（已实现，`CommunityDownloadSourcesTest`）

1. `normalizesUrls`：补协议、去尾斜杠、空白；
2. `validatesUrls`：http/https 合法，无协议/ftp/空主机/空串非法；
3. `derivesNames`：默认主机名、超长名称截断；
4. `roundTripsJson`：`toJson`/`parse` 保留主源、镜像顺序与 `schema`；
5. `parseFiltersInvalidAndDuplicates`：非法地址丢弃、重复地址去重、镜像截断到 5；
6. `parsesEmptySection`：空段落 = 无自定义源；
7. `findsDuplicates`：跳过空槽位，返回首个重复地址；
8. `buildsProviderCandidatesInOrder`：空配置首 URL 为官方；配置后候选第 0/1 项为主源/镜像的 `/mc/game/version_manifest.json`。

### 5.2 手工验收（需真实桌面环境）

1. 全新数据目录启动 → 打开“设置 → 下载源”，主源/镜像均空；
2. 添加 6 个镜像 → 第 6 个按钮禁用；
3. 填两个相同地址 → 保存被拒并提示重复；
4. 填 `example.com`（无协议）→ 保存后显示 `https://example.com`；
5. 点“测试” → 副标题出现“测试中…”并最终变为连接正常/失败（可断网验证失败分支）；
6. 依次配置主源与 2 个镜像 → 保存 → 重启 → 配置仍在；
7. 打开上游“下载设置”页切换三档 → 重启后社区配置仍生效（候选仍以自定义源开头）；
8. 点“恢复默认” → 确认后仅剩官方源；删除 `community-settings.json` 后行为一致。

### 5.3 回归关注点

- 版本列表/资源/模组下载均经同一 provider，改源后上述四类都应变；
- `hmcl.bmclapi.override` 不再影响社区配置的源（自定义源优先）；
- 下载线程数、代理等上游设置不受影响（本步不触碰）。

## 6. 风险

| 风险 | 影响 | 处置 |
|---|---|---|
| 自定义源并非 BMCLAPI 兼容 | 替换表路径 404，下载失败 | UI 提示“必须是 BMCLAPI 兼容 API 根”；错误由上游按候选回退，最终官方兜底 |
| 用户误以为上游“下载源”三档仍有效 | 设置无效、困惑 | 分组提示条 + 文档；后续可考虑在步骤 19 主题层做禁用样式（不做代码侵入） |
| 第三方源可见用户下载内容 | 隐私/供应链风险 | 明示第三方源由用户自行选择；官方源兜底；不内置任何默认镜像 |
| 正在进行的下载不会切换 provider | 旧任务继续用旧源 | 已知限制；保存后仅新任务生效 |
| `DownloadProviderWrapper` 结构变化（上游重构） | 覆盖失效 | `instanceof` 检查 + WARNING；步骤 01 的上游同步周期内回归 |
| 无头环境无法验证 UI | 交互缺陷后置发现 | §5.2 手工清单；CI 只做编译/单测/打包 |
| 保存期间并发点击 | 配置覆盖 | `setBusy()` 禁用全部控件 |

---

## 7. 回退

1. 运行时：设置页“恢复默认”，或删除 `community-settings.json` 中的 `downloadSources` 段 → 下次启动仅官方源；
2. 代码：移除 `CommunityDashboard.mount` 中的 `CommunityDownloadInstaller.install()` 调用即可完全回到上游行为（其余类不被引用，无副作用）；
3. 紧急开关：如需在发行版中临时关闭，可在 `mount` 中加系统属性判断（当前未实现，避免增加未测试分支）。
