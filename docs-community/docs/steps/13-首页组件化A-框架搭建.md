## 1. 目标

在启动器首页加一块**可装配的仪表盘**：组件可注册、布局可编辑并持久化、组件异常隔离、全部 I/O 异步且可释放。框架本身不内置业务组件（由 14/15 通过 `ServiceLoader` 注册），因此在 14 落地前**首页视觉零变化**——刻意保持低风险。

完成标志（DoD）：

- [ ] `MainPage` 侵入 ≤ 15 行，`-Dcommunity.dashboard.enabled=false` 时与上游完全一致；
- [ ] 组件经 `ServiceLoader<WidgetProvider>` 注册，新增组件不改框架代码；
- [ ] 布局纯函数可单测：1–4 列自适应、1×1 / 2×1 / 2×2、越界与脏数据容错；
- [ ] 配置持久化 `<本地根>/config/dashboard.json`：schema v1、未知字段保留、原子写、编辑完成才落盘；
- [ ] 编辑模式：拖拽 + 右键菜单双通道（上移/下移、尺寸、本次隐藏、添加、恢复默认、取消）；
- [ ] 组件创建/刷新抛异常 → 单卡错误态 + "本次隐藏"，不影响首页其它部分与启动；
- [ ] `dispose()` 契约 + 监听器袋；泄漏开关 `-Dcommunity.dashboard.debugLeaks=true`；
- [ ] 组件数据刷新全部走后台线程，FX 线程零阻塞 I/O；
- [ ] 上游 `git diff --stat` 仅 `MainPage.java`（13 行）。

### 2.2 为什么放弃"侧栏新导航项"

旧稿曾设计"零侵入：在 `RootPage` 侧栏加一项进入仪表盘"。**否决**：

1. 侧栏项硬编码在 `RootPage.java:225-240`，加一项同样要改上游，且比 `MainPage` 挂载**行数更多**；
2. 在当时会新增第 5 处代码侵入点，违反 `00` §4.2 的固定预算（v3.1 已由产品决策改为 6 处，侧栏反而被移除，见[步骤 21](21-主页重构与侧边栏移除.md)）；
3. 产品上，社区版首页即工作台，仪表盘应嵌在首页而不是藏进二级导航。

因此本文档的"零侵入"仅指**除 `MainPage` 挂载块外**不修改上游其它文件；不再出现"零侵入"表述。

> **v3.1 变更（2026-10-22，步骤 21）**：用户（m07850）要求移除左侧文本侧栏。上文“加侧栏导航项”的否决被产品决策覆盖：`RootPage.Skin` 的侧栏已删除，账户/实例/下载/设置入口收进 `HomePane` 顶部导航与右栏；`MainPage` 挂载点不变，`DashboardPane` 保留但不再挂载。

### 3.3 组件契约

```java
/// 仪表盘组件元数据。
```

```java
/// 仪表盘组件基类。子类实现 createContent() 与（可选）refreshAsync()。
public abstract class DashboardWidget extends VBox {
    private final DashboardWidgetDescriptor descriptor;
    protected final DashboardContext context;
    private final List<Runnable> disposables = new ArrayList<>();
    /// 是否已释放；迟到回调据此丢弃。
    protected volatile boolean disposed;

    protected DashboardWidget(@NotNull DashboardWidgetDescriptor descriptor,
                              @NotNull DashboardContext context) { ... }

    /// 创建静态内容（FX 线程；禁止 I/O、禁止 sleep）。
    @NotNull protected abstract Node createContent();

    /// 异步刷新数据；默认空实现。
    protected void refreshAsync() { }

    /// 隐藏/删除/退出时调用；子类覆写必须调用 super.dispose()。
    public void dispose() { disposed = true; disposables.forEach(Runnable::run); disposables.clear(); }

    /// 登记随组件释放的 listener/handler。
    protected final void onDispose(@NotNull Runnable r) { disposables.add(r); }

    /// 后台执行 io，结果回到 FX 线程；异常统一转错误卡片。
    protected final <T> void loadAsync(@NotNull Supplier<T> io, @NotNull Consumer<T> ui) { ... }
}
```

`loadAsync` 的统一实现（组件内禁止自建线程）：

```java
protected final <T> void loadAsync(Supplier<T> io, Consumer<T> ui) {
    CompletableFuture.supplyAsync(io, Schedulers.io())
            .whenComplete((value, error) -> Schedulers.javafx().execute(() -> {
                if (disposed) return;
                if (error != null) DashboardErrors.show(this, error);
                else ui.accept(value);
            }));
}
```

- 调度器来自上游 `HMCLCore/src/main/java/org/jackhuang/hmcl/task/Schedulers.java:85`（`io()`）与 `:89`（`javafx()`）；
- 框架为每个组件加 `AtomicBoolean loading` 去重：同一时刻最多一个刷新在飞，防止 `Schedulers.io()` 被慢组件占满。

### 3.5 布局引擎（纯函数，可单测）

```java
/// 布局常量。
public final class DashboardLayout {
    public static final int GAP = 12;
    public static final int ROW_HEIGHT = 120;
    public static final int MIN_TILE_WIDTH = 180;
    public static final int MAX_ROWS = 64;

    /// auto 列数：<700→1；<1000→2；<1400→3；否则 4。
    public static int autoColumns(double width);

    /// 行优先放置；非法 span 收敛到 [1, columns]；重复/缺失 id 跳过。
    @NotNull public static List<PlacedItem> compute(@NotNull List<DashboardItem> items, int columns);
}
```

`compute` 算法（无回溯、结果可预测）：

1. `occupied[rows][columns]` 布尔矩阵，起始 `rows = 0`，按需增长；
2. 逐 item（已按 `order` 稳定排序）：从 `row=0` 起扫，找第一个 `col + colSpan ≤ columns` 且矩形全空闲的 `(row,col)`；
3. 放置后标记矩阵；`row` 超过 `MAX_ROWS` 的 item 进入"异常区"（不渲染，错误卡片提示 + 日志）；
4. 尺寸：卡片高 `rowSpan*ROW_HEIGHT + (rowSpan-1)*GAP`，宽 `colSpan*cellWidth + (colSpan-1)*GAP`，其中 `cellWidth = (width - (columns-1)*GAP)/columns`；
5. 返回顺序即渲染顺序（决定 tab 焦点顺序）。

单测（≥15 条）：空列表；单卡片；2×2 在 1 列窗口收敛为 1×1；跨列换行；重复 id；`order` 相同稳定性；`colSpan=3` 在 2 列容器收敛；`MAX_ROWS` 越界；列数断点 699/700/999/1000/1399/1400；宽度小于 `MIN_TILE_WIDTH` 时列数强制 1。

### 3.7 持久化 `dashboard.json`

路径：`<Metadata.HMCL_LOCAL_HOME>/config/dashboard.json`（步骤 06 的本地数据根；**不写** `~/.hmcl`、不写用户根）。

```json
{
  "schema": 1,
  "columns": "auto",
  "items": [
    {"id": "instances", "enabled": true, "order": 10, "colSpan": 2, "rowSpan": 1},
    {"id": "memory",    "enabled": true, "order": 20, "colSpan": 1, "rowSpan": 1}
  ],
  "pinnedInstanceIds": [],
  "widgetProps": {},
  "updatedAt": "2026-10-21T13:50:00+08:00"
}
```

| 项 | 规则 |
|---|---|
| `schema` | 当前 1；读到 `>1` → 只读模式（默认布局 + 顶部"配置由更高版本创建，暂不可编辑"），**绝不覆盖** |
| 未知字段 | 读入保留原始 `JsonObject`，写回合并；升级不丢字段 |
| 容错 | 损坏/类型错误 → 备份 `dashboard.json.corrupt-<timestamp>` + 默认布局 + WARNING，不阻塞启动 |
| 原子写 | 写 `dashboard.json.tmp` → `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)`；失败回退普通 move |
| 落盘时机 | 编辑"完成"、`pinnedInstanceIds` 变更后 1 s 防抖、组件 dispose 三处；拖拽过程中不写盘；禁止每次鼠标移动都写 |
| 规模 | `items` 上限 30，超出丢弃 `order` 最大者并日志说明 |
| 未知 id | 保留在文件中但不渲染（升级后不丢用户布局）；`pinnedInstanceIds` 原样透传（14 使用） |
| 默认布局 | 13：`items=[]`；14：首次加载且文件不存在时生成默认布局 |

### 3.8 生命周期、线程与泄漏

| 事件 | 行为 |
|---|---|
| `mount` | 同步读配置（<100 KB，避免首帧闪烁）→ 构建注册表 → 无可用组件或启用项为空 → 返回 `null` |
| 首次渲染 | 只为 `enabled=true` 且已注册的 item 创建组件；耗时组件可延后到首次可见 |
| 首页离开 | `MainPage` 被 `RootPage` 缓存，不销毁；组件**禁止定时轮询**，只在刷新事件拉数据 |
| 隐藏/删除 | `dispose()` + 从 Grid 移除 |
| 退出 | 在步骤 05 §4.1 的 `CommunityBootstrap`（06 已扩展路径注入）里追加 shutdown hook：`CommunityDashboard.disposeAll()`；13 不改该类的属性设置顺序 |
| 泄漏审计 | `-Dcommunity.dashboard.debugLeaks=true` 每 60s 打印组件实例数、监听器袋总数、存活卡片数（仅开发用） |

**禁止事项**（写入 14/15 实现检查清单）：

### 3.10 社区设置面板 `CommunitySettingsPanel`（13 交付，给 03/06/12/16/17 提供挂载点）

**为什么需要它**：13/14 不新增侧栏导航项、不碰上游 `SettingsPage`（`HMCL/src/main/java/org/jackhuang/hmcl/ui/main/SettingsPage.java`，内容硬编码、无扩展点），但步骤 03（关于社区版）、06（旧配置导入）、12/17（内存开关）、16（快照策略）都需要一个"我们自己"的设置入口。统一收敛到首页标题行右侧的 [设置] 按钮，避免各步各自往 `RootPage`/`SettingsPage` 塞入口（那会突破 §4.2 的侵入预算）。

```java
public record SettingsSection(@NotNull String id, @NotNull String i18nKey, int order,

/// 分组提供者；通过 META-INF/services 发现，单个抛异常只 WARN 跳过。
public interface SettingsSectionProvider {
    @NotNull List<SettingsSection> sections();
}

public final class CommunitySettingsPanel {
    /// 打开设置面板（模态）；重复调用只聚焦已打开的窗口。
```

- 分组内容首次选中才构造；读盘（路径、日志大小、计划任务状态）走 `Schedulers.io()`，回填走 `javafx()`；
