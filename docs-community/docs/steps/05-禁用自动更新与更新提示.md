# 步骤 05 · 禁用自动更新与更新提示

> **阶段**：阶段一 · 工程底座 ｜ **优先级**：P0（最不容出错的一步） ｜ **工期**：2–3 天
> **前置**：[步骤 03](03-产品身份与合规改造.md) ｜ **后续**：[步骤 06](06-数据目录与用户迁移.md)
> **侵入点**：0（新增 `community.CommunityBootstrap`、`community.update.CommunityUpdateNotifier` + `HMCL/build.gradle.kts` manifest 1 行，均属"新增/构建"登记）

---

## 1. 目标

产品决策（2026-10-21）：**LMCL 不做自动更新**。我们需要的是：

1. 上游 HMCL 的自更新链路（检查→下载→自替换）**结构上不可用**，且**不向官方更新源发任何请求**；
2. 提供自己的"发现新版本"提示：**只弹窗提示，不下载、不替换**；用户点按钮后**在浏览器打开 GitHub 或 Gitee 仓库**（仓库尚未创建，先留空 = 功能静默关闭）；
3. 不修改上游逻辑文件（`UpdateChecker`/`UpdateHandler`/`SettingsPage`/`MainPage` 均保持原样）。

完成标志（DoD）：

1. 发行产物不含 `META-INF/hmcl_signature`，`IntegrityChecker.isSelfVerified() == false`；
2. `UpdateChecker.checkUpdate()` 在**联网前**抛 `IOException("Self verification failed")`，只记 WARNING，不弹错误框、不阻断启动；
3. Bootstrap 在 `Metadata` 类初始化之前写入 `hmcl.update_source.override = <官网>/api/update_link`（域名 `https://www.kerzeftu.top/lmcl`），官方更新源不出现在任何代码路径；
4. 启动、切渠道、崩溃、退出全过程**无任何发往 `huangyuhui.net` / 官方 CI / 官方统计服务的请求**（mitmproxy 证据）；
5. 发行版 `hmcl.self_integrity_check.disable` 被强制为 `false`（外部 `-D` 覆盖无效）；
6. 自有更新服务 `CommunityUpdateNotifier`：仓库未配置时 `isConfigured() == false` 且 `checkAsync()` 立即返回空、**零网络请求**；配置后只返回 `UpdateInfo`（版本/发布页/说明），**没有任何下载或写盘 API**；
7. UI（步骤 13 交付）：发现新版本 → 弹窗 [前往下载]（打开 `repositoryUrl()`）/ [稍后]；同一版本选择"稍后"后写入 `updateSkippedVersion`，不再重复提示。

> 本步**不修改**任何上游逻辑文件。更新提示的 UI 壳在步骤 13 的 `CommunitySettingsPanel` 与首页挂载点，本步只交付可测试的服务与进程入口。

## 2. 依据：v3.16.4 源码实测

| # | 位置 | 事实 |
|---|---|---|
| 1 | `IntegrityChecker.java:48` | `DISABLE_SELF_INTEGRITY_CHECK = "true".equals(System.getProperty("hmcl.self_integrity_check.disable"))`，类加载时读一次 |
| 2 | `IntegrityChecker.java:114` | `isSelfVerified()`：用内置公钥 `assets/hmcl_signature_publickey.der` 验证 `META-INF/hmcl_signature`；未签名 → `false` |
| 3 | `UpdateChecker.java:87-88` | `checkUpdate()` 第一段就是 `if (!DISABLE && !isSelfVerified()) throw new IOException("Self verification failed")` —— 在构造 URL、发 HTTP 之前 |
| 4 | `UpdateHandler.java:177-178` | `applyUpdate(Path)`（`--apply-to` 自替换）同样先过校验 |
| 5 | `UpdateHandler.java:126` / `197-200` | `updateFrom()` 下载后再次校验；`requestUpdate()` 在 `DISABLE == false` 时 `verifyJar(updateTo)` |
| 6 | `Metadata.java`（`HMCL_UPDATE_URL`） | `System.getProperty("hmcl.update_source.override", PUBLISH_URL + "/api/update_link")`，**在 `Metadata` 类初始化时读取一次**；`Metadata` 由 `EntryPoint.main` 第 48 行 `http.agent` 赋值触发 |
| 7 | `UpdateChecker.java:73-109` | `init()` → `requestCheckUpdate(...)`：唯一自动触发点，位于 `Launcher.java:147`；失败仅 `LOG.warning("Failed to check for update")`，UI 侧把副标题设为 `update.latest`（"已是最新"） |
| 8 | `MainPage.java:390-393` | 更新气泡点击 → `UpdateHandler.updateFrom(target)`（下载并自替换）；`showUpdate` 绑定 `outdated`，本步后恒为 `false`，气泡永不出现 |

推论：

- **不设置** `hmcl.self_integrity_check.disable` 时，守卫拦截发生在网络之前，官方更新源根本不会被连接；
- 因此"禁用自更新"的正确姿势是**保持校验开启**（而不是 `-Ddisable=true`，那会把检查放行到网络层）；
- 官方更新 UI 全部依赖 `outdated` 属性 → 上游更新入口（气泡、设置页按钮、崩溃窗按钮）在本步后**自然全部消失**，无需改 UI；
- 需要的是**另建**一套提示：不依赖 `RemoteVersion` / `UpdateHandler`，只用 Releases API + 版本比较 + 浏览器跳转。

### 2.1 渠道值的副作用

```java
public static final String BUILD_CHANNEL = JarUtils.getAttribute("hmcl.version.type", "nightly");
public static boolean isStable()   { return "stable".equals(BUILD_CHANNEL); }
public static boolean isDev()      { return "dev".equals(BUILD_CHANNEL); }
public static boolean isNightly()  { return !isStable() && !isDev(); }
```

- `isNightly()` 为真 → `MainPage` 显示 nightly 公告卡（`MainPage.java:128-171`，本地 i18n，不联网但误导）；
- `IntegrityChecker.isOfficial()`（`IntegrityChecker.java:142-143`）在 `nightly && GITHUB_SHA != null` 时为 `true`；CI 一定有 `GITHUB_SHA` → **禁止 nightly**；
- 结论：发行构建 `VERSION_TYPE=stable`，开发包 `VERSION_TYPE=dev`（写入步骤 02/18 的构建约束）。

### 2.2 与步骤 04 的关系

步骤 04 默认 No-Go（不 relocate）。`CommunityBootstrap` 引用 `org.jackhuang.hmcl.Main` 的字面类名不受影响；若未来 Go，Bootstrap 的字节码引用会被 Shadow 改写，但 manifest `Main-Class` 必须人工同步（§4.2 验收覆盖）。

## 3. 方案选择

| 方案 | 做法 | 结论 |
|---|---|---|
| **A. 保持校验 + 钉属性 + 自有提示服务** | 不设 disable；Bootstrap 钉更新源与校验开关；新增 `CommunityUpdateNotifier` 只读 Releases API，跳浏览器 | ✅ 采用 |
| B. `-Dhmcl.self_integrity_check.disable=true` | 关闭校验 | ❌ 更新检查被放行到网络层，只剩更新源一道防线 |
| C. 删除 `upgrade/` 包 | 删 7 个类 | ❌ 与上游同步冲突大；`CrashWindow`/`Controllers`/`RootPage` 均引用 |
| D. 自建签名更新通道（自动下载） | 换公钥 + CI 私钥 + 自有 update JSON | ❌ 与"不做自动更新"的产品决策冲突，仅留作日后参考 |

**A 案的本质**：把"未签名"变成"拿到官方更新能力的开关被焊死"，同时用一条独立、只读的提示通道满足"告诉用户有新版本"。

## 4. 详细实施

### 4.1 `CommunityBootstrap`（已实现，提交 `a1925ded2`，含 manifest 改动）

位置：`HMCL/src/main/java/org/jackhuang/hmcl/community/CommunityBootstrap.java`（新增包，登记于 00 §4.2）。

启动链（v3.16.4）：

```
shadowJar manifest Main-Class
  └─ org.jackhuang.hmcl.community.CommunityBootstrap.main(args)   ← 本步新增
       ├─ System.setProperty("hmcl.update_source.override", <官网>/api/update_link)
       ├─ System.setProperty("hmcl.self_integrity_check.disable", "false")   ← 发行模式
       └─ org.jackhuang.hmcl.Main.main(args)                        ← HMCLBoot 的 Main
            └─ checkDirectoryPath() → Java 版本检查（≥17）
                 └─ EntryPoint.main(args) → Launcher.main(args)
```

代码（已落盘）：

```java
@NotNullByDefault
public final class CommunityBootstrap {
    private static final String PROP_UPDATE_SOURCE = "hmcl.update_source.override";
    private static final String PROP_DISABLE_INTEGRITY = "hmcl.self_integrity_check.disable";
    private static final String PROP_DEV = "hmcl.community.dev";
    private static final String UPDATE_SOURCE_PATH = "/api/update_link";

    public static void main(String[] args) throws Throwable {
        boolean dev = Boolean.getBoolean(PROP_DEV);
        if (dev) {
            if (System.getProperty(PROP_UPDATE_SOURCE) == null) {
                System.setProperty(PROP_UPDATE_SOURCE, CommunityMetadata.WEBSITE + UPDATE_SOURCE_PATH);
            }
        } else {
            System.setProperty(PROP_UPDATE_SOURCE, CommunityMetadata.WEBSITE + UPDATE_SOURCE_PATH);
            System.setProperty(PROP_DISABLE_INTEGRITY, "false");
        }
        Main.main(args);
    }
}
```

要点：

- 属性必须在 `Metadata` / `IntegrityChecker` 类初始化之前写入。`Metadata` 由 `EntryPoint.main:48` 的 `http.agent` 赋值触发，因此 Bootstrap 是最后的安全注入点；
- 为什么转交 `Main` 而不是直接调 `EntryPoint`：跳过 `Main` 会丢失 `checkDirectoryPath()`（路径含 `!` 等检查）与 Java 版本检查（`HMCLBoot/.../Main.java:144-152`）；
- `hmcl.community.dev` 只给开发用：允许外部 `-D` 覆盖以便抓包；CI 发行构建禁止设置（步骤 02/18 加扫描）；
- 异常处理：不做 try/catch；属性写入是纯内存操作，`Main.main` 的异常交由上游崩溃处理。

### 4.2 manifest `Main-Class`

`HMCL/build.gradle.kts` 的 `shadowJar.manifest.attributes` 把 `"Main-Class"` 从 `org.jackhuang.hmcl.Main` 改为 `org.jackhuang.hmcl.community.CommunityBootstrap`（只改一行）。

验证（本机已实测通过）：

```bash
python3 - <<'PY'
import zipfile
z = zipfile.ZipFile("HMCL/build/libs/HMCL-3.16.1000.jar")
print(z.read("META-INF/MANIFEST.MF").decode())
PY
# 期望：Main-Class: org.jackhuang.hmcl.community.CommunityBootstrap
#       Implementation-Version: 3.16.1000
```

exe 侧：`makeExecutables` 把 stub + jar 拼成 `HMCL-<version>.exe`（发行改名 `LMCL-<version>-win-x86.exe`），`Main-Class` 同样生效；裸机双击验证归步骤 20。

### 4.3 自有更新提示服务 `CommunityUpdateNotifier`

位置：`HMCL/src/main/java/org/jackhuang/hmcl/community/update/CommunityUpdateNotifier.java`（已实现，编译通过）。

数据源：GitHub Releases API 或 Gitee Releases API，**只读**。

```java
public record UpdateInfo(String version, String releaseUrl, String notes, String source) {}

public static boolean isConfigured()                                  // 两个仓库都为空 → false
public static String repositoryUrl()                                  // GitHub > Gitee > 官网下载页
public static CompletableFuture<Optional<UpdateInfo>> checkAsync()    // 未配置时立即返回 empty（零网络）
```

实现约束：

- 端点：`https://api.github.com/repos/<owner>/<repo>/releases/latest`、`https://gitee.com/api/v5/repos/<owner>/<repo>/releases/latest`；
- 超时 8s；`IOException` / 非 200 / JSON 异常一律 `LOG.warning` 后返回空（启动路径**静默失败**）；
- 版本比较用 `VersionNumber.compare(Metadata.VERSION, tag)`（`HMCLCore/src/main/java/org/jackhuang/hmcl/util/versioning/VersionNumber.java`），`tag` 去掉 `v` 前缀；只在新版本时返回；
- 发布说明截断到 800 字符；
- **类型层面禁止自动更新**：本类没有下载、写盘、启动 `UpdateHandler` 的方法；UI 只能打开 `releaseUrl`。

配置留空（当前状态）：

```java
public static final String GITHUB_REPO = "";   // "owner/repo"，仓库创建后填
public static final String GITEE_REPO = "";    // "owner/repo"，镜像仓库创建后填
```

### 4.4 UI 接线（步骤 13 交付，本步只定义契约）

- **启动提示**：`DashboardPane` 首次挂载后调 `checkAsync()`；`UpdateInfo` 存在且 `version != updateSkippedVersion` → `MessageDialogPane`：标题 `update.available.title`，正文含版本与 notes（最多 3 行），按钮 [前往下载]（`FXUtils.openLink(info.releaseUrl())`）/[稍后]（写 `updateSkippedVersion`）；
- **手动检查**：`CommunitySettingsPanel` 的"关于"组放 [检查更新] 按钮，结果用 toast/对话框反馈（未配置仓库时禁用按钮并提示"仓库尚未发布"）；
- 新增 i18n key：`community.update.title`、`community.update.body`、`community.update.download`、`community.update.later`、`community.update.check`、`community.update.not_configured`；
- 存储：`updateSkippedVersion` 落 `community-settings.json`（schema 由 06/08 定义，13 只加字段）。

## 6. 已知债务与风险

| 风险/债务 | 等级 | 应对 |
|---|---|---|
| 设置页更新按钮显示"已是最新"，语义误导 | 低 | 13 的"关于/更新"组明示"自动更新已关闭"；不为一句文案新增代码侵入 |
| 用户外部 `-D` 打开校验 | 中 | 发行模式强制覆盖；§5.3 测试 |
| 上游同步把守卫移到网络之后 | 中 | 列入 01 的同步后回归清单（本步 §5.2 重跑） |
| GitHub/Gitee API 限流 | 低 | 启动不阻塞、失败静默；UI 手动检查时提示"检查失败" |
| 仓库地址留空导致功能"消失" | 低 | 13 设置面板显式显示"仓库尚未发布"，避免用户以为坏了 |
| 更新提示被用户当成自动更新 | 低 | 弹窗文案明确"不会自动下载"；按钮只开浏览器 |
| 渠道值误设 nightly | 中 | 02/18 CI 断言 + §5.6 |

---

## 7. 回退方案

- 删除 Bootstrap 两行 `System.setProperty(...)`（或整个类）→ 恢复上游默认；
- `Main-Class` 改回 `org.jackhuang.hmcl.Main`；
- `CommunityUpdateNotifier` 无副作用，可直接不接线；
- **任何情况下不得把更新源改回 `https://hmcl.huangyuhui.net/api/update_link`**。
