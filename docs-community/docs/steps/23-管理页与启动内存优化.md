## 1. 目标

用户 m11000 要求把账户/实例管理从“其他”页提升为侧栏一级入口，并将主页里可配置的入口优先导到设置/管理页面；同时在“其他”页预留内存优化入口，在版本设置和全局设置中加入“启动游戏前执行内存优化”。

完成标志：

1. 左侧 64 px 侧栏顺序为：主页 → 下载 → **管理** → 设置 → 弹性空白 → 其他；
2. 管理页有账户、实例、Java 三个 tab，账户默认；账户/实例功能与步骤 22 的内嵌页一致，Java 直接复用上游 `JavaManagementPage`；
3. “其他”页只剩内存优化、帮助、反馈、关于 LMCL 四个 tab；
4. 主页账户卡 → 管理·账户；启动卡“切换/更多”、最近存档“全部实例” → 管理·实例；
5. 网络卡“配置下载源” → 设置·下载；
6. 版本设置与全局游戏设置都有“启动前优化启动器内存”，同一可继承属性，默认开启；
7. 启动时在游戏进程创建前执行一次内存回收，日志含 `trigger=launch`；脚本生成、`-XX:+DisableExplicitGC`、非交互式启动跳过；
8. 主页弹窗统一为上游 `DialogPane`，移除自绘 `✕` 标题栏和本轮涉及的内联文字颜色；
9. 编译、`checkTranslations`、community + 设置测试、`shadowJar`/`makeExecutables` 通过；
10. 不新增账户/实例业务逻辑，只换容器与入口；不改 `dashboard.json` 格式。

## 3. 启动内存优化

### 3.1 设置属性

`HMCL/src/main/java/org/jackhuang/hmcl/setting/GameSettings.java`：

```java
public static final String PROPERTY_MEMORY_OPTIMIZATION_ON_LAUNCH = "memoryOptimizationOnLaunch";

@SerializedName(PROPERTY_MEMORY_OPTIMIZATION_ON_LAUNCH)
private final InheritableProperty<Boolean> memoryOptimizationOnLaunch =
        newInheritableProperty(PROPERTY_MEMORY_OPTIMIZATION_ON_LAUNCH, true);

public InheritableProperty<Boolean> memoryOptimizationOnLaunchProperty() {
    return memoryOptimizationOnLaunch;
}
```

- 默认 `true`：符合“默认帮用户回收一次”的产品取向，可在全局或单实例关闭；
- `InheritableProperty<Boolean>` 自动支持全局预设与实例覆盖，无需新增配置迁移；
- 旧 `config.json` / `instance-game-settings.json` 没有该字段时回退默认值。

### 3.2 设置页复选框

`HMCL/src/main/java/org/jackhuang/hmcl/ui/game/GameSettingsPage.java`，在“启动器设置”组 `disableAutoGameOptions` 之后加：

```java
var memoryOptimizationPane = createInheritableBooleanButton(GameSettings::memoryOptimizationOnLaunchProperty);
launcherSettings.getContent().add(memoryOptimizationPane);
memoryOptimizationPane.setTitle(i18n("settings.launcher.memory_optimization_on_launch"));
memoryOptimizationPane.setSubtitle(i18n("settings.launcher.memory_optimization_on_launch.subtitle"));
```

- 全局设置与实例设置共用同一个 `GameSettingsPage`，因此两处自动都有；
- 实例页使用上游继承按钮，可“跟随全局/覆盖”；
- 文案说明“尽力回收、JVM 可忽略”，不承诺降低游戏内存占用。

### 3.3 回收器方法

`HMCL/src/main/java/org/jackhuang/hmcl/community/memory/MemoryReclaimer.java` 新增：

```java
public synchronized boolean optimizeForLaunch() {
    if (shutdown.get() || explicitGcDisabled) {
        return false;
    }
    try {
        doReclaim("launch");
        return true;
    } catch (Throwable e) {
        LOG.warning(LOG_PREFIX + " launch-time reclaim failed", e);
        return false;
    }
}
```

- 不受手动回收 60 秒冷却限制，也不要求“自动回收”已开启；
- 仍复用 `doReclaim`：记录 before/after、`lastReclaimAt`、`totalReclaimed` 与自适应策略；
- `-XX:+DisableExplicitGC` 时直接返回 false，由任务记录日志，不阻断启动。

### 3.4 启动任务

新增 `HMCL/src/main/java/org/jackhuang/hmcl/community/memory/MemoryLaunchOptimizationTask.java`：

- `implements LaunchStartupTask`，`ID = "memory-optimization"`，`ORDER = 150`（体检 100 之后、快照 200 之前）；
- `run(LaunchContext)`：
  - `!context.interactive()` 直接完成（生成启动脚本不执行）；
  - `context.setting() == null` 或 `!setting.getInheritable(GameSettings::memoryOptimizationOnLaunchProperty)` 直接完成；
  - 否则 `MemoryReclaimer.instance().optimizeForLaunch()`，日志记录 `trigger=launch versionId=... reclaimed=...`；
  - 捕获 `Throwable`，只 WARNING，不阻断启动。
- 注册：`HMCL/src/main/resources/META-INF/services/org.jackhuang.hmcl.community.launch.LaunchStartupTask` 追加一行；
- 现有 `LaunchContext` 的 `setting` 为 `GameSettings.@Nullable Effective`，实例/全局继承值已由启动链算好。
