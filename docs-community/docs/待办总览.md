## 0. 结论摘要

### 0.1 现在真正卡住发布的是什么

1. **没有任何 Windows 实机验收记录**。当前开发环境是 WSL2，无 X11/Windows GUI；从 v3.9 以后的大量 UI（M3 主题、玻璃、主页 9 卡、四页返回按钮、下载设置、管理器、对话框、DPI/缩放）只有编译、单测、静态检查，没有真实点击、截图、DPI 与文件占用验证。
2. **产品身份物料**：自有图标已于 v3.17.21 替换（JavaFX + HMCLauncher ICO）；Windows VERSIONINFO、MSVC 正式构建、10 项启动壳行为验收仍未完成。
3. **Microsoft OAuth 暂停**：没有自有 Entra client id / tenant，也没有 Minecraft 服务端 AppID allowlist；微软登录在无 id 时被禁用，第三方 authlib 仍会有“非官方”警告。
4. **官网/仓库/发布链未落地**：官网 `https://www.kerzeftu.top/lmcl`、更新源、反馈、条款、GitHub/Gitee 仓库（`origin` 未配置）、CI/签名/SBOM/灰度/回滚仍为空或未验证。
5. **M3 材质重做已完成，待实机验收**：v3.17.22 已把主页 9 卡 + 账户卡 + 侧栏统一为 `GlassSnapshot` far/near 双图材质，删除 sheen/白边/噪点，`Fallback` 统一半透明；无快照不再整块隐藏；仍缺 Windows 实机对模糊强度、对比度、GPU 性能的验收。B3–G 仍是大块工作。

### 0.2 当前最优先的三件事

1. **磨砂材质实机验收**：v3.17.22 已按[磨砂材质统一与多层模糊](修复方案-磨砂材质统一与多层模糊.md)完成 9 卡 + 账户卡 + 侧栏的双层模糊、去 sheen/白边/噪点；用带 `[glass-material]` 日志的 `m3expressive23` 在 Windows 验收，再按观感微调 tint/blur；随后主动提醒 JavaFX 21 标准化任务。
2. **Windows 验收批次**：用 m3expressive23 做首轮验收，至少覆盖默认 M3、Classic↔M3 切换、三视觉主题、顶栏随壁纸变色、主页亚克力/9 卡、账户卡、日历、每日一言、下载设置、设置导入/导出、四页返回。
3. **发布身份闭环**：OAuth + 官网/仓库 + 发布链三件事确定 owner 与时间点；在此之前不应宣称“可发布”。

### 0.3 已明确不做 / 不阻塞的事项

- 自动更新（已定案不做，只留只读提示）。

### REL-03 Microsoft OAuth 与第三方认证提示 ⛔

**来源**：[品牌方案](修复方案-HMCL品牌残留清理.md) §2.4、总纲 §12 #12。

**现状**：P0 暂停。`MICROSOFT_AUTH_ID` 为空时微软登录按钮被禁用；没有 Entra 应用、tenant、Minecraft AppID allowlist，不能完成 `login_with_xbox`。第三方 authlib 的“非官方 HMCL”警告来自 `IntegrityChecker.isOfficial()` 对社区构建恒 false，不能简单改全局 `isOfficial()`。

**需要用户提供/决定**：

- 自有 Microsoft Entra 应用 client id（public client，回调 `http://localhost/auth-response`）。
- Azure 租户（个人账户没有默认租户时，先创建 Azure 免费账户/默认租户）。
- Minecraft 服务 AppID allowlist 申请（`https://aka.ms/mce-reviewappid`），通过前登录会 403。
- 决定“只做离线/第三方认证”还是“必须支持微软登录”；若前者，需在 UI 明确说明并关闭微软入口。

**后续实现**：注入 id → 替换微软登录页 `.snapshot`/`unofficial.hint` → 去掉 authlib 的 `!isOfficial()` 警告（账户 UI 用社区判断，不改全局）→ OAuth 回调页品牌 → 协议链接改 LMCL。

### VIS-01 毛玻璃未生效与 M3 强调色 🟡（v3.17.22 已实现，待 Windows 验收）

**来源**：用户 m26263、m27893；B1/B2 玻璃实现；[旧诊断](修复方案-毛玻璃未生效.md)；[新方案](修复方案-磨砂材质统一与多层模糊.md)。

**现状**：B2 已实现侧栏/9 卡玻璃、动态顶栏与强调色四模式，但材质本身有缺陷：侧栏有 `GlassSurface.sheen` 的 `LinearGradient` 渐变；卡片叠加 wrapper 1 px 白色 20% 高光边框 + sheen + 内层 `.card` 实色底/描边，形成“双层不同圆角”观感；账户卡/页头在 v3.17.18 按“不要组件框”要求去掉了玻璃；Java 推荐/启动健康/下载源三卡表现为无半透明；模糊只有一张 640×400、单层 `BoxBlur`，强度不足且没有层次。新方案要求“低不透明度表面色 + 两层高斯模糊”，删除渐变/高光/噪点，统一 `materialCard`，账户卡恢复材质、页头保持无框。

**进展（v3.17.22）**：`GlassSnapshot` 双图（far 约 64 / near 约 24）、`GlassSurface` 删除 sheen/噪点/白边、9 卡 + 账户卡 `materialCard`、侧栏同材质、fallback 统一；新增 `[glass-material]` 日志与 `run-m3-debug.bat`。**下一步**：Windows 实机按 VIS-02 测对比度/性能并微调 tint/blur；随后主动提醒 JavaFX 21 标准化。

### VIS-02 玻璃对比度与可读性 ⬜

**来源**：M3 方案 H6；审查记录 §68.4。

**现状**：当前 tint 0.30 + 侧栏图标 `on-surface-variant` + 96×96 噪点/高光，没有在真实壁纸上测 4.5:1；半透明表面叠任意壁纸无法保证对比度。新方案的卡片 tint 约 0.28、侧栏约 0.40，仍需实测。

**下一步**：按新方案 P3 取浅/深壁纸 × 亮/暗主题 × 玻璃开/关四组测 4.5:1；不达标提高 tint 或加统一纯色 scrim（不用渐变），仍不达标就提供 `glass=off` 明确回退。

### PLAT-01 JavaFX 21 全量标准化 ⬜（低优先级，材质 P4 后启动）

**来源**：用户 m28123；[JavaFX 21 全量升级方案](修复方案-JavaFX21全量升级.md)。

**现状**：Windows x64 包已是 JavaFX **21.0.8**（JRE 17），但构建期在 JDK 23+ 会切到 JavaFX **25**；Windows x86/arm64、Linux arm32/LoongArch/RISC-V/FreeBSD 仍用 19/18/17 的 JavaFX。用户要求“完全升级到 JavaFX 21”，真正剩下的是：升到 21 LTS 最新补丁（核查为 21.0.13）、删除 modern 25/legacy 19 分支、明确官方支持平台、同步运行时清单与包。

**下一步**：**不早于磨砂材质 P4（`m3expressive23`）**。材质交付后主动提醒用户启动；届时确认 5 个官方平台（Windows x64、macOS x64/arm64、Linux x64/arm64）与遗留平台取舍，再按方案 J0–J4 执行。
