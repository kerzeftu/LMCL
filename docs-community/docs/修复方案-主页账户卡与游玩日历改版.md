## 1. 我的理解

### 1.1 账户卡

1. **不是新开一个账户页面**：账户卡继续固定在主页左栏第一张，不参与 `dashboard.json` 的左右栏拖拽，也不进入“主页组件”列表。
2. **当前账户那一行右侧加一个向下小三角**：三角是可点击按钮，不是装饰；点击后卡片向下展开账户列表，再点收起。
3. **展开列表里是“所有可选择的账户”**：每个条目显示头像、名称、账户类型/认证服务器（复用 `AccountAdvancedListItem` 的既有样式），点击某一条即切换当前账户并收起列表；列表要随 `Accounts.getAccounts()` 变化实时刷新。
4. **“卡片长度不够的时候就平滑过渡伸长”**：不是把卡片高度写死，也不是突然跳到最终高度；展开时让新增列表区域的高度从 0 平滑增长到内容需要的高度，父容器（左栏 `VBox` / `ScrollPane`）自然把后面的卡片往下推；收起时反向缩回。
5. **两个按钮**：
   - `[新建账户]`：直接打开账户创建入口，至少覆盖 Microsoft 登录、离线账户、认证服务器账户；不要求用户先跳“管理”页。
   - `[管理账户]`：跳转到现有 `ManagementPage` 的账户 tab。
6. **两个按钮的排布**沿用 v3.17.1 已定的卡片 footer 规则：恰好两个按钮时一左一右，中间留空；不新造第三种按钮排列。

### 1.2 游玩日历

1. **固定 5 行 × 7 列**：7 列对应周一至周日，5 行对应最近 5 个自然周；不再按卡片宽度显示 4/12/26 周。
2. **时间顺序从上到下**：最上面一行是最早的一周，最下面一行是当前周；同一行内从左到右是周一到周日。
3. **“最新的在最底下”**：采用“自然周”语义，底行是本周，今天位于底行对应的星期列；不是把今天强行放到右下角。
4. **没有记录的日期仍是格子**：老日期没有游玩记录时显示中性的无记录格，而不是消失、留白或跳过；未来日期也保留格子，但用更淡的“未来”样式，避免 5×7 出现缺口。
5. **不再按宽度重排周数**：删除 `weeks()` 和 `widthProperty` 监听；卡片高度由 5 行固定格子和 footer 内容决定，符合 v3.17.1 的“内容驱动高度”。
6. **统计摘要保留**：顶部仍显示本月游玩天数/小时数，数据源仍是 `PlayRecordStore`；日历只改变展示窗口，不改变统计口径。

### 1.3 需要确认的两个语义点

这两点不影响先写方案，但会影响最终观感，建议在实现前确认：

1. **底行是“本周”还是“最近 35 天”**：
   - 本文按“自然周日历”实现：底行是本周（周一至周日），今天在底行中间某个位置；例如今天是周三，底行第 3 格是今天，右侧 4 格是未来。
   - 如果你要的是“从今天往前数 35 天，今天永远在右下角”，那么列不再是星期一至星期日，日历语义会变；本文不采用这个方案。
2. **是否加星期一至星期日的表头**：
   - 本文建议在 5 行方格上方加一行很小的“一 二 三 四 五 六 日”表头；它不属于 5 行数据格，只是帮助识别列。
   - 如果你希望完全只有 5×7 方格，也可以去掉表头。

## 2. 现状取证

### 2.1 账户卡现状

`HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/builtin/HomePane.java:464-484`：

```java
private VBox buildAccountCard() {
    Label title = new Label(i18n("community.home.account.title"));
    title.getStyleClass().addAll("title-label", "community-title");

    AccountAdvancedListItem item = new AccountAdvancedListItem();
    item.accountProperty().bind(Accounts.selectedAccountProperty());
    item.setOnAction(event -> {

    item.setPrefHeight(48);

    VBox card = new VBox(6, title, item);
    card.getStyleClass().add("card");
    card.setMaxWidth(Double.MAX_VALUE);
    card.setMinHeight(Region.USE_PREF_SIZE);

```

现状问题：

- 整行账户条目只有一个点击动作：跳“管理 → 账户”；没有展开列表、没有新建/管理按钮。
- 账户卡没有自己的 `dispose`；如果新增 `Accounts.getAccounts()` 监听、动画 `Timeline`，必须挂到 `HomePane.dispose()`，否则主页重建后监听泄漏。
- `HomePane.dispose()` 在 `HomePane.java:229-255`，目前只移除 `Accounts.selectedAccountProperty()` 监听和启动事件监听；需要增加账户卡释放。

可复用 API：

- `HMCL/src/main/java/org/jackhuang/hmcl/setting/Accounts.java:441` `getAccounts()` 返回 `ObservableList<Account>`；
- `Accounts.java:449` `setSelectedAccount(Account)`；
- `Accounts.java:453` `selectedAccountProperty()`；
- `HMCL/src/main/java/org/jackhuang/hmcl/ui/account/AccountAdvancedListItem.java:78-93`：`new AccountAdvancedListItem(account)` 会设置头像、名称、副标题；无参构造还会额外注册滚轮切换账户，因此展开列表必须使用**带 account 的构造**，避免每个条目都响应滚轮。
- `HMCL/src/main/java/org/jackhuang/hmcl/ui/SVG.java:38-39`：`ARROW_DROP_DOWN` / `ARROW_DROP_UP` 可直接做倒三角。

### 2.2 新建账户入口现状

`HMCL/src/main/java/org/jackhuang/hmcl/community/ui/AccountsPane.java` 已经有完整的账户创建工具栏：

- `AccountsPane.java:72-75`：Microsoft / 离线 / 认证服务器菜单；

- 认证服务器的“新增服务器”仍要处理 `SettingsManager.isAuthlibInjectorServersReadOnly()`，保持现有确认逻辑。

### 2.3 游玩日历现状

`HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/builtin/ActivityCalendarWidget.java:145-187`：

- `weeks()` 返回 4 / 12 / 26，`rebuild()` 用 `week × day` 双重循环；
- `grid.add(cell, week, day)`：列是周，行是星期；
- 未来日期直接 `cell.setVisible(false)`，所以当前不是固定 5 行，也不是 7 列；
- 无记录日期仍会画 `community-activity-level-0`，这一点与新需求一致，可以保留；
- `widthProperty().addListener(... rebuild())` 在 `createContent()` 中注册，改动后要删除。

现状数据模型不需要改：

- `PlayRecordStore.DayRecord` 已有 `playSeconds`、`sessions`、`estimatedSeconds`；
- `levelOf()` 五档逻辑可原样保留；
- `tooltip()`、`updateSummary()` 可原样保留。

## 3. 账户卡设计

### 3.1 结构

建议把账户卡拆成独立类，避免 `HomePane` 继续膨胀：

```text
VBox community-account-card
├── Label 标题（community.home.account.title）
├── HBox 当前账户行
│   ├── AccountAdvancedListItem（绑定 Accounts.selectedAccountProperty，占满剩余宽度）
│   └── Button 倒三角（36×36，SVG.ARROW_DROP_DOWN / ARROW_DROP_UP）
├── ScrollPane 账户列表（默认收起）
│   └── VBox 账户条目（每个 new AccountAdvancedListItem(account)）
└── HBox 操作行
    ├── Button [新建账户]
    └── Button [管理账户]
```

新增类建议路径：

`HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/builtin/HomeAccountCard.java`

职责：

- 构建上述节点；
- 监听 `Accounts.getAccounts()` 与 `Accounts.selectedAccountProperty()`；
- 管理展开/收起动画；
- 提供 `dispose()`；
- 不直接读磁盘、不发起网络请求。

`HomePane` 只保留：

```java
private @Nullable HomeAccountCard accountCard;
...
accountCard = new HomeAccountCard();
...
if (accountCard != null) accountCard.dispose();
```

### 3.2 当前账户行

- 账户条目仍绑定 `Accounts.selectedAccountProperty()`，切换后头像/名称自动更新。
- 点击条目主体：保持现状，跳 `ManagementPage.showAccounts()`；这样不会和右侧三角的“展开”语义冲突。
- 点击右侧三角：只切换展开/收起，不跳页。
- 三角按钮要求：
  - `setFocusTraversable(true)`，可用空格/回车触发；
  - `setAccessibleText(i18n("community.home.account.expand"))` / 收起时切换文案；
  - 图标使用 `SVG.ARROW_DROP_DOWN`，展开时旋转 180° 或换 `ARROW_DROP_UP`；二选一，本文推荐换图标，避免旋转过程中出现半像素模糊；
  - 触控目标至少 36×36，视觉图标 20×20。

### 3.3 展开/收起动画

目标：卡片不是“啪”一下变高，而是列表区域平滑长出来。

实现要点：

1. 账户列表放在 `ScrollPane` 里：
   - `setFitToWidth(true)`；
   - `setHbarPolicy(NEVER)`；
   - `setVbarPolicy(AS_NEEDED)`；
   - 背景透明、无边框，由 CSS `community-account-list` 控制；
   - `ScrollPane` 自身会裁剪 viewport，避免动画过程中条目画到卡片外。
2. 收起状态：
   - `list.setVisible(false)`；
   - `list.setManaged(false)`；
   - `list.setMaxHeight(0)`；
   - `list.setMinHeight(0)`。
3. 展开：
   - `list.setVisible(true)`、`setManaged(true)`；
   - `list.setMaxHeight(0)`；
   - `applyCss()` / `layout()` 后取 `list.prefHeight(width)`，目标高度取 `min(pref, MAX_LIST_HEIGHT)`；
   - 用 `Timeline` 在 180–220 ms 内把 `maxHeightProperty()` 从 0 动画到目标值，`Interpolator.EASE_BOTH`；
   - 动画结束后保持目标 `maxHeight`，不改成 `USE_COMPUTED_SIZE`，避免下一帧再次改变高度。
4. 收起：从当前 `maxHeight` 动画到 0，结束后再 `setVisible(false)` / `setManaged(false)`。
5. 动画途中再次点击：
   - 先 `stop()` 当前 `Timeline`；
   - 从当前 `maxHeight` 继续向新目标动画，不回到 0 重来。
6. `SettingsManager.settings().animationDisabledProperty().get()` 为 true 时：
   - 不做动画，直接设置最终 `maxHeight` / 可见性；
   - 与 `M3MotionSupport` 的 reduced motion 保持一致。
7. `MAX_LIST_HEIGHT` 建议 `5 * 48 + 8 = 248`；账户超过 5 个时列表内部滚动，保证“所有可选择的账户”都能到达，同时卡片不会无限高。
8. 动画只改 `maxHeight`，不改 `prefHeight`/`minHeight`；父 `VBox` 会自然重排，后面的卡片平滑下移。

### 3.4 账户列表

- 数据源：`Accounts.getAccounts()`。
- 每个条目：`new AccountAdvancedListItem(account)`，不要用无参构造。
- 点击条目：
  ```java
  Accounts.setSelectedAccount(account);
  collapse();
  ```
- 选中态：
  - 给条目加 `community-account-option`；
  - 用 `PseudoClass.getPseudoClass("selected")` 标记当前账户；
  - CSS 只画 1 px 边框/浅色背景，不使用硬编码颜色。
- 列表变化：
  - 给 `Accounts.getAccounts()` 加 `ListChangeListener`；
  - 账户增删、重命名、登录状态变化后重建条目；
  - `dispose()` 时移除监听。
- 空态：
  - `Accounts.getAccounts().isEmpty()` 时显示 `community.home.account.empty`；
  - 三角仍可点，但展开后只显示空态 + 新建按钮，不显示空白 ScrollPane。
- 加载/失败：
  - 账户列表是内存数据，不需要 loading；
  - 头像加载失败由 `AccountAdvancedListItem` 自己回退默认皮肤，不额外处理。

### 3.5 “新建账户”按钮

推荐使用一个普通按钮 + `ContextMenu`，不放第二个 `MenuButton`，避免一行出现两个下拉箭头：

```text
[新建账户]
  ├── Microsoft 登录
  ├── 离线账户
  ├── ─────────
  ├── <认证服务器 A>
  ├── <认证服务器 B>
  └── 添加认证服务器…
```

行为：

- Microsoft：`Controllers.dialog(new MicrosoftAccountLoginPane())`；
- 离线：`Controllers.dialog(new CreateAccountPane(Accounts.FACTORY_OFFLINE))`；
- 认证服务器：`Controllers.dialog(new CreateAccountPane(server))`；
- 添加认证服务器：`Controllers.dialog(new AddAuthlibInjectorServerPane())`；
- 账户文件只读：调用 `SettingsManager.isUserGameAccountsReadOnly()` 时先走 `Controllers.confirmBackupAndOverwrite(...)`，与 `AccountsPane` 完全一致；
- 认证服务器列表只读：新增服务器时走 `isAuthlibInjectorServersReadOnly()` 的确认分支；
- 菜单每次显示前重建，保证新增的认证服务器立即可见。

### 3.6 “管理账户”按钮

```java
ManagementPage page = ManagementPage.getInstance();
page.showAccounts();
Controllers.navigate(page);
```

与现有账户卡主体点击行为一致。

### 3.7 视觉与布局

- 账户卡根节点：`card` + `community-account-card`；
- 标题：`title-label` + `community-title`；
- 操作行：复用 v3.17.1 的 `BuiltinWidgets.cardFooter(createButton, manageButton)`，两个按钮一左一右；
- 按钮用 `FXUtils.newBorderButton` 或 `BuiltinWidgets.borderButton`，不新造按钮样式；
- 不使用内联 `setStyle`；颜色/圆角/间距全部进 `community.css` 的 `.community-account-*`；
- M3 开启时只由 `.lmcl-m3 .community-account-card` 补 token，不改变结构。

## 4. 游玩日历设计

### 4.1 固定 7 列 × 5 行

常量建议：

```java
private static final int CALENDAR_COLUMNS = 7;
private static final int CALENDAR_ROWS = 5;
private static final double CELL_SIZE = 22;
private static final double CELL_GAP = 4;
```

`CELL_SIZE` 可在实现时微调到 20–24，但不再依赖卡片宽度切换周数。

### 4.2 日期映射

```text
row 0（最上面）：4 周前的周一 … 4 周前的周日
row 1：3 周前
row 2：2 周前
row 3：上周
row 4（最下面）：本周
```

计算：

```java
LocalDate today = LocalDate.now();
LocalDate thisMonday = today.with(TemporalAdjusters.previousOrSame(DayOfWeek.MONDAY));
LocalDate start = thisMonday.minusWeeks(CALENDAR_ROWS - 1L);

for (int row = 0; row < CALENDAR_ROWS; row++) {
    for (int column = 0; column < CALENDAR_COLUMNS; column++) {
        LocalDate date = start.plusDays((long) row * CALENDAR_COLUMNS + column);
        grid.add(createCell(date, today), column, row);
    }
}
```

关键点：

- `grid.add(cell, column, row)`：列在前、行在后；这与旧实现的 `grid.add(cell, week, day)` 相反。
- 最下面一行固定是本周；今天在底行对应的星期列。
- 未来日期仍生成格子，但只加 `community-calendar-cell-future`，不显示游玩等级。
- 没有记录的过去日期加 `community-activity-level-0`，tooltip 显示“无记录”。
- 今天额外加 `community-calendar-cell-today`，用描边/圆点标识；这不是新数据，只是视觉辅助。
- 不再调用 `weeks()`，不再注册 `widthProperty` 监听，不再维护 `renderedWeeks`。

### 4.3 格子内容

每个格子：

- 尺寸固定 `CELL_SIZE × CELL_SIZE`；
- 基础类 `community-calendar-cell`；
- 等级类 `community-activity-level-0..4`；
- 估算类 `community-activity-estimated`（保持现有）；
- 今天类 `community-calendar-cell-today`；
- 未来类 `community-calendar-cell-future`；
- Tooltip 保留现有 `tooltip(date, record)`；
- 可访问性：给格子 `setAccessibleText(date + " " + levelLabel)`，避免只能靠 tooltip。

### 4.4 表头与摘要

- 建议在 `grid` 上方加一个 7 列的星期表头（`一 二 三 四 五 六 日`），使用 `community-calendar-weekday` 小字；如果用户不需要，可删除，不影响 5×7 数据格。
- 摘要仍用 `community.calendar.summary`，显示本月天数/小时数；本次不改统计口径。
- footer 仍保留提示文案和 [设置] 按钮；日历变高后 footer 继续贴底。

### 4.5 CSS

新增/调整：

```css
.community-calendar-cell-future { -fx-opacity: 0.35; }
.community-calendar-cell-today { -fx-border-color: -monet-primary; -fx-border-width: 1.5; }
.community-calendar-weekday { -fx-font-size: 10px; -fx-opacity: 0.7; }
```

实际颜色用现有 `-monet-*` 变量或主题色，不写 hex；M3 模式下由 `.lmcl-m3` 作用域覆盖。

## 5. 与 M3 重构方案的关系

本次账户卡/日历改版是**结构/交互改动**，不是 M3 切片 B–G 的一部分：

- 不新增 m3fx 控件依赖；
- 不改变 `HomePane` 的左右栏、卡片显隐、拖拽排序；
- 不改变 `dashboard.json` 的 schema；
- 账户卡继续固定左栏，不进入可拖拽组件列表。

但它必须遵守 M3 方案的视觉约束：

- 只用语义 CSS 类，不写内联颜色/圆角；
- 按钮使用 HMCL 现有 `FXUtils.newBorderButton` / `community.css`；
- 动画遵守 `animationDisabled` 与 reduced motion；
- 不改变 i18n 既有 key 的显示含义，只新增社区 key。

- 卡片按钮：`BuiltinWidgets.borderButton(i18n("community.calendar.settings"), this::openCalendarSettings)`；`openCalendarSettings()` 先 `Controllers.getSettingsPage()`，再 `showStatisticsCalendar()`，最后 `Controllers.navigate(page)`；异常只记 WARNING，不阻断主页。
- 设置页：`StatisticsPage` 是普通 `StackPane`，由 `TabHeader` 承载；记录开关使用 `LineToggleButton`，读 `PlayRecordStore.enabled()`，写操作在 `Schedulers.io()` 执行，完成后回 FX 刷新概览；打开目录用 `FXUtils.openFolder(store.dataFile().getParent())`；清空用 4 参 `Controllers.confirm`，完成后 `reloadStats()`。统计读取失败时值显示 `—` 并显示 `settings.statistics.unavailable`。
- 滚动定位：`scrollToCalendarSettings()` 在 `calendarSection.requestLayout()` 后 `Platform.runLater`，按 `calendarSection.getBoundsInParent().getMinY() / (contentHeight - viewportHeight)` 设置 `vvalue`；内容不足以滚动时直接 `vvalue=1`。与 `PersonalizationPage.scrollToHomeCustomization()` 同模式。
- 不修改 `dashboard.json`、左右栏/排序语义；不新增上游代码侵入点（`LauncherSettingsPage.java` 仍是既有第 8 处）。
