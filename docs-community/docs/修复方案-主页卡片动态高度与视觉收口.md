# 主页卡片动态高度与视觉收口方案

> 状态：**已实现，待 Windows 实机验收**
> 基线：`lmcl` 代码 `a80de431c`（M3 切片 A 可见基线）、测试包 `m3expressive3`
> 用户原话（m19426）：
> “现在倒是可以了，但是视觉上不太协调，主页组件卡片不要是固定长度，根据里面项的数量动态变化，组件内按钮统一下对齐，然后比如下载源那边，有几个就要如实写几个的地址，不用写‘无内置兜底源’这种从用户角度看起来很奇怪的话，总览分析，先写md。”

本文记录现状取证、设计决策、验收计划与实现记录；实现已完成，Windows 实机视觉验收仍待执行。

---

## 1. 目标与范围

### 1.1 要解决的问题

1. **卡片高度不再写死**：主页卡片的高度由标题、内容项数量、操作行共同决定，而不是由 `HomePane` 的槽位表固定。
2. **操作按钮统一贴底**：同一卡片内的按钮行固定在内容底部；一个按钮靠右，两个按钮分列左右，三个及以上靠右成组。
3. **下载源如实展示**：主页网络卡显示每一个已配置下载源的地址，而不是只显示第一个源、再用“无内置兜底源”这种实现视角的文案补充。
4. **总览视觉收口**：以这三项为入口，检查主页卡片的外壳、标题层级、留白、列宽、空态和 M3 样式的一致性，给出可执行的统一规则。

### 1.2 不在本方案内

- 不重做 M3 切片 B–G（毛玻璃、Wavy 进度条、四页逐页重构）。
- 不改主页组件的数据模型、`dashboard.json` 语义、左右栏配置和排序逻辑。
- 不新增页面、不引入新依赖、不改上游 `ui/**` 源码。
- 不改变各组件已有的数据来源和刷新策略；只调整布局、内容密度和文案。

### 1.3 成功标准

- 在 1280/1600/2560 宽度、100%/125% DPI、M3 开/关下，主页没有固定高度的空条、裁切或按钮悬空。
- 9 张组件卡（另加账户卡）每张的高度都等于“标题 + 实际内容 + 操作行 + 内边距”。
- 每张卡的操作按钮位于卡片内容底部；一个按钮靠右，两个按钮分列左右，三个及以上靠右成组。
- 网络卡在 0/1/3/5 个源时分别显示空态或对应数量的完整地址，不再出现“无内置兜底源”。
- 编译、`checkTranslations`、community/全量测试、`makeExecutables` 通过；文档与包同步。

## 2. 现状取证

### 2.1 固定槽位高度是主因

`HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/builtin/HomePane.java`：

- `:101-113` 定义了两张固定槽位表：

```java
private static final List<Slot> INFO_SLOTS = List.of(
        new Slot("activity-calendar", 318),
        new Slot("recent-worlds", 272));

private static final List<Slot> INSTANCE_SLOTS = List.of(
        new Slot("launch", 168),
        new Slot("pinned-instances", 188),
        new Slot("java-recommend", 168),
        new Slot("snapshot", 176),
        new Slot("crash-history", 176),
        new Slot("health-check", 154),
        new Slot("network", 142));
```

- `:406` 重建栏位时调用 `addWidget(target, item.id(), slotHeight(item.id()))`。
- `:455-468` 的 `slotHeight()` 按 id 查表，未登记组件回退 150。
- `:473-480` 的 `addWidget()`：

```java
widget.setMinHeight(minHeight);
widget.setPrefHeight(Region.USE_COMPUTED_SIZE);
widget.setMaxHeight(Region.USE_PREF_SIZE);
```

注释写的是“槽位高度只是最小高度”，但实际效果是**每张卡先被强制拉到槽位高度**；内容不足时，多出来的空间留在卡片底部，形成固定长度的空条。

`DashboardWidget` 基类本身已经允许内容决定高度：

- `HMCL/src/main/java/org/jackhuang/hmcl/community/dashboard/DashboardWidget.java:96-125`：`setMinHeight(0)`、`title + contentBox`，`contentBox` 设置 `VBox.setVgrow(ALWAYS)`。
- 只要不覆盖 `minHeight`，卡片应能按标题和内容计算 `prefHeight`。

| 卡片 | 当前最小高度 | 当前高度相关逻辑 | 实际结果 |
| --- | ---: | --- | --- |

| `network` | 142 | 无 | 只显示第一个源 + 数量 + 固定文案；底部空白 |

### 2.5 总览视觉问题

除三个明确问题外，主页还有以下不一致：

1. **卡片外壳不统一**：
   - 上游 `.card` 是 `-fx-background-radius: 4; -fx-padding: 8;`，带明显阴影（`root.css:1071-1077`）。
   - `m3-community.css` 里又有两条 `.lmcl-m3 .card`（一条改底色，一条改 16px 圆角 + 描边），规则重复，经典/M3 两套视觉叠加。
   - 账户卡和组件卡都走 `.card`，但账户卡没有组件标题的层级。
2. **标题层级不统一**：
   - `.community-title` 15px/600、`.community-headline` 20px/700（`community.css:9-22`）。
   - M3 基线又加 `.community-headline` 28px/500。
   - 卡片标题、主页问候、列标题之间没有统一的比例。
3. **左右列节奏不一致**：
   - 左列固定 `INFO_WIDTH=340`，`B` 右列自适应；左侧账户 + 日历 + 记录，右侧 7 张卡。
   - 当前左列卡片最小高度偏大，右列卡片偏小，视觉重心明显偏左。
4. **空态/错误态样式各异**：
   - 崩溃卡把空态放进 footer；健康卡用独立 `error`；网络卡用固定 fallback；最近世界用 `empty`。
   - 没有统一的“空态占位高度/字号/图标”。
5. **卡片内容密度不一致**：
   - 日历卡 26 周、记录卡 3 行、启动卡单行，信息密度差异过大；用户会感觉“有的卡很空、有的卡很挤”。
6. **M3 样式的作用域不够干净**：
   - `HomePane` 根节点没有 `community-home` 类，CSS 只能靠 `.lmcl-m3 .card` 命中所有卡片。
   - 后续做动态高度时，建议新增 `.community-home` 作用域，避免影响上游其他 `.card` 页面。

## 3. 设计原则

1. **内容决定高度**：卡片高度 = 标题 + 实际内容 + footer + padding；不再有按组件 id 的固定高度表。
2. **宽度决定密度，数量决定行数**：响应式只看宽度；显示几条由数据数量 + 明确上限决定，不由当前高度反推。
3. **一个 footer 契约**：所有卡片用同一种“内容区可增长 + footer 贴底”的结构；一个按钮靠右，两个按钮分列左右。
4. **如实、正向、可行动**：下载源卡显示每个源的真实地址；空态直接告诉用户下一步，不使用“无兜底”这类内部术语。
5. **样式作用域**：新增 `.community-home`，M3 规则只作用于社区主页；不修改上游 `.card` 的全局语义。
6. **小步可回退**：先做高度和 footer，再做网络卡，再做视觉统一；每步可独立构建/测试。

## 4. 详细设计

### 4.1 移除固定槽位高度

**改动文件**：`HomePane.java`

1. 删除 `INFO_SLOTS`、`INSTANCE_SLOTS`、`slotHeight()` 和 `Slot` 记录（若没有其他引用）。
2. `addWidget()` 去掉 `minHeight` 参数：

```java
private void addWidget(VBox column, String id) {
    DashboardWidget widget = registry.create(id, context);
    if (widget == null) return;
    widget.setMinHeight(Region.USE_PREF_SIZE);   // 最小高度 = 自身 pref
    widget.setPrefHeight(Region.USE_COMPUTED_SIZE);
    widget.setMaxHeight(Region.USE_PREF_SIZE);
    widget.setMaxWidth(Double.MAX_VALUE);
    widgets.put(id, widget);
    column.getChildren().add(widget);
    widget.initialize();
    widget.requestRefresh();
}
```

3. 调用点改为 `addWidget(target, item.id())`。
4. `DashboardWidget` 基类不改（旧 `DashboardPane` 仍走网格布局，避免影响旧路径）；只在 `HomePane` 覆盖最小高度。
5. 在 `HomePane` 构造器加根样式类：

```java
getStyleClass().add("community-home");
```

这样 CSS 用 `.community-home .card` / `.lmcl-m3 .community-home .card`，不碰上游其他卡片。

**为什么用 `USE_PREF_SIZE` 而不是 `0`**：`minHeight=0` 会让某些空态/错误态在布局早期被压到标题高度以下；`USE_PREF_SIZE` 表示“最小就是自己的 pref”，既没有额外固定值，也不会被父容器无故压缩。

### 4.2 每张卡的内容驱动规则

> 原则：先有数据，再决定显示多少；高度由显示出来的内容自然撑开。除日历外，不再监听 `heightProperty`。

| 卡片 | 当前依赖高度的逻辑 | 改为 | 说明 |
| --- | --- | --- | --- |
| `launch` | 无 | 保持 1 个选中实例 | 有实例显示实例 + 启动/切换；无实例显示新建/管理 |
| `pinned-instances` | `:145` 高度 ≥200 才 6 个 | `MAX_VISIBLE = 6`，按 `min(6, valid.size())` | 第 7 个起显示 `+N`；卡片高度随 1–6 个 tile 变化 |
| `java-recommend` | 无 | 自然高度 | 两行信息 + footer；不再被 168 撑开 |
| `snapshot` | 无 | 自然高度 | 4 行摘要 + footer；无选中时只显示空态 |
| `crash-history` | `:123-126` 高度 ≥220 才 4 条 | `MAX_VISIBLE = 4`，`min(4, entries.size())` | 默认 2x1 宽卡最多 4 条；删除 `COMPACT_ENTRIES`/`LARGE_ENTRIES` 与监听器 |
| `health-check` | `:125` 高度 <170 则 compact | 取消 compact；显示 summary + time + 最多 4 条 details | 报告很长时只列前 4 条，详情在复查中看；不再因高度隐藏 |
| `network` | 无 | 全部源，行数 = `sources.size()` | 详见 §4.4；卡片随源数量增长 |
| `activity-calendar` | `:151` compact、`:256` 26 周 | 宽度决定周数：`width >= 720 ? 26 : width >= 320 ? 12 : 4`；取消 compact | 左列 340 宽 12 周，右栏宽卡 26 周，窄卡 4 周；高度由 7 行格子决定 |
| `recent-worlds` | `:316` 高度 ≥300/170/1 | `MAX_VISIBLE = 3`，`min(3, worlds.size())` | 默认 3 条；不足 3 条卡片自然变矮；删除高度监听器 |

补充约束：

- 所有“按数量显示”的上限只影响卡片内展示，不改变数据层；“查看全部/管理”仍打开完整页面/对话框。
- 日历周数只看宽度，不再看高度；`grid` 的 7 行由周数决定，卡片高度自然变化。
- 删除 `heightProperty` 监听后，`renderedRows`/`renderedWeeks`/`maxEntries` 等字段可删除或改为只按数据/宽度判断。
- 如果某张卡在 1×1 宽度下确实放不下（如网络 5 个源），由右列 `ScrollPane` 承担滚动，不裁切、不省略。

### 4.3 统一 footer 契约

**改动文件**：`BuiltinWidgets.java` + 各组件。

新增一个简单的 footer 构造器（不引入新的 UI 框架）：

```java
static HBox cardFooter(Node... nodes) {
    HBox footer = new HBox(8);
    footer.getStyleClass().add("community-card-actions");
    footer.setAlignment(Pos.CENTER_RIGHT);
    footer.setFillHeight(true);
    if (nodes.length == 2) {
        // 两个按钮：一个贴左、一个贴右，中间用可伸缩空白撑开。
        footer.getChildren().addAll(nodes[0], spacer(), nodes[1]);
    } else {
        // 一个或三个以上：整体靠右；三个以上按传入顺序从左到右排列。
        footer.getChildren().add(spacer());
        footer.getChildren().addAll(nodes);
    }
    return footer;
}
```

各卡片内容根统一为：

```java
VBox body = new VBox(4, ...实际内容...);
VBox content = new VBox(6, body, footer);
VBox.setVgrow(body, Priority.ALWAYS);
```

- `body` 是唯一可增长区域，`footer` 永远是最后一个子节点，因此贴底。
- 卡片高度由 `title + contentBox + body + footer` 的 pref 决定；当父容器给额外高度时，`body` 吃掉额外空间，footer 保持在底部。
- 列表型卡（crash/recent/pinned）把列表放在 `body` 内，并保留 `VBox.setVgrow(list, ALWAYS)`，让列表区域增长；footer 仍贴底。
- 日历把 `grid` 放在 `body` 内，保留 `VBox.setVgrow(grid, ALWAYS)`。

**按钮横向规则**（m19511 用户确认）：

- **只有一个按钮**：靠右。
- **恰好两个按钮**：一个贴左、一个贴右，中间由 `spacer()` 撑开；不再把两个按钮挤在右侧。
- **三个及以上**：整体靠右成组，按传入顺序从左到右排列。
- 状态/提示文字不放进 footer；放在 body 的 footer 上方，避免抢占左右按钮的位置。
- 每张卡的 footer 顺序：

| 卡片 | footer 顺序（从左到右） |
| --- | --- |
| `launch` | `[启动/运行中]` 左，`[切换]` 右 |
| `pinned-instances` | 只有一个按钮 `[管理]`，靠右；`更多` 只是 body 中的提示文字 |
| `java-recommend` | `[推荐 Java…]` 左，`[管理 Java]` 右 |
| `snapshot` | 三个按钮靠右成组：`[回滚到上次成功] [标记当前为可用] [管理…]` |
| `crash-history` | `[打开目录]` 左，`[查看全部]` 右；无错误时打开目录隐藏，查看全部仍在右 |
| `health-check` | `[复查]` 靠右 |
| `network` | `[配置下载源]` 靠右 |
| `activity-calendar` | `[设置]` 靠右；提示文字在 body 中靠左 |
| `recent-worlds` | `[全部世界]` 左，`[刷新]` 右 |

> 两个按钮“一左一右”是用户明确要求的规则；三个以上仍保持右对齐成组，避免四角分散。

### 4.4 网络卡：逐源展示真实地址

**目标布局**：

```text
下载源  3 / 5
1  My Source
   https://example.com/api
2  Backup
   https://backup.example.com/api
3  ...
[配置下载源]                        ← footer，右下
```

- 头部：`下载源 %d / %d`，不再重复“源：”。
- 每个源两行：
  - 第一行：序号 + 名称（`CommunityDownloadSource.name()`，空名用 `defaultName(url)`）。
  - 第二行：完整 URL，`Label` 或 `Text` 换行，`community-source-url` 小字号。
- 没有源：
  - `尚未配置下载源`
  - `添加下载源后即可下载`
  - footer 只有 `[配置下载源]`。
- 不再显示 `community.network.fallback`；同步删除该 key（三份资源）。
- 如果 URL 很长，使用 `setWrapText(true)` + `setMaxWidth(Double.MAX_VALUE)`；如果 JavaFX `Label` 对无空格超长 URL 不能断行，则退化为 `Text` + `wrappingWidth`，以实际 Windows 渲染为准。
- 数据来源仍为 `CommunityDownloadSources.load()`，顺序按用户配置/测速后的顺序；不额外排序、不去重（数据层已保证）。

- 新增 `.community-empty`：`-fx-padding: 12; -fx-text-fill: -monet-on-surface-variant;`。

- 网络、崩溃、最近世界、快照、启动的空态统一使用 `BuiltinWidgets.caption/body` + `.community-empty`。

#### 4.5.4 按钮

- `.community-card-actions`：`-fx-spacing: 8; -fx-alignment: center-right;`。

#### 4.5.5 列宽与滚动

- 左列保持 340px（`INFO_WIDTH`）；如果实机截图显示左列仍偏宽，可降到 320px，但不在本方案首轮改动。
- 右列 `HBox.setHgrow(ALWAYS)`；两列独立滚动，不互相抢高度。
- 卡片高度动态后，右列可能出现“短卡 + 长卡”；这是内容驱动的预期，不做等高对齐。
- 滚动条仍贴右边缘；卡片底部留 12px，避免最后一张卡贴住滚动条。

## 7. 风险与回退

| 风险 | 可能性 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 动态高度导致右列过长 | 高 | 需要滚动更多 | 由 `ScrollPane` 承担；网络 5 源时接受更高卡片 |
| 删除高度监听后信息变少/变多 | 中 | 用户不习惯 | 固定上限（crash 4、recent 3、pinned 6）；保留“查看全部” |
| `USE_PREF_SIZE` 在 CSS/字体加载前后抖动 | 中 | 首次布局跳动 | 在 `initialize()` 后请求一次 `requestLayout()`；实机观察 |
| footer 的 `body` vgrow 与列表 vgrow 冲突 | 中 | 列表被压扁/按钮不贴底 | 每张卡只保留一个 `ALWAYS` 增长子节点；代码审查 |
| 网络长 URL 不换行 | 中 | 横向溢出 | `setWrapText(true)` + 实测；必要时用 `Text` + `wrappingWidth` |
| M3 作用域过宽 | 中 | 影响上游卡片 | 所有选择器加 `.community-home`；不改全局 `.card` |
| 文案删除 key 后其他语言缺失 | 低 | `checkTranslations` 失败 | 三份资源同步；先 grep 引用 |

回退策略：

- 高度/ footer 改动集中在 `HomePane` 和 9 个 widget；如出现严重布局问题，恢复 `slotHeight()` 即可回到旧布局，数据/配置不受影响。
- 网络卡可单独回退到“首个源 + 数量”，但不再恢复“无内置兜底源”文案。
- CSS 改动可通过移除 `.community-home` 作用域回退；不影响上游页面。
