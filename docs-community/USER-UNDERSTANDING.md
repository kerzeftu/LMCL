# LMCL 用户理解（USER-UNDERSTANDING）

> 本页留存原设计面向的玩家、术语和反馈，不是现行支持政策。项目已暂停；实际交付状态以 [暂停清单](docs/待办总览.md) 为准。

---

## 1. 目标用户

- 原目标人群：中文 Minecraft 玩家，尤其是使用整合包、管理多个实例、关注启动器外观的人。
- 历史测试包针对 Windows x64；开发时的 WSL2 检查不能代替 Windows 实机验收。
- 判断截图时应区分空状态、禁用状态和点击未命中；仅凭一张截图不能覆盖其他状态。
- 关注点排序：**视觉观感（磨砂/过渡/边缘）≈ 可用性（按钮能点、文字完整）> 新功能**；性能/流畅度会提，但排在观感之后。

---

## 2. 产品意图（LMCL 相对 HMCL 的差异）

1. 视觉：M3 Expressive + 实时壁纸磨砂（五层高斯）+ 顶部/底部边缘渐隐，目标是 HyperOS 2 一类“高级材质”观感。
2. 结构：主页改为左侧 64px 侧栏 + 两列组件卡；管理/设置/“其他”页保留上游能力但换入口。
3. 品牌：LMCL 自有图标、名称、关于页、崩溃页文案；不冒充 HMCL。
4. 约束：不新增上游侵入点（现 18 处）；不做自动更新/包名 relocate/macOS dmg；Windows 绿色包。

## 3. 术语表（与用户对齐）

| 用户说法 | 含义 |
| --- | --- |
| 主页 / 首页 | `HomePane` 的两列组件卡页面 |
| 卡片 / 组件 | `DashboardWidget` 经 `materialCard` 包装后的玻璃卡 |
| 材质 / 磨砂 / 毛玻璃 | 五层实时壁纸模糊 + 半透明 tint（不是静态截图，不是纯色） |
| 过渡带 / 渐隐带 / 模糊条 | `GlassEdgeFade`（顶/底各 72px，滚动驱动） |
| 搁板 | 底部带在内容截断以下的“全不透明材质区”（向下延伸方案） |
| 置顶 | **层级在最上、点击命中按钮本身**，不是“把按钮移到卡片顶部”（v3.17.34 已澄清） |
| 点不到 | 可能是禁用态（无选中实例）、被覆盖、被裁切；需区分 |
| 亮边 / 亮的这条 | 过渡带外缘比带身更亮（清晰壁纸外缘导致，v3.17.31/32 已处理） |
| 硬切 | 内容在视口边缘被直接裁断，没有渐隐过渡 |
| 完整绿色包 | 含 `jre-x64/` 与 `dependencies/…/openjfx/` 的解压即用包，不是 delta 补丁 |
| Classic / M3 | 视觉主题：Classic=实色卡片；M3=玻璃材质 |

## 5. 用户的判断标准（验收口径）

1. **看效果，不看解释**：截图/实机观感为准；代码正确但观感不对仍算未完成。
2. **不要“亮边、硬切、色带、补丁块”**：过渡带必须与卡片同材质、边缘无亮线、内容截断不可见。
3. **按钮必须“看得见、点得到、字完整”**：层级在上、命中按钮本身、文案不省略（窄列换行 + tooltip）。
4. **空状态要自解释**：没有实例/账户时，用户能看懂为什么按钮是灰的。
5. **改动要收敛**：不要为修一个问题引入新的观感问题；不要反复改同一处试错。
6. **不写“已修复/实机验证通过”**，除非用户自己确认。

---

## 6. 沟通与工作方式偏好

- 先给结论/路径，再给细节；能一句说清就不要长篇。
- **不要过度防御、过度校验**：不为“确保正确”反复写验证脚本、堆 assert、同一改动多轮交叉核对；按文档标准验证一次，确认生效就停。
- 遇到视觉问题先要截图（或让用户描述“哪里亮/哪里被盖/哪里硬切”），不要凭空猜。
- 用户说“先写 md”时，先出诊断/方案（PRD），确认后再改代码。
- 交付时给：包名、大小、SHA-256、测试数、未实机验证的明确说明、需要用户重点看的 2–3 项。

---

## 7. 容易误判的点（务必避免）

1. **把“没置顶”当成“位置要在卡片顶部”**：用户要的是层级/点击，位置早已在 footer 也可以；v3.17.33 因此走过弯路。
2. **把“点不到”当成遮挡**：先看是否为禁用态（空状态文案“请先选择实例”），再看裁切，最后才查覆盖层。
3. **为消除“亮边”而删除整条底部带**：用户要的是“不要亮边”，不是“不要模糊”；v3.17.31 因此被要求恢复。
4. **只改底部带不考虑顶部带**：两列顶/底带共用 `GlassEdgeFadeImage`，改材质会同步影响顶部带；改前说明影响。
5. **声称视觉通过**：WSL2 没有 Windows GUI，任何“观感正常”都只能由用户确认。

## 8. 当前待确认项（用户视角）

- 选中实例后，快照三按钮是否可正常点击（需要一张选中实例的截图；若仍不可点，按 `TROUBLESHOOTING.md` §4 的顺序排查）。
- 底部“渐隐+搁板”方案是否符合“模糊向下延伸”的预期（内容截断处仍会渐隐，属于软过渡的固有代价）。
- 空状态是否接受“保留按钮 + 文案说明”，还是希望隐藏按钮改为一行提示。
